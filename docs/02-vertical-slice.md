# 首个纵向切片范围与验收标准

用途：明确首个纵向切片的范围、目标与验收标准。

> 当前医院内容包和测试参数已由 DEC-029 至 DEC-039 及冻结报告确认；完整七日内容和其他世界仍未设计。当前工程实现进度不代表整个可玩切片已经完成。

## 纵向切片目的

验证从异常电梯出发、进入场景探索、撤离返回、完成日结算并自动保存的核心流程。

医院纵向切片用于验证已冻结的探索、战斗、撤离与结算规则能否形成可实现闭环。

> 根据 DEC-041，医院一日 Production Playability 的 New Run 暂不包含专长选择、专长状态或专长效果，当前使用固定基础角色。该暂缓不改变新 Run 必须使用新状态与新种子的要求；当前医院一日 New Run 仍必须显式从撬棍、手电筒、工具箱中选择一件初始实用装备。专长尚未实现，并且必须在完整七日感染世界里程碑完成前补回。

## 玩家流程

从电梯中枢进入一个场景，在4至6个节点组成的网络中移动，完成至少一次主要搜索，处理至少一个具有多种解决方式的障碍或事件，并主动撤离、结算返程、完成当日结算及自动存档。

> 医院节点、障碍、事件及测试行动成本已冻结；完整游戏和其他世界内容仍待设计。

## 包含系统

- 一名玩家与一个敌人实体的无站位、无多目标简化 CTB 战斗；
- 基础攻击、当前武器的一个标志性行动、通用防御、一个可战斗快捷物品，以及逃跑和脱离准备；
- 敌人一个基础行动、一个具有明确意图的特殊行动，以及可见的下一行动意图；
- 敌人相对生命状态和胜利、逃跑、战败三种结果；
- 战斗时间与场景时间分离，并在战斗结束后写回持续量和状态变化。

> 不要求同时验证全部武器、防具、实用装备或正式敌人内容。

## 不包含系统

遵循 `docs/01-game-design-v0.1.md` 的“首版明确不做”章节。

> 医院纵向切片的不包含范围以本节、DEC-029 至 DEC-039 和设计冻结报告为准。

## 内容范围

- 一个场景；
- 4至6个节点；
- 节点网络移动；
- 至少一次主要搜索；
- 至少一个具有多种处理方式的障碍或事件；
- 主动撤离、返程、当日结算和自动存档。

> 医院切片的具体场景、节点、事件、战斗和物品测试内容已冻结；完整七日内容仍待设计。

## 验收标准

- UI能够展示剩余时间与预计返程成本。
- 节点主要搜索不能重复执行或刷新物资。
- 玩家返回节点时，本次探索的节点运行状态保持不变。
- 非战斗状态下整理背包不消耗场景时间。
- 主动撤离需要按照节点网络计算返程。
- 时间耗尽时进入最小强制返程流程，而不是立即死亡或直接判定 Run 失败。
- 完成撤离后能够进入当日结算并触发自动存档。
- 快速和缓慢行动能够在时间轴上形成可观察的顺序差异。
- 玩家能够根据敌人意图选择攻击、防御、使用物品或逃跑。
- 普通基础攻击默认命中。
- 逃跑不使用隐藏成功率，且脱离准备期间敌人可能先行动。
- 防御只覆盖明确处理的直接攻击风险。
- 使用快捷物品后，对应快捷位变空且不会自动补充。
- 战斗结果能够改变场景剩余时间和玩家状态。
- 相同战斗种子与相同行动序列能够复现结果。
- 战败只返回战败结果，不在本切片中确定永久死亡或完整 Run 失败后果。
- 自动存档或快照不能恢复到行动只结算一半的状态。
- 玩家拥有内部整数生命值，普通 UI 显示精确当前值和上限。
- 最小敌人攻击能够造成直接生命伤害，并至少验证流血或轻度伤势、感染暴露两类额外风险中的一种。
- 只实现其中一种额外风险不代表另一种从首版设计中删除。
- 绷带或止痛药中至少一种可以通过快捷栏在战斗中使用，并通过标准化 Effect 写回状态。
- 生命恢复不能自动清除流血、伤势或感染等独立状态。
- 场景行动后能够执行一次最小持续状态检查。
- 当日结算保留饱食和感染进展接口。
- 同一持续状态不得在一个结算点重复触发。
- 饱食不会在每次普通攻击或节点移动后自动减少。
- 状态变化能够自动存档并按相同种子和操作确定性恢复。
- 不要求实现完整伤势列表、正式七日世界变化或完整生存经济。
- 玩家撤离或完成最小强制返程后进入返回电梯结算，而不是自动推进日期。
- 返回结算能够转移普通物品，并按测试数据分别处理任务物品、权限物品、情报和收藏品，显示探索摘要后自动保存。
- 返回结算与每日结算保持为不同操作。
- 返回结算后进入不消耗场景时间的电梯中枢整备，并至少允许一种消耗实际资源的不可逆治疗、补给、制作或维修操作。
- 普通重载不能恢复已被不可逆整备操作消耗的资源。
- 玩家主动确认“结束本日”，确认界面展示已知状态、持续风险和日级资源警告。
- 流血、伤势、感染风险或饱食不足不硬锁结束本日。
- 最小日结算依次提供持续危险、感染进展、饱食消耗、有限恢复、次日状态和日期推进接口。
- 持续危险先于基础恢复；基础恢复不自动清除流血、伤势、感染或修复装备。
- 饱食不足不会因一次结算立即死亡，止痛药默认不跨多个日期。
- 日结算完整结果原子化保存，重载恢复稳定次日状态且不能进入部分完成状态。
- 相同结算前状态、种子和操作序列复现相同结果。
- 不要求完整七日内容、全部医疗品与配方、完整感染或饱食经济、中枢升级、复杂世界变化及正式失败系统。
- 最小战斗中生命降至0后，战斗返回战败，Run 流程进入失败结算而非普通撤离。
- 失败后不能继续场景、中枢或日结算；冻结最终状态，记录最小日期与原因并生成摘要。
- 既有 Profile 内容不会被清除，未安全提取收藏品不会写入 Profile。
- 活动 Run 原子化标记为失败并自动保存，重载只显示终止摘要，不能回到战败前继续。
- 玩家可创建使用新状态和新种子的 Run，新 Run 不继承旧 Run 的物品、任务、情报或状态。
- 根据 DEC-041，医院一日 New Run 暂不选择、保存或应用专长，但仍使用新 RunIdentity、新种子和新状态，并保留撬棍／手电筒／工具箱的显式初始实用装备三选一。
- 异常退出本身不导致失败，相同初始状态、种子和操作序列复现相同战败与终止结果。
- 仅为成功、放弃、感染终末、期限和剧情失败保留接口，不要求实现完整七日失败、正式结局、统计、排行榜、永久成长、复活或救援。

> 医院纵向切片的时间、风险、战斗和强制返程测试参数按 DEC-030 至 DEC-033 执行；完整游戏平衡仍待设计。

## Production Playability 启动与 New Run 验收

- 生产网页冷启动严格读取唯一 Run 槽，并能恢复合法的 `current-day-hub`、`scene-session` 和 `run-failure`。
- `current-day-hub` 与 `scene-session` 自动进入对应正式玩法 UI，不增加无实际选择价值的 Continue 页面；`run-failure` 只恢复终止摘要，不能恢复成活动 Run。
- 无存档进入 New Run Setup，不自动创建默认 Run。
- 损坏或不兼容存档进入阻塞错误并保留原值；只有玩家显式确认后，才清除可读取但无法恢复的存档。底层存储读取失败不得自动清除或回退为无存档。
- 活动 Hub 或 Scene 不提供 New Run，不得以覆盖存档绕过未来正式 Run Abandon。
- 医院一日 New Run 只可从无存档或合法 `run-failure` 进入，使用新的 RunIdentity、新 seed 和新状态，不继承旧 Run 的物品、任务、情报、日期、场景或玩家状态。
- New Run 必须由玩家显式从撬棍、手电筒、工具箱中三选一；根据 DEC-041 使用固定基础角色，不显示、保存或应用专长。
- 一次 New Run Confirm 只生成一次身份和一个完整 Day 1 `CurrentDayHub`，只尝试保存一次并只建立一个 `StableRunStore`；从 `run-failure` 创建时直接覆盖唯一槽，不先清除旧终止存档。
- 首次保存失败时保留已建立的新 Run 作为当前会话内存真相，不回滚、重试、重新生成身份或建立第二个 Store，并明确提示刷新可能丢失未持久化的新 Run。
- 最终生产链需要验证：创建新 Run → 完成正式命令并保存 → 刷新网页 → strict resume 同一 canonical phase。本任务只冻结该验收方向，不代表链路已经实现。

## 医院纵向切片内容包

- 正式场景：封锁医院·急诊楼一层；
- 场景 ID：`scene_blockaded_hospital_emergency_floor_1`；
- 主要任务：取得密封病原样本箱并安全返回电梯；
- 六个节点：电梯前室、急诊大厅、药房、保安值班室、隔离走廊、标本冷藏室；
- 基础连线：
  - 电梯前室 ↔ 急诊大厅；
  - 急诊大厅 ↔ 药房；
  - 急诊大厅 ↔ 保安值班室；
  - 急诊大厅 ↔ 隔离走廊；
  - 保安值班室 ↔ 隔离走廊；
  - 隔离走廊 ↔ 标本冷藏室。
- 初始整备：金属管、厚实外套、绷带×1，实用装备从撬棍、手电筒、工具箱中三选一，背包基本为空；
- 急诊大厅、药房和保安值班室各有一次不可重复的主要搜索；
- 保安值班室稳定提供实体门禁卡和不完整敌人情报；
- 隔离区防火门支持门禁卡、所选实用装备、消防斧兼容方案、强行处理和放弃等不同路径；手电筒不作为开门工具；
- 隔离走廊触发单敌人感染护工战斗，敌人只有抓挠和扑咬两个行动，扑咬必须显示明显意图；
- 标本冷藏室提供样本箱及污染风险取舍，不要求特定装备；
- 样本箱进入背包后占 `2×2`、重量4，不能自动传回电梯，安全带回后进入任务储存区；
- 玩家可以完成目标后撤离、未完成目标主动撤离、从战斗逃跑，或战败并终止 Run；
- 未完成目标撤离仍进入返回结算、中枢整备和日结算；战败不执行普通提取。

## 医院内容包验收

1. 六节点地图及基础连线与 DEC-029 一致。
2. 表层观察不直接公开隐藏信息。
3. 急诊大厅、药房和保安值班室的主要搜索不能重复。
4. 保安值班室搜索能够稳定取得门禁卡。
5. 门禁卡重量为0但占用一个背包格子。
6. 防火门能通过门禁卡、适用实用装备或强行处理形成不同路径。
7. 手电筒不会被当作开门工具。
8. 感染护工按单敌人 CTB 运行，只有抓挠和扑咬，扑咬提前展示意图。
9. 金属管能够验证钝击控制方向。
10. 逃跑后感染护工仍然存在。
11. 样本箱正常占格、计重且不会自动传送回电梯。
12. 未取得样本箱时仍可主动撤离，且撤离本身不自动受罚。
13. 战败不会把背包内容视为安全提取。
14. 完成目标撤离后可继续返回结算、中枢整备和日结算。
15. 不要求实现全部装备、敌人或完整七日内容。
16. 相同种子和操作序列能够复现场景搜索、敌人行为及事件结果。

## 医院场景时间测试参数

- 初始时间：200时间刻。
- 时间档位：无耗时0、快速10、普通20、缓慢30。
- 六条节点连线基础移动时间均为10。
- 负载移动与返程为基础成本的110%，超载为125%，最终统一向上取整。
- 基础10移动在正常、负载、超载时分别消耗10、11、13；同一次移动只最终取整一次。
- 急诊大厅、药房和保安值班室主要搜索：
  - 使用手电筒照明时20并消耗1次照明；
  - 无可用照明时30；
  - 无手电筒仍可完成搜索。
- 手电筒初始3次照明，一单位通用电池恢复3次。
- 防火门：
  - 门禁卡10；
  - 撬棍20、耐久−1；
  - 工具箱30、耐久−1并固定获得电子元件×1；
  - 消防斧10、耐久−1；
  - 强行撞门20并执行轻度伤势风险；
  - 放弃0。
- 样本箱提取：谨慎提取30、直接提取10、放弃0。
- 剩余时间大于0时可以确认执行越过零点的合法行动；行动完整结算后时间截断为0并立即强制返程。
- 时间已经为0时不能开始新的普通行动。
- 战斗场景时间按 DEC-031 使用 `max（10，ceil（战斗实际经过CTB时间 ÷ 100）×10）`，并在战斗结束后一次写回。

| --- | ---: |

### 时间规则验收

1. 场景开始时剩余时间为200。
2. 六条边在正常负重下均消耗10，基础10在负载和超载时分别消耗11和13。
3. 单次移动不会在多个计算阶段重复取整。
4. 任务物品改变负重档位后，返程估算立即更新。
5. 无手电筒不会阻止搜索，但成本从20增加到30。
6. 手电筒搜索消耗1次照明，重复查看 UI 不消耗照明，已完成搜索不会刷新。
7. 撬棍和工具箱使用后正确消耗耐久，工具箱固定获得电子元件×1。
8. 防火门成功处理后往返不重复收费。
9. 两种成功提取方式获得同一个样本箱，污染风险按 DEC-032 的测试参数结算。
10. 正时间可以执行越过零点行动，归零后不能继续普通行动并立即强制返程。
11. UI显示行动后剩余时间和预计返程时间。
12. 医院纵向切片的感染进展、轻度挫伤移动和强制返程测试值按 DEC-033 执行；其他未确认边界不在本节扩展。

## 最小 CTB 战斗测试参数

- 玩家生命12；感染护工生命14，阶段为完好11～14、受伤7～10、重伤3～6、濒危1～2、失去能力0。
- 金属管耐久6；基础攻击伤害4、CTB 100、耐久−1；蓄力击打伤害6、CTB 180、耐久−3，对感染护工总延后200。
- 厚实外套完整度4，固定减伤1、伤势风险降2级、感染暴露风险降1级、无 CTB 负担。
- 初次 CTB 为玩家0、敌人70；重入为玩家0、敌人50。
- 同时间点顺序为逃跑脱离完成、玩家行动、敌人行动。
- 防御 CTB 80；先应用外套减伤，再将剩余直接伤害减半并向上取整；伤势风险再降1级，不降低感染暴露。
- 绷带 CTB 80，消耗1单位、恢复1生命、停止流血并处理一个开放伤口。
- 逃跑准备为正常80、负载80、超载110；未处理开放伤口每个追加10，最多20。
- 逃跑准备在玩家选择行动时，根据当刻的负重档位和已经存在的未处理轻度开放伤口一次性计算，并锁定本次脱离完成时间。
- 准备期间新增的流血或开放伤口正常保留，但不追溯延长本次逃跑；只有失能、束缚、明确的逃跑阻断或未来确认的中断效果可以改变正在进行的脱离准备。感染护工当前没有此类行动。
- 风险档位为无0%、低20%、中40%、高60%、极高80%；同一行动风险检查顺序固定。
- 抓挠：伤害3、CTB 100、伤势风险高60%、感染暴露无。
- 扑咬：伤害7、CTB 140、伤势风险极高80%、感染暴露风险高60%，依次独立检查伤势与暴露。
- 流血不叠层，仅在每次玩家行动完整结算后扣除1生命；绷带行动先止血。

## 场景时间透支、流血与终局优先级

- 剩余时间大于0时仍可开始合法正时间行动，即使成本越过零点；时间已经为0时不能开始第二项普通行动。
- `超时债务 = max（0，行动最终时间成本－行动开始时剩余时间）`。
- `有效紧急撤离时间 = 超时债务＋行动完成后按真实状态计算的预计返程时间`。
- `基础损耗 = min（4，ceil（有效紧急撤离时间 ÷ 20））`；流血且有效时间大于0时额外损失1，独立于基础上限。
- 玩家可以主动燃烧生命与恢复空间换取额外行动收益，这是正式风险策略；UI必须预览债务、返程、损耗、死亡风险和安全提取可能性。
- 无债务且返程0时损耗0；位于电梯前室但有债务时仍按债务结算。
- 每个正时间非战斗行动完成后只检查一次场景流血并损失1；背包、情报、地图、UI、0时间和中枢操作不检查。
- 绷带和符合条件的急救包先止血，行动后不扣流血；止痛药和消毒剂不止血，仍扣1。
- 行动主要效果先结算，但玩家死亡优先于战斗胜利、逃跑、安全返回、战利品和任务物品提取。
- 同点顺序为已开始行动完成、玩家行动、敌人行动；行动完成主要效果后仍必须执行流血与生命检查。

## 装备维护、破损使用与长期续航

- 维护层级与装备类别分开。金属管、厚实外套、撬棍分别为基础机械武器、基础织物防具、基础机械工具；手电筒为基础电子设备且只管理照明电量；工具箱为专业复合工具。
- 每日基础维护工时3点，只生成一次、不跨日；每点为基础装备恢复1，不能用于工具箱或手电筒。
- 金属零件1生成5点基础机械维修量，布料1生成4点基础织物维修量；工具箱以金属零件1和电子元件1恢复耐久1。
- 场景非战斗使用电池消耗10时间，中枢使用为0场景时间；恢复3且上限3，单位资源不可透支。
- 耐久0装备仍可无限维修且普通维修不降低最大值。主动耐久至少1时可破损使用并完整结算后截断到0；防具完整度至少1时最后一次防护完整生效后截断到0。

- 固定收益保障基础武器与防具维护底线，随机收益提供缓冲、工具和高级维护。长期验证使用维护覆盖率，并须完成七日与抽象三十日预算回测。
