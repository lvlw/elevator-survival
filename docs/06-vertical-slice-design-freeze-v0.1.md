## 5. 完整玩家流程

```text
默认生产入口严格读取唯一 Run 槽
├─ current-day-hub：自动恢复并从电梯中枢继续下列流程
├─ scene-session：自动恢复当前场景，不回退到中枢
├─ run-failure：恢复终止摘要并停止，不继续该 Run
├─ 无存档：进入 New Run Setup，原子创建后从电梯中枢开始下列流程
└─ 损坏或不兼容存档：阻塞并保留原值

进入电梯中枢
→ 查看角色、状态、仓库和装备
→ 使用每日维护工时、材料维修或电池充能
→ 配置武器、防具、实用装备、快捷栏和背包
→ 进入医院并在电梯前室开始探索
→ 移动至急诊大厅
→ 搜索大厅、前往药房或保安室、或处理防火门
→ 通过撬棍、工具箱、门禁卡、消防斧或强行撞门等合法路线进入隔离区
→ 可能触发警觉
→ 在隔离走廊与感染护工战斗
→ 使用防御、攻击、蓄力击打、医疗、逃跑或临时攻击
→ 前往标本冷藏室
→ 直接或谨慎提取样本箱
→ 主动返回或因时间耗尽强制返程
→ 结算死亡、任务物品入库和安全返回
→ 执行原子日结算
→ 自动保存稳定状态
```

医院一日 New Run 使用新的 RunIdentity、seed 和完整初始状态，由玩家显式从撬棍、手电筒、工具箱中三选一；使用固定基础角色，并根据 DEC-041 不保存或应用专长。一次确认只建立一个完整 Day 1 phase、尝试保存一次并建立一个 Store。活动 Run 不提供 New Run；从合法 `run-failure` 创建时直接覆盖唯一存档槽，不先清除终止摘要。

根据 DEC-044，医院一日 Day 1 initial Hub 预绑定由新 RunIdentity、Day 1 和正式医院主场景定义确定性派生的首日 Scene identity，同时保持 Return Ledger 为空。该 ID 是首次出发前的生命周期锚点，不表示 Scene 已启动或返回；首次 Launch 必须验证并使用同一个 identity，只有首次安全／强制返回完成正式 Return Settlement 后才将其写入 Ledger。该冻结当前只覆盖医院一日的单一正式主要场景；完整七日若出现多个首日候选场景，identity 的绑定时点必须另行复查。

## 6. 地图与节点快照

场景为“封锁医院·急诊楼一层”，入口为电梯前室，共6个节点。六条边均双向，基础移动成本均为10。

| 起点 | 终点 | 初始状态 |
| --- | --- | --- |
| 电梯前室 | 急诊大厅 | 可通行 |
| 急诊大厅 | 药房 | 可通行 |
| 急诊大厅 | 保安值班室 | 可通行 |
| 急诊大厅 | 隔离走廊 | 被隔离区防火门阻挡 |
| 保安值班室 | 隔离走廊 | 权限控制的工作人员通道 |
| 隔离走廊 | 标本冷藏室 | 走廊危险解除后可通行 |

急诊大厅、药房和保安值班室各最多一次主要搜索；隔离走廊是唯一正式战斗节点；标本冷藏室承载样本箱目标。

- 工作人员通道由当前背包中的隔离区门禁卡直接授权；通行不需要额外开门行动，不消耗门禁卡，只支付正常移动时间。
- 工具箱处理防火门固定产生的电子元件×1作为当前节点的已揭示场景物品实体保留，不自动进入背包，必须使用显式拾取命令取得。

## 7. 场景时间快照

- 初始场景时间200；标准行动档位为0、10、20、30。
- 正常移动10；负载为11；超载为13。轻度挫伤对节点移动和返程使用独立的1.10倍率；多个百分比修正按倍率相乘，全部应用后只统一向上取整一次。
- 正式返程算例由 DEC-038 冻结：`ceil（30 × 1.25 × 1.10）= 42`。不得将25%与10%直接相加，也不得在各倍率之间分别取整；镇痛只移除轻微挫伤倍率。
- 三个搜索节点使用手电筒时20并消耗1次照明，无照明时30。
- 防火门：门禁卡10；撬棍20／耐久1；工具箱30／耐久1并获得电子元件1；消防斧10／耐久1；强行撞门20；放弃0。
- 样本提取：直接10、谨慎30、放弃0。
- 场景医疗：绷带10、止痛药10、消毒剂10、急救包20；场景使用电池10，中枢使用均为0场景时间。
- 战斗场景时间：`max（10，ceil（战斗实际经过CTB时间 ÷ 100）× 10）`。
- 剩余时间大于0时可开始一次越过零点的合法行动；行动完整结算并把场景时间截断为0。时间已为0时不能开始第二个普通行动。

```text
超时债务
= max（0，行动最终时间成本－行动开始时剩余时间）

有效紧急撤离时间
= 超时债务＋行动后真实状态下的预计返程时间

基础损耗
= min（4，ceil（有效紧急撤离时间 ÷ 20））
```

有效时间大于0且仍流血时额外损失1；该追加不计入基础上限。债务与返程均为0时损耗0；已在前室但存在债务时仍按债务结算。

## 8. 背包、负载与装备快照

- 背包为 `6×4`、共24格；物品可按定义旋转。只有 `1×1` 物品可堆叠。
- 装备槽为武器位、防具位、实用装备位；另有两个快捷位。
- 当前装备和快捷栏不占背包格、不计背包负重；备用装备进入背包后正常占格计重。
- 负重档位：正常0～16、负载17～24、超载25～28、无法携带≥29。无法携带时不能确认携带方案；超载允许有限行动并使用既有修正。
- 任务物品仍进入背包；样本箱为 `2×2`、重量4。
- 破损装备仍保留原尺寸、重量和容器占用。
- 非战斗状态整理背包不消耗场景时间；战斗中不能换装或自由整理背包。

## 10. 搜索、噪声与警觉快照

- 急诊大厅固定揭示金属零件1和门禁路线提示，再从通用电池1（40%）、布料1（30%）、电子元件1（30%）抽取一项。
- 药房固定绷带1，再从消毒剂1（35%）、止痛药1（30%）、急救包1（20%）、感染抑制剂1（15%）抽取一项。
- 保安值班室固定门禁卡1、通用电池1和保安监控记录，不额外抽取。
- 搜索和风险使用独立、确定性的派生随机子流；查看UI、重载或改变无关顺序不得重刷。

- 消防斧和强行撞门设置警觉；警觉不叠加，将感染护工首次行动从70提前至50，但不直接修改伤害、风险或意图顺序。

## 11. 战斗规则快照

战斗为单敌人、无站位 CTB。玩家生命12，感染护工生命14。

| 行动 | 伤害／效果 | CTB | 资源 |
| --- | --- | ---: | --- |
| 金属管基础攻击 | 伤害4 | 100 | 耐久1 |
| 蓄力击打 | 伤害6、对感染护工总延后200 | 180 | 耐久3；每次探索最多一次 |
| 防御 | 伤害0；外套后减半直接伤害并降1级伤势风险 | 80 | 无耐久 |
| 战斗绷带 | 恢复1、止血、处理一个伤口 | 80 | 绷带1 |
| 战斗止痛药 | 产生镇痛 | 80 | 止痛药1 |
| 临时攻击 | 伤害2、无延后、无签名效果 | 140 | 无耐久 |
| 抓挠 | 伤害3、伤势风险高60% | 100 | 敌人行动 |
| 扑咬 | 伤害7、伤势风险极高80%、暴露风险高60% | 140 | 敌人行动 |

- 感染护工固定以抓挠、扑咬交替。未警觉首次行动70，警觉50。
- 逃跑准备：正常80、负载80、超载110；开始时每个未处理开放伤口+10，最多+20，并锁定完成时间。
- 直接伤害、伤势和感染暴露独立结算。厚实外套一次攻击最多消耗1完整度。
- 同点顺序为已开始行动完成、玩家可行动、敌人可行动。玩家行动后依次检查流血、玩家死亡、敌人失能、逃跑成功。
- 玩家死亡高于胜利、逃跑和提取；最后一击或逃跑完成后因流血死亡仍为Run失败。
- 主动装备耐久至少1时允许破损使用，行动完整生效后截断为0。耐久0后武器行动失效。
- 临时攻击只依据当前武器槽；槽为空或当前武器无合法攻击能力时开放。背包备用武器不影响资格，战斗中不换装。

## 12. 生存状态与医疗快照

生命、流血、轻度挫伤、各开放伤口及处理状态、未结算暴露、感染进度、感染阶段、饱食和镇痛相互独立。

- 场景中每个正时间非战斗行动完成后只检查一次流血并损失1，不按10／20／30重复扣除。
- 背包整理、纯UI、0时间和中枢操作不检查场景流血。
- 绷带和移除唯一流血伤口的急救包先止血；止痛药和消毒剂不止血，流血时使用后仍损失1。
- 绷带：战斗80、场景10、中枢0；恢复1、止血、处理一个轻度开放伤口。
- 止痛药：战斗80、场景10、中枢0；镇痛持续到下一次成功日结算。
- 消毒剂：不可战斗、场景10、中枢0；未结算暴露−1，每日最多1。
- 急救包：不可战斗、场景20、中枢0；恢复4并移除一个合格轻伤。
- 感染抑制剂作用于当日感染增加，不等同于消毒剂；压缩口粮恢复2饱食且不超过6。

## 13. 提取、返回和终局顺序

样本箱可直接提取（10、风险60%）或谨慎提取（30、风险20%）；有效外套分别降至40%和0%。污染成功记录暴露1，不影响取得动作。

```text
行动主要效果
→ 行动后流血
→ 玩家死亡检查
→ 时间与返程检查
→ 强制返程或安全返回
→ 普通物品及任务物品入库
→ 中枢与日结算
```

只有生还并安全返回，样本箱才进入任务储存区。主动返回使用真实路线；强制返程使用最短已知路线并结算超时债务。玩家死亡高于敌人失能、战斗胜利、逃跑成功、节点返回、安全返回和任务物品入库。

## 14. 每日结算和 Run 终止

- 日结算是不可逆、原子化操作；成功后生成次日状态并自动保存，不保存中间可加载状态。
- 未解决流血先造成日损失；暴露转换为感染增加，随后处理抑制、感染阶段、饱食消耗和有限恢复。
- 饱食上限及初始值6，每日消耗2；基础生命恢复2，受饱食、轻伤、感染阶段和流血限制。
- 轻度挫伤及已处理轻度开放伤口在成功生成次日状态时自然移除；未处理伤口保留。镇痛在成功日结算后清除。
- 生命归零或感染进度达到120等已确认终止条件导致Run失败；失败时不生成次日状态。
- Run保存任务世界、玩家、库存、场景和进度；Profile保存永久收藏与长期档案；Hub保存跨Run中枢状态。三者不得混写。
- 本冻结不补充中重度伤势或感染完全治疗。

## 15. 装备维护和长期续航

- 医院物品状态资源快照：金属管耐久6、消防斧耐久2、撬棍耐久3、工具箱耐久2、厚实外套完整度4、手电筒电量3；其余12项正式物品为无状态资源。
- 18项医院物品现已具备完整正式资源定义；消防斧耐久上限缺失由 DEC-039 关闭。
- 维护层级与装备类别分离：金属管、厚实外套、撬棍、手电筒为基础；工具箱为专业。特种为已确认层级但医院无当前实例。
- 普通装备可从0无限维修，普通维修不降低最大耐久或完整度。
- 每日基础维护工时3，每日只生成一次、不跨日；每点恢复1，只能用于基础装备。
- 金属零件1提供5点基础机械维修量；布料1提供4点基础织物维修量；未使用材料维修量不形成隐藏库存。
- 工具箱配方为金属零件1＋电子元件1→耐久恢复1；不能仅靠自己产出的电子元件免费自修。
- 电池恢复3次照明，上限3；满电不能使用，多余不储存。
- 固定收益保障基础维护，随机收益承担缓冲和高级维护；专业与特种装备不保证每天满修。

```text
金属零件5＋基础维护工时3＝8点确定性维护能力
金属管典型磨损5＋厚实外套典型磨损2＝7点基础磨损
```

标准周期产生1点不可储存恢复余量；加入撬棍1点磨损后为8比8。漏掉金属零件的一日形成4点缺口，恢复标准周期后约4次修复。工具箱在当前单一医院测试经济中约每5个周期可稳定维修使用一次；这些均为当前配置的预算验证，不是所有世界的硬编码规则。

## 18. 非阻塞观察项

- 急诊大厅固定金属零件是当前医院维护锚点；多世界长期任务池须提供替代基础维修来源。
- 保安值班室固定电池可能使重复医院周期产生电池净增长，正式多世界电池经济以后复核。
- 工具箱是间歇使用的专业工具。
- 临时攻击只防止行动硬锁，不是正常战斗流派。
- 当前没有战斗中换装、正式拆解收益或完整制作配方。

## 19. 尚未设计但不阻塞实现

正式七日完整场景与事件、正式三十日内容、其他任务世界、其他装备完整维护层级、正式拆解收益与制作配方、装备替换经济、维修设施升级、中重度伤势、感染完全治疗、专长维修、特种维修材料、商店交易、战斗中换装、不可逃跑战斗、更多敌人、完整难度曲线以及美术、音频和叙事制作均未完成，但不阻塞医院纵向切片规则内核实现。

侦察、工程、生存三个专长的正式效果、状态所有权、Modifier 接入、保存恢复和 UI 尚未实现。根据 DEC-041，它们不阻塞医院一日 Production Playability，但必须在完整七日感染世界里程碑完成并通过验收前补回；专长未实现时不得将完整七日里程碑标记为正式完成。

Production Bootstrap、严格恢复 UI、损坏存档显式清理 UI、Production RunIdentity adapter、正式医院一日 Headless New Run constructor／原子创建事务、Day 1 pre-first-launch Hub strict restore 特殊分支及首次 Launch identity consistency tests 已经实现。New Run Setup React UI 与浏览器点击创建新局仍未实现；不得将 DEV Preview fixture 计为正式 New Run UI。

## 21. 实现阶段不得自行补规则

出现相互冲突定义、缺少优先级或行动资格、资源消耗时点不明、死亡前收益提交不明、不可逆保存边界不明、需要新增玩家选择或策略取舍、需要未经确认随机或正式内容字段时，必须停止并提出问题。

实现团队可以自行决定内部纯函数与测试组织、UI组件拆分、不影响规则的显示顺序、错误文案、辅助类型、性能优化及不改变存档语义的实现细节。

1. 初始化React、TypeScript、Vite工程。
2. 建立纯TypeScript规则内核和版本化配置。
3. 定义Run、Profile、Hub状态边界。
4. 实现场景节点、时间事务、库存、背包、装备和负载。

9. 实现维修、充能、破损使用和临时攻击。
10. 实现中枢、日结算、自动保存和配置版本绑定。
11. 编写确定性回放与冻结回归自动化测试。

规则核心先于完整界面；UI不拥有规则真相，不在组件中散落规则数值，也不在实现阶段扩展范围。

## 23. 首批自动化验收清单

- 固定种子下搜索、风险、敌人行为和重载结果一致。
- 节点移动、照明搜索、负载修正及一次取整正确。
- 超时债务、强制返程、零距离和流血追加正确。
- 场景流血每个正时间行动只检查一次。
- CTB时间轴、警觉70／50差异及CTB290抓挠正确。
- 玩家死亡优先于胜利、逃跑、返回和任务入库。
- 绷带、止痛药、消毒剂和急救包顺序正确。
- 样本箱只在生还安全返回后入库。
- 破损使用、防具最后防护和耐久0状态正确。
- 临时攻击只按当前武器槽派生，背包武器不参与。
- 每日维护工时只生成一次且不跨日。
- 工具箱双材料维修不形成自循环。
- 电池恢复3、上限3及使用上下文正确。
- 七日与抽象三十日维护预算通过。
- 保存和回放保持Run绑定配置版本。
- Day 1 initial Hub 使用正式派生的预绑定 Scene identity、空 Return Ledger，并能在首次 Launch 前保存和严格恢复。
- 首次 Launch 复用预绑定 identity 且不写 Ledger；首次真实 Return Settlement 后 Ledger 才记录该 ID。
- 错误预绑定 identity、Day 2+ 空 Ledger、已使用主要场景却空 Ledger及预填伪造返回记录均严格拒绝且不修复。
