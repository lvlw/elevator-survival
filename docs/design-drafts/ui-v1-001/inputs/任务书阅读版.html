2. 一屏信息架构

2.1 五块区域，只有一个玩法主入口

  • 顶部 HUD：任务日、生命、精力、饱食、当前公开病程／必要异常；不画虚构时钟。保存状态可在顶部或底部单一位置持续显示，避免两处不一致。
  • 左侧常驻：本委托一句话总目标、成果状态、当前区域／地点、简化已知拓扑。详细目标与地图在中央按需展开。
  • 中央内容区：真实当前场景美术、区域与地点标题、少量主要行动、实际单边方向；容纳探索结果、关键节点、人物交流、参数、地图详情及战斗。
  • 右侧常驻：装备／背包切换、真实6×4格位、两个快捷位。物品详情可展开到中央；不能为“丰满”复制两套身体条、背包或任务件库存。
  • 底部窄反馈条：最近实际公开反馈与保存异常入口；完整记录按需局部展开，不占据半屏开发日志。

密度来自必要且稳定的信息，不来自多画按钮。场景没有来源／NPC时，不用假入口填空。

2.2 中央面板不等于强制确认框

正常态保留外围；“放大”只占满中央内容区，不使用浏览器全屏、不遮盖整个三栏外壳。地图详情、节点特写、NPC、战斗共用框架，但各自内容结构和关闭资格不同。

仅允许一个主要中央层；次级对象详情尽量在其内部切页或侧区显示，不叠五层弹窗。敏感确认可以临时置顶，完成／取消后返回原上下文。打开、关闭、缩放、切页、看地图和看详情均为纯展示。

3. 交互原则与知情选择

  • L0：短信息尽量就近常驻；复杂说明主动展开。不再让每个主按钮一经 Hover／Focus 就打开大面板。键盘能读取相同信息，但焦点移动不能触发玩法或连环展开。
  • L1：完整普通意图一次执行。地图、任务、背包、信息层的“查看”不得计行动。
  • L2：仅补真实必要参数。工具、方法、数量、来源材料、目标、格位、旋转、总池分配不得自动替玩家选择；完整请求显示正式预览。
  • L3：沿用当前有效合同的敏感操作与动态保护。不得擅自把稀缺物资、进入战斗、所有跨区移动、所有任务物放置一概加确认。新增保护要求列 Draft，不能混入本次默认交互。
  • 当前已知代价靠简短文字／图标说明；“可执行”“未证明必死”“unknown”不得混称“安全”。
  • 普通已揭示整实例拾取仅使用现有获准便利，不扩展到任务取得／交易／安装，不自动重排或合并。
  • 地图只读；节点连线与位置稳定，区域分组清晰。仅绘制玩家实际已知的节点／边，不先画全图灰色问号。
  • 跨图前明确“目的区域／地点”，跨图后标题、地图标记、背景及短到达反馈同步。不用新增确认模仿空间感。
  • 新 current／阶段变化／恢复／失锁后旧草稿失效；单纯保存重试不换对象。无声替换成第一件物品禁止。

5. 尺寸耦合总合同：先定义容器，再做素材

本节与 尺寸耦合合同-v1.0.json 是本次建议起始预算，不是声称现有网页测量值。 设计者可在本任务内用真实版面验证后改进数值，但必须成组更新 token、表格、原型和资产裁切证明；不能只修改一张画布。改变三栏常驻／中央放大／只读地图等方向则须列待审。

5.1 坐标与分辨率口径

  1. Viewport 指浏览器网页内容的 CSS 宽高，不是显示器分辨率，也不包含浏览器工具栏。
  2. 设计母版采用 1920×1080 CSS px，主要适配1600×900、1440×900、1366×768、1280×720。
  3. 源图像素与显示像素分列，目标位图至少支撑所需显示尺寸的2×；不是把整个网页用 transform: scale() 缩小。
  4. 2560×1440等大窗口默认居中放置最大1920×1080逻辑外壳，外缘用不承载信息的延展底色／纹理。不能因4K屏让正文任意放大或小地图变巨型。
  5. 100%、125%、150%浏览器缩放需记录实际CSS视口后测试；缩放不能靠反向缩字体抵消。

5.2 主布局方程

记：视口 W×H，外边距 M，栏间距／纵向主间距 G，左栏 L，右栏 R，HUD高 T，底反馈高 F。

中央内容宽 C = W − 2M − 2G − L − R
三栏内容高 B = H − 2M − T − F − 2G

横向：M + L + G + C + G + R + M = W
纵向：M + T + G + B + G + F + M = H
CSS视口 M／G 左栏L 中央C 右栏R HUD T 三栏高B 反馈F
1920×1080 24／16 280 1200 360 72 888 40
1600×900 20／16 240 968 320 64 728 36
1440×900 16／12 224 856 304 64 744 36
1366×768 16／12 208 814 288 60 620 32
1280×720 12／12 192 768 272 56 584 32

这些是明确的设计档位。断点建议：1280、1360、1440、1600、1920；档位间中央吃剩余空间，边栏使用对应档位token。中间宽高不可各自随意写百分比，造成总宽超出。

桌面≥1280且高≥720时，两侧保持常驻。低于这个范围才切紧凑排版：保留当前区域／目标摘要，外围信息以可切换抽屉出现；任何必要操作仍能到达。窄屏是降级验证，不把桌面正式稿设计成移动端。

5.3 背包格位—右栏—图标的联动

右栏边框 b=1，内边距 p：1920／1600档为16，其余桌面档为12；格间距 g=4。令右栏内容宽 Rin=R−2p−2b：

单格边长 c = floor((Rin − 5g) / 6)
背包像素宽 = 6c + 5g
背包像素高 = 4c + 3g
占 a×d 格的物品外框 = [a*c + (a−1)*g] × [d*c + (d−1)*g]
视口宽 单格c 6×4背包总尺寸 2×2物品外框
1920 51 326×216 106×106
1600 44 284×188 92×92
1440 43 278×184 90×90
1366 40 260×172 84×84
1280 37 242×160 78×78

舍入后余量居中或归入边内距，不能偷偷多一列。格位是容器几何，不是“图标512px就占一格”。1×2／2×2物品跨格尺寸必须可见；旋转改变占格，不拉扁图像。数量、资源条、选中／非法放置态在组件层叠加，不烘焙进物品图。

两快捷位各有固定容器与独立数量／资源显示；它们不额外复制背包中的同一实例。关键任务件摘要不扩容。

5.4 中央正常／放大尺寸

内缩 I=16（≥1600）或12（≤1440）：

正常大面板 Wn = min(1080, C−2I)
正常大面板 Hn = min(780, B−2I)
放大面板 Wm×Hm = C×B

当 C<840 或 B<700，战斗和复杂参数默认直接使用中央最大态，不把可用空间二次压窄。放大仅改变可视窗口；不能重新创建角色、重新结算、重新加载场景或触发保存。

普通短详情采用内容自适应的320—440宽起始预算，并受 C−24 上限约束；不是所有说明都用1080宽。正文正常14—16 CSS px，主要按钮文字≥14，辅助说明不低于12；尺寸不足先改布局／分组，再局部滚动，不缩字伪装一屏。

5.5 战斗面板内部再分账

战斗的背景／角色竞技区、标题、时间轴、行动条、结果摘要必须相互留空间。不得把背景先铺满再把时间轴压在敌人脚上。

6. 高度、遮挡与响应式验收

  • 三栏共用同一上下边界，顶部HUD和底反馈不随中央局部滚动移动。左右栏内容过长在栏内滚动，关键状态／快捷位及主行动保持可达。

  • 至少验证所有25页族在1920×1080；P03/P09/P10/P12/P15/P16/P23/P24在1600×900、1366×768；核心三栏、背包2×2放置、战斗、敏感确认在1280×720。

  • 压力视口：2560×1440、1366×650、1024×768、390×844；至少探索、地图详情、药食参数、战斗和保存异常可到达。1366×650可局部滚动，不保证完整无滚动，但不能裁掉提交／取消／退却。

7.3 必须提交裁切和分辨率计算

cover缩放 s = max(槽宽 / 源宽, 槽高 / 源高)
可见源区域 = 槽宽/s × 槽高/s
居中时每侧横向损失 = (1 − 可见源宽/源宽) / 2
所需源像素 = 目标CSS显示像素 × 目标DPR，并结合实际缩放／裁切逐轴核对

示例：3840×2160图用于1440×900档的856×744中央舞台，居中cover只保留约64.7%的源宽，左右各裁约17.6%。因此，重要人物／操作物不能画在靠边10%处。

暂定关键构图区域为源图中央60%宽、15%—75%高；这只是起点。还必须叠加标题区、行动区、正常／放大面板遮挡蒙版验证。仅“主体在中央”不能替代逐槽裁切。非中心焦点需写 focalX/focalY；同一资产的不同用途各自记录。

每件资产登记：ID、对应正式内容、用途、源尺寸、CSS最小／基准／最大槽、fit、crop、alpha、focal、safe zone、anchor、变体组、9-slice参数、导出倍率、文件名与来源。ID仅为设计资产，不是新玩法／存档身份。

8. 战斗视觉与动效：可欣赏贴图，不改变CTB

8.1 推荐分层

即使遭遇固定，也把 场景底板 → 地面／投影 → 玩家／敌人透明主体 → 受击FX → 公开状态／时间轴 → 行动条 分开。

固定遭遇映射可以严格；背景可有针对该敌人的站位构图，但不要把敌人画死在背景里，否则无法换战损、受击、后仰或未来高清替换。三敌不能共用一张不符合地点的背景。

五阶段共用canvas、比例、脚底锚点，建议归一化脚锚 (0.50,0.92)；动作／受击变体也保持该基准。设计元数据同时提供躯干命中锚、轮廓包围盒与允许位移包络。切图不能靠重新自动裁透明边缘导致角色跳动。

8.2 时间轴的演出边界

Owner希望“速度快的标记移动快，抵达临界点触发操作”的视觉效果。本轮必须出时间轴动效样稿，但不能自行把现有CTB改成持续实时战斗。

  • 已知安全接口目前只提供当前玩家决策点及相对先后关系，并不直接提供完整未来队列和可任意显示的精确CTB。
  • 表现只能由正式允许的当前／已提交事件驱动；不能在UI根据系统时间、猜测速度或敌人私有数据跑第二套时间轴。
  • 到玩家决策停点应稳定停住等待选择；用户读说明、看贴图、放大面板不推动敌人攻击。
  • 结算已完成后，可以按真实公开结果依次播放标记移动、命中、阶段切图；动画回调不是伤害或保存的唯一入口。刷新、跳过／减少动画不得重放结算。
  • 更精细的连续标记位置／速度若缺安全字段，交付所需字段、可披露性、事件顺序与暂停语义的接口缺口候选。原型里的模拟位置清楚标记为动效示范，不假称当前安全接口已支持，也不默认公开精确距离。
  • 当前安全战斗DTO也缺少完整敌人名称／素材映射。三敌原画可以按正式内容制作；生产不能只凭地点猜敌、读取内部身份来绑图。将最小公开呈现键列为后续只读接口候选，由主线审定，不在此任务改schema或暴露内部ID。
  • 不显示精确敌人生命或百分比血条；五阶段图、当前公开意图与相对顺序足够。命中数值仅在现有安全事实允许时显示，否则用命中视觉反馈。

8.3 演出状态须出图／原型

普通／放大、等待选择、玩家行动已提交、敌人响应、命中瞬间、战损切换、合法退却、胜利回场景、敌仍活死亡、双方归零死亡。受击短时位移与淡入可用约120—250ms作为表现候选参数，不是游戏CTB单位。

受击建议独立FX＋小幅X/Y位移／旋转后归位，不做整屏猛烈抖动。提供减少动态／静态等价设计，不依赖音频。缩放期间身体锚点、FX命中点与时间轴指示必须重新映射，不能错位。

9. 原型、效果图和资产三者不能混交

  • 效果图：单页全尺寸PNG，显示完整界面和实际中文内容。不得只交一个八宫格拼贴。
  • 可编辑设计源：文字、背景、角色、状态、地图、按钮、面板与组件状态分层；支持改文字和改尺寸，不是一张底图上覆盖热点。
  • 独立素材：无HUD／文字／按钮烘焙的可替换素材。背景、NPC、敌人、物品、FX分别导出；整图裁切只能作参考，不算生产资产。
  • 交互原型：能实际点击打开／关闭／放大中央层、查看小地图详情、选择方法／材料／格位、显示相应状态。它是设计仿真，不接真实S、不写Owner存储、不声称验证规则或保存。
  • 动效原型：展示时间轴与受击／战损切换、暂停及减少动态；标注数据是当前公开样例还是需要未来安全接缝。

代码形式的设计原型只能位于本任务设计目录或仓库外，且与当前应用入口、Storage和生产依赖隔离。不为做原型改package.json或装新仓库依赖。无真实工具访问时明确失败点；不要用“待设计稿”“提示词已写”冒充完成。
