## 4. W1——玩家文案与审查模式分离（要有可操作原型）

### 4.1 交付

在现有设计原型上增加明确的玩家预览模式与作者审阅模式。两者使用同一布局与同一份设计上下文，不复制一套独立页面实现；参数例如view=player/review由Codex确定并写清。默认审阅入口须说明这仍是无真实规则/存档的设计模拟；不能为了游戏感伪装成已经接线的正式游戏。

玩家区移除工程断言和审查提示；作者模式保留这些解释、样例编号、通用FX按钮及检查入口。禁止靠只读CSS遮罩掩盖危险控件：玩家模式内作者导出/写图按钮和监听器也不可用。

整理25页面族当前可见文字的映射表：原文、推荐玩家文案、正式来源/准确路径、保留的事实、所在控件/状态、是否只供作者。实际应用到共享模板，按影响范围生成代表截图；不只交一张措辞表。

### 4.2 最小必须修改

- 背包数字明确标为“负重 x/y”，保留6×4真实格位，装备/快捷计重边界照正式来源；没有事实时不用硬编码数值。
- “明确实例与目标格位”“打开搬运参数”“独立迁移，不复制实物”等改成玩家可理解的对象与动作表达；不能更改opaque引用或自动选择另一个对象。
- 采样保留精力、护具名称、完整度前后、2×2目标要求。默认只呈现实际可读支付，技术计量“请求1/实际1”留作者注释或必要详情；末次/耗尽/未装备边界不能丢。
- 保存失败必须仍表达“操作已生效，尚未保存”；冷恢复不伪造新保存成功。无新IO、无重新加载或补发物资。
- “通用受击FX”“不计算伤害”“不是生产规则运行记录”等退出玩家主操作区；保留整体设计模拟标识，不能把审查样例当实玩承诺。
- 总任务、区域/地点、已知路径、成功/失败/死亡/无后继文案遵守现有公开事实；不新增奖励、商品、继续探索、重接或复活。
- 不改普通动作一次执行、L2必要输入、L3现行保护范围。禁止借文案精简恢复统一确认或删除确认。

### 4.3 验证

以R2原30项隔离回归作为保留基线，不修改原测试或helper。若旧测试仅依赖文字/导出控件：原检查在作者模式继续运行，新玩家模式增加独立检查；不可为通过而放宽对象、资源、身份和终局断言。

真实浏览器代表链覆盖初选→确认→出发、跨区查看、物品详情/菜单/整理、采样支付、战斗/退却、保存异常和终局。只验证设计原型，不冒充S/真实玩法长链。

模式切换与theme切换前后，设计上下文、所选物品ref、任务/生命/精力样例、当前区域与终局保持。玩家模式必须没有作者写图入口。为隐藏审查标记和误显示负重含义建立正反例。

## 5. W2——视觉主题包候选协议、分类模板及真实替换实验

### 5.1 范围

这是设计侧schema/validator/实验适配器与未来契约候选，不是生产主题加载器、引擎SDK、插件市场、动态脚本系统或热更新。主题不得决定规则、秘密、真实物品身份、背包占格、伤害、掉落或存档。

覆盖现有清单全部64份栅格及实际使用的注册SVG/框体/地图标记，保留废弃/历史图为明确状态。数量以实际扫描为准；不把主题逻辑槽位数量强制等同64件文件。一个样本箱可有icon/detail等子资源，但共用同一对象组。

### 5.2 必须交付的结构

- 主题元数据：schemaVersion、themeId、themeVersion、compatibility、baseline/source SHA、状态及来源说明。
- 稳定逻辑assetKey与文件版本/文件路径分离；建立旧文件/资产ID到逻辑键的映射，不能把版本字符串作为唯一游戏身份。
- 分类：场景背景、关键节点近景、玩家/NPC、敌人五阶段组、物品/装备/任务件、框体/控件、地图/状态标记、FX。分类缺资源如实列gap，不凭空画新内容。
- 每个资源：原文件哈希、解码像素、格式/alpha/色彩说明、真实原始像素与后处理历史、呈现画布、槽位约束、fit/focal/safe zone、脚点/命中锚/动效包络、九宫格切边、发布状态与权威公开条件引用。
- 几何约束继承R2；主题换皮不能任意改变三栏、背包格数、关键按钮触达或时间轴披露。颜色/材质token和布局契约分开。
- 反向依赖：资源→使用角色/节点/物品/页面族/尺寸/动效→应联检项；区分真正运行时引用、仅历史引用、条件加载和未观测引用。不能只扫<img>，须覆盖CSS url、SVG href、注册wrapper、JS映射和九宫格。
- 分类模板、中文替换指南、验证器CLI及机器可读诊断。Schema通过与美术合格分开。

### 5.3 三个实际替换实验

在独立设计实验室实际切换：单物品组（绷带）、一个完整敌人五阶段组（优先现有搬运工组）、一套九宫格框体，并可回退基线。更换的必须是同一视觉对象的合法候选；允许明确标TEST的可逆颜色/边缘演示派生图验证通路，不得把TEST处理称为新最终美术。不能只换文件名冒充替换已发生。

同组替换提交要完整声明全部成员及各自版本/哈希；部分成员保留旧图时必须显式声明，禁止缺一阶段时静默拼成未知混合组。组失败不部分启用；成功验证后一次启用展示映射。失败保持原展示映射与原设计上下文，不修改规则数据。

基线已有低清/待清稿必须能以REVIEW_ONLY加载用于比较，同时验证器能阻止其被标成PRODUCTION_READY。测试缺文件、坏摘要、错误尺寸/alpha、非法锚点/九宫格切边、重复key、未知版本、跨目录路径/外部URL、不完整阶段组、角色上下文漂移等；允许明确保留的历史资源不得被误当最终候选。

主题数据不允许可执行JS/事件处理器/外部字体/未知SVG脚本或任意CSS。SVG只限当前所需安全子集，外部引用仅允许包内受清单管理的资源。模板不得接受把伤害/血量/占格规则作为“主题配置”。至少3类业务负控应导致明确失败，而不是导入/环境错误。

## 6. W3——高清与透明清稿的有界方法验证

### 6.1 先验证方法，不再盲做18张

先实际盘点当前可用工具、输出像素、透明编辑/蒙版能力、授权与失败记录。使用现有允许工具，不下载未知模型、不购买软件、不访问新计费API。图像生成与编辑需使用实际图像工具；纯提示词、放大文件头、简单插值、锐化或扩空画布不算完成。

第一关只做两件：
A. 冷藏室bg-h5的真实高像素试产，尽量保持已选构图/焦点/门柜位置与语义。
B. player-back-v2的保形透明清稿，优先非破坏蒙版/边缘修补，避免整个人物重新生成造成服装/姿态变化。

每条制作路径最多2次同类失败尝试；本批全部图像生成/生成式编辑调用上限12次。相同尺寸/边缘问题重复出现就停止该路径，不堆无效请求。工具权限或能力缺口列CAPABILITY_BLOCKED，继续W1/W2/W4。

### 6.2 作者门槛通过后的预授权展开

这不是等待Owner再次确认的节点：作者实测达到下列标准后，可继续同批候选生产；最终仍待主线/Owner认可。

候选独立编号、独立文件，不覆盖R2原图或其metadata；通过也不自动替换默认主题。新资源放新目录、通过实验包映射比较。失败保留诊断与必要样本，但不把多轮大型失败图全部提交Git。

### 6.3 像素与尺寸耦合

按实际槽位逐项计算，不能只看文件宽度或画布数值。
- cover：s=max(Cw/Sw,Ch/Sh)，有效源像素/CSS像素=1/s，目标DPR2要求1/s>=2；同时核验focal和可见内容。
- 1200×888为当前大舞台基准；16:9源图例如3200×1800可满足此槽的像素比，2400×1350则不满足高度要求。建议足量余量，但不能把固定4K文件名当验收。
- 用于其他比例的近景、放大、角色和物品槽必须各自核算；角色呈现画布1536×1920不等于原生PNG，注册放大也计入有效像素。
- 允许真实高分辨率重绘/分区细化的独立方法候选，但必须记录来源和合成步骤，不称为单次原生高分生成。生成式超分若仅可获得，单列RECONSTRUCTED候选，不自动关闭原native2×门槛；禁止因工具限制自行降低既批质量要求。
- 不缩小舞台、人物、正文或改变布局来伪造像素达标。

### 6.4 透明清稿

观察黑、白、棋盘和实际场景；保留头发、布料毛边、武器边缘及有意FX。不得统一阈值硬切导致发丝丢失或锯齿，不把alpha=1噪点减少当唯一通过理由。

记录每次处理的蒙版/步骤、原/后尺寸、alpha分布、非主体孤点、边缘放大图、主体可见包围盒与脚点/命中锚偏差。五阶段必须在同画布同注册下闪切/叠合；不逐张自动trim。原不需修改的RGB不得无理由改材质。候选品质不足保留未采用，不能为了交差接回默认资源。

交付实际候选原图、处理源/蒙版（工具支持时）、四底对照、最大槽位预览、像素与登记报告、失败原因和剩余18背景/主体清单的状态。
