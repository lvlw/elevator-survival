## 7. 尺寸耦合与未完成门槛

### 7.1 原生2×仍未达标
主线逐件核对64PNG实际像素与manifest，64一致。将18份背景按其大舞台目标1200×888、cover计算，均未达到2源像素/CSS像素。
典型1672×941背景的有效密度为min(1672/1200,941/888)≈1.0597。横向宽度足够某一用途，不代表垂直裁切后的大舞台2×已通过。
原生清晰度是美术交付欠账，不得通过改manifest、扩大画布、简单插值或缩小实际舞台暗中消除。若工具不能产出合格源，清楚标注能力缺口；不无限重复同一无效尺寸请求。

### 7.2 alpha确有改善，但不是全部清稿完成
主线只读8邻域alpha>0连通分析复算：
- player v1：外8px非透明17，最大主体外1122。
- player v2：外8px非透明0，最大主体外132。
与作者数字一致。分离分量只是清稿诊断，不能把每个分量都机械当噪声删除；需保留合理细丝/半透明轮廓并核对黑/白/场景背景。
没有把本轮一个玩家图的改善泛化为全部敌人/NPC/物品已清稿。

### 7.3 普通面板不是全部600×360
现有预算normal=min(1080,C−2I)×min(780,B−2I)：
1920档占中央面积79.05%；1600档92.44%；1440档94.06%；1366档93.29%；1280档92.89%。
这解释了为什么“普通”与“放大”感受差别很小。对应来源 `prototype/ui.css:3`、尺寸合同，以及 `reviews/OWNER-modal-size-followup.md:3–7`。
建议单详情/短结果、必要参数、复杂整理/地图/战斗分档；约600×360只作为简单内容的设计起点。不得等比例缩小字和控件，不能因新面板变小使背包格、人物命中点、行动条或素材裁切失效。

### 7.4 真实缩放已有新作者证据
上传Edge记录为100%=2552×908/DPR1，125%=2042×726/DPR1.25，150%=1701×605/DPR1.5，最后恢复100%。本轮读到对应截图和可达操作记录。
它不再只有“尝试快捷键但未生效”的旧记录；可保留为该平台的作者执行证据。主线未亲自更改浏览器缩放，不宣称跨平台/全部状态通过。
