## Owner 阅读入口

**CONFIRMED INPUT — 本轮最新直接授权。** Owner 在本任务中明确：“从单日切片，要升级到7日乃至后面更多日的世界，那必然要在世界内连续驻留，休整等……方向是确定的（详见那2个额外的讨论稿），细节你来定。”因此本稿以世界内连续驻留、实际位置休整为主方案，结合讨论稿的单一精力和目标重设方向展开。**不再把是否采用连续驻留交回 Owner 重新选择。**旧规则不支持这些行为的部分列作后续正式落文差异，不退回每日中枢模型。

**DESIGN DRAFT — 玩家经历。** 玩家进入仍有人等待转运的封锁街区，携回指定病原样本，并恢复医院的本地转运设施。医院提供医疗与样本，物流提供控制组件及支路设备，通信提供核验信息与应急启动模块。玩家在当地过夜，随身物品和已造成的改变继续存在。早取样能尽早确认成果，晚取样能减轻携带压力；调查能减少后续核验成本，直接深入则节省日期但增加风险。完成后必须亲自到达回归位置，显式离开。

**DESIGN DRAFT — 本批重点。** 审阅优先看两条成果线的任务目的、每天一个主要区域与连续驻留的结合，以及受损后能否合理调整。详细问题见[决策队列](10-decision-queue.md)，普通参数交由设计核算，不逐个要求批准。

**ASSUMPTION — 证据等级。** 本包路线与预算是条件性设计核算，不是生产引擎结果。完整世界尚未实现，通关、平衡与分段突破体验均未验收。

## 世界背景与目标

**DESIGN DRAFT。** 感染暴发后，医院停止地面接驳。仍可修复的急救转运升降机连接当地安置点，但旧指令曾把危险引向运输通道，值班人员因而主动隔离支路。广播仍播放过去的接驳通知，不能证明此刻有人接应。记录中的分歧来自不同观察时点与职责，而不是无提示欺骗玩家。

**DESIGN DRAFT。** 异常电梯委托玩家带回指定样本，并恢复能运送担架与医疗设备的本地通道。样本不是疫苗、燃料或万能钥匙；普通组件不制造跨世界能量。任务不要求消灭全城感染者。林岑关心有限医疗物资的交付，周衡关心恢复设备是否重演事故；他们有有限帮助，不能成为主线唯一资格、无限商店或跟随队伍。

**DESIGN DRAFT — 成功候选。** 本地转运装接与功能验收已完成；指定样本仍在角色合法携出容器中；角色存活并到达医院前室的真实回归位置；玩家显式完成委托并回归。组件、材料必须在现场真实使用，任务不能仅按访问次数或独立勾选数判定。最终返回与成功的完整事务待工程契约，不伪称当前已有 Success 实现。

**CONFIRMED INPUT — 保留的终局原则。** 七日是本世界期限，Day 7 仍能行动，没有 Day 8 自由探索；条件齐备可提前结束且不追加尚未发生的过夜。已提交死亡不能被完成任务覆盖，下一晚可能死亡不能提前判死。来源：[DEC-028、035、047](../../05-design-decisions.md)。

**DESIGN DRAFT — 失败候选。** 保留生命归零、感染终末、到期未满足主线，以及明示且无真实替代的关键成果永久遗失。一次撤退、低饱食、可选目标未做、未终末感染或路线暂时受阻均不独立判失败。失败生还回归、期限边缘位置和长期家底代价进入[终局队列](10-decision-queue.md#endgame)，不新增“部分成功”等生命周期状态。

## 世界特殊性与范围

**DESIGN DRAFT。** 以少量设施因果构成世界变化：危险支路隔离后恢复必要供电；接口核验后取得匹配模块；装接让担架通道可用；广播时间戳纠正接驳误判。日期推进不自动复活敌人、补满来源、重新关门或撤销已完成供电。

**CONFIRMED INPUT。** 玩家知识与世界真实状态分离；随机来源必须可复现。明确声明的敌人、物理成果和一次性来源持续，分段突破允许但 Owner 实际试玩仍 OPEN / NOT RUN。来源：[DEC-013、045、048](../../05-design-decisions.md)、[未决清单](../../proposals/small-world/pending-items.md)。

**DESIGN DRAFT。** 首包为医院、物流、通信三个主要区域，医院九节点是未来世界内容，不修改原六节点冻结包。酒店和供电所在讨论稿中的人物、补给、休整与支路职责先折入三地；五地图扩展保留 OPTION，并非 Owner 否决。每天一个主要区域作为本任务仍有效的范围约束，具体连续驻留解释见02。

**OPTION。** 后续更长世界复用日期、精力、来源和任务职责，但须重做期限与经济；七日固定储备不能直接乘成三十日续航。本轮不加入配送循环、商店、多人、队伍、格子战斗、第二世界或实时追逐。

## 独立体系接口化分析

**CONFIRMED INPUT。** 核心为纯 TypeScript；React 只展示并发送命令；规则使用统一可注入随机、标准化效果、唯一可变事实和原子提交。来源：[DEC-006、010、011](../../05-design-decisions.md)、[架构](../../03-architecture.md)。

**DESIGN DRAFT。** Input / Output / Query / Subscription 仅描述职责，不定义代码接口、函数、字段、事件总线或新的 RunState。

| 体系及唯一事实 | Input | Output | Query | Subscription |
| --- | --- | --- | --- | --- |
| 精力：当前额度和上限 | 合法行动成本、休整点目标 | 消耗后额度、合法次日目标 | 当前额度、行动资格和预览 | 参加正式行动／跨日计划；不响应UI重绘，不直接修改生命 |
| 日期：当前日与期限 | 显式过夜、稳定位置、终止条件 | 一次次日推进或终局交接 | 今日、余日、末日资格 | 协调同次跨日结果；切图、归零、现实时间不自动加日 |
| 世界：设施与来源事实 | 合法互动、物理解除、物品移出 | 新的设施条件、来源兑现 | 规则读取真实状态；公开查询按知识过滤 | 只响应内容声明的因果；日期不自动补库存 |
| 任务：要求与已交付事实 | 真实物品转移、验收、信息取得 | 条件缺口、成果、无解信号 | 已满足条件、已知行动机会 | 结果提交后更新公开投影；不复制库存／万能完成开关 |
| NPC：有限需求及交付 | 显式交谈、实物交付、可验证成果 | 有来源情报、有限奖励、反应 | 已公开要求、报价、已兑现情况 | 仅响应列名事件；不自动移动、搜集、过夜补货 |
| 装备：实例与耐久／电量 | 实际使用、适配材料维护／充能 | 资源余量、可用行动、防护效果 | 资格、消耗、修复收益 | 参与对应行动；休整不免费维修或生成旧日工时 |
| 威胁：感染暴露／进展 | 明确暴露、医疗抑制、跨日请求 | 新进展、可见阶段、终末信号 | 玩家只看阶段与已知风险 | 按固定跨日阶段处理一次，不响应日志追加 |
| 健康／饱食 | 医疗、攻击、日级后果 | 生命、伤势、流血、饱食效果和死亡信号 | 公开状态、自救资格 | 危险与消费按阶段处理；不拥有精力目标，不因休整回血 |
| 库存：实例、数量、位置 | 拾取、丢弃、安装、交付、消耗 | 守恒的实体转移 | 几何、重量、来源与目标资格 | 只参与实际事务；切区、对话、任务查询不自动入库 |

**DESIGN DRAFT — 组合次序。** 验证显式过夜的位置、期限与版本 → 持续危险 → 感染 → 饱食及匮乏 → 生还时处理药效／次数 → 所在地精力目标与次日 → 一次验证／提交 → 玩家可见结果通知。任何阶段已经终止，不生成可继续的下一日。展示订阅只能读取已提交结果，不能再结算。提交前错误不留下半状态；提交后保存失败不重跑玩法。

**DESIGN DRAFT — 验证职责。** 单项验证输入输出；组合验证死亡优先、消费和日期顺序；路线验证取得时点、位置和携带守恒；人工试玩判断有趣与疲劳。参数变化须重算，合法状态变化须正式落文与版本处理，接口稳定不免除这些工作。
