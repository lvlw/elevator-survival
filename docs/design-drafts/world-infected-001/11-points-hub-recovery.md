## 1. 推荐带来的实际选择

普通成功路线以0积分入场，在真实完成当地转运、携回样本且生还返回后获得120积分。角色保留受伤与感染；玩家可花40恢复身体，再花18购买一份下次能携带的绷带，留下62积分和真实带回的剩余物资。也可以暂缓治疗、保留全部120，承担下一次明确日结算的风险；返回与奖励不会替玩家自动选择。

严重感染的合法成功末端报价80，积分账可留下40，或买一份绷带后剩22；这是末端身体／交易条件，不冒充已完成的重病全程路线。高损耗成功也不保证总资产盈利：途中已吃掉的药食、已损毁或用材料修过的装备不因积分余款而补回。本稿不按伤势、钱包或损耗提高奖励，也不为了制造负收益另加收费。

第一期推荐 **一种身体服务＋一种可购买准备物**。仅做积分＋治疗可以验证“活着回来有机会修复”，但尚不能充分验证“积累让我愿意完成下一次委托”；一份真实绷带至少让成功收入有当前可用的准备出口。它仍是很窄的动机验证，不等于完整成长系统已经成立。

## 2. 积分归属、范围与唯一事实

| 事实 | 本期候选职责 | 明确边界 |
| --- | --- | --- |
| 可消费积分 | 同一角色历程的唯一余额，初始0 | 不属于可继承的账号钱包；任务间延续，角色实际死亡后不可用 |
| 任务结果／评级／历史 | 真实执行的只读结果与履约证据 | 本期不新增评级算法；历史不是可再次领取的奖励包 |
| 兑换资格 | 从该角色已正式成功的委托事实判断 | 花光积分不撤销资格；资格不自动生成商品 |
| 实际拥有物 | 唯一库存中的真实单位、位置及 ItemState | “可购买”不是“已拥有”，资料或按钮不能当实物 |
| 经验／等级 | 本期不创建 | 不把累计收入、当前余额或完成次数改名为经验 |

**余额为0—2,147,483,647的整数。** 小数、负数、布尔值、非有限数、越界值、缺失金额及非法来源均拒绝，不取整、不修复、不创建欠款。正常支付必须足额；不足时钱、物、身体和操作完成事实都不变。失败罚是本页明示的有限扣款政策，不能把这一例外推广成商品可赊账。

本期在任务世界内不赚取、支付或转移积分。确认接取前要求 `当前余额＋本次最大可得120 ≤ 上限`；超过则拒绝接取且不耗供给、不推进日期。玩家可在中枢进行有真实用途的消费后再接取。已接委托因此有足额入账空间；成功不得被静默截奖。通用消费／收入请求仍须检查整数加减与来源，溢出请求全部拒绝。上限是数据边界，不用作经济平衡手段。

积分账户只接受“属于哪个角色、哪次正式来源、什么原因、多少积分、前提是否成立”的受控请求，不认识H0、病种、床位或地图。任务、健康、目录各自拥有资格和计算，返回／购买／治疗协调在一个确定性操作内组合它们。读余额、报价、显示结果和 React 订阅均只读。

## 3. 收入怎样兑现

| 只取得样本、只安装设备、只完成调查、只到过地点 | 0 | 可记录真实部分成果，但不变成完整成功或提前奖；本期无额外成果积分 |

任务说明在接取前公示120和失败后果。实际入账只有一次：**已发生的行动／日级后果 → HP死亡判断 → 本次任务出口与实物资格 → 唯一成功或失败结果、合法实物交接及积分收支同时提交 → 静态中枢整备 → 玩家显式治疗／购买。** 条件齐备的正常H0返航不追加未来过夜。奖励不能先拿来治好本已死亡的角色；合法生还者也不必先交治疗费才能领取本次奖励。

奖励绑定角色与本次唯一执行身份（沿用既有 RunIdentity／规则版本设计边界），不只绑定世界名称。同一世界的另一委托必须有新的执行身份和自己的成果；不能继承上一委托安装、样本或已领奖事实。当前唯一执行从活动到终止只提交一次，重载终止页、重复发结算请求、保存失败后重试显示均不能再入账。最小设计用“该执行已终止且奖励与结果同时提交”的正式事实守住幂等，不先建设任意可改的已领奖ID全集或第二套事件仓库。

## 4. 失败代价与20E反例

**推荐Draft：当前委托所有失败生还，扣 `min(当前积分, 30)`，并回收本任务新取得、尚未消耗的普通物。旧中枢库存与真正携入且仍存在的普通物、装备及其当前状态保留。** 这是对失败携出范围的实质性新处罚候选，应在接取时明示为委托的失败回收条款；它不是 Owner 已确认的普通实物延续方向自然推出的规则，也不是隐藏提取配额。

新组合 **替代** v1.1“最多口粮1＋金属1”，不再叠扣粮金；期限异地生还也不额外丢弃全部旧背包／快捷物。异地必须承担其已选择截止日的真实健康检查与任务失败，不能据此减免已经发生的病程。成功不收30，也不回收成功合法带出的普通物。少了120成功奖是机会损失，30扣款和新物回收才是明确处罚。

| 来源或处理 | 失败后结果 |
| --- | --- |
| 出发前留在中枢的旧物 | 不因本次容器交接被覆盖；保留原数和状态 |
| 真实携入的旧单位仍在背包、快捷或装备栏 | 按返回时状态保留；途中已用、已交、已丢的旧物不补回 |
| 当前委托新搜出／交换得到的普通物仍存在 | 失败回收；换槽、合堆、拆堆、装备或重新拾取不洗掉来源 |
| 旧绷带1先用掉，再拾取新绷带1 | 新绷带仍是新来源，不能按“出发前也有1”当旧物保留 |
| 新物在世界内已合法使用 | 保留已经产生的真实HP、饱食或维修结果；不倒扣身体或倒退耐久来伪造回收 |
| 样本、任务专件、门卡、地面遗留物 | 按[终局稿](reviews/endgame-candidates-v1.1.md)处理，不因为积分规则变成普通家底 |

这一候选需要库存保留可追溯的单位来源，混合堆叠的各来源数量必须守恒；不是依靠总数量相减判断归属。**消费次序Draft：** 对已选混合堆叠优先消费本委托新单位，再消费旧单位；同类来源按稳定来源身份排序。若已选择快捷位中的独立单位，则消费该真实单位，不越容器换药。拆分／转快捷同样按这一公开次序，不允许改写来源；NPC交换所得全部是本次新取得物。新旧数量及失败会收走多少应可查，避免用隐蔽会计惩罚玩家。取得、消费和维修仍只有原有真实物品事实，来源标签不是第二份可领取库存。未来工程还须验证此混合来源合同、严格恢复与提示，不能用设计脚本的标签字典冒充已实现的 ItemState。

**直接囤药反例。** H0→H1→H2→药房暗搜→取绷带→H1→H0，共20E，无战斗且不依赖随机附加。0积分者失败扣0，新绷带回收；本次不能净带出绷带。再次接任务前必须经历第6节真实休整，不免费刷新精力、饱食、医疗次数或起始物资。

**仍存在的转化收益。** 先使用新绷带再失败，可以把药变为已恢复的HP；新金属先修旧工具再失败，也保留实际修复。无感染的HP受损角色，在饱食耗尽后可用每轮绷带+1抵消任务间饥饿−1，维持身体而无积分／囤药增长。该方式不因“来源一次性”被消除：压力见证明确提供10个不同执行身份的新委托。主案没有完全封闭故意失败收益，需比较10次完整成功的积分、物资、维护和日期，不能只报告库存没有上涨。[07生存专长候选](07-enemy-continuity.md#minimal-specialties)的任务内绷带+2还可能使这种循环逐轮净回复HP；无专长+1基线的持平结果不覆盖这项OPTION，须独立列例或明确未运行。实际联合结果以[08](08-balance-budget.md)和[evidence](evidence/README.md)为准。

**替代，不同时启用。** 重复委托可收12积分接取费（第一个0，其后每次实际接取时支付，不与本案默认叠加）；或让新的委托按明确有限供给发放。前者使0积分者无法无限启动下一轮，但会让首个任务失败且无钱的人活着停在唯一内容版中枢；后者减少重复取物，也会牺牲可重复游玩，供给耗尽不等于玩家已死亡。这两项不能靠隐藏补给、自动卖物或换账号许可掩盖代价。主推荐暂不收费、不伪造有限供给已获确认，保留上述残留风险供 Owner 权衡。

## 5. 一项完整身体恢复服务

### 5.1 可用窗口与报价

只在真正完成生还返回的中枢可用；世界内H0仅是返航节点，尚未正式返回时不能远程治疗。HP必须大于0；服务不要求满精力、下一日、未用医疗次数或曾经成功。失败者有旧积分即可在返回后立即用。所有当前身体问题一次处理，不拆出十几项手术。

按病因分三档，按下表自上而下选择，**不相加、不按钱包定价，也不按每滴HP报价**：

| 当前真实状态 | 全部身体恢复价 | 判断理由 |
| --- | ---: | --- |
| 感染进展≥90，仍活 | 80 | 危急／高阶段感染需要更昂贵处理；120不再独立致死 |
| 感染进展1—89，或未结算暴露>0 | 40 | 需要处理感染／暴露；HP1或HP11不改这一档 |
| 感染0、暴露0，但HP未满、流血或任一本期伤势仍存在 | 20 | 身体损伤修复；不再细分HP阈值 |
| HP满、无流血、无伤势、感染0、暴露0 | 0／无变化 | 返回“已无需治疗”的no-op，不扣钱、不清药效、不刷新任何资格 |

待比较的简单总价是任何身体问题一律40：规则更短，却让一滴擦伤与危急感染同价，弱化预防和自救的费用意义。推荐上述病因三档。早期讨论的HP9／HP5档已撤下：它会使一份绷带跨过HP门槛就省40，不符合少量可解释状态报价的目标。

### 5.3 操作边界

报价是只读投影，包含服务版本、当前身体摘要、准确价格和当前状态版本。取消不扣钱、不治疗。显式提交时再次验证角色仍活、人在合法中枢、状态未变、价格和余额足额；不接收客户端指定效果或自报低价。

合法操作将 **扣积分、全部覆盖效果和完成结果** 一次提交。报价后用药、食用口粮、购买、修理或其他正式状态变化使旧报价失效，即使价格恰好相同也先拒绝再报价。重复旧报价拒绝且零变化；治疗后针对最新健康状态重新请求是0消费no-op。这样不需要建立任意请求ID的永久收藏表。

保存／严格恢复的原子性是未来工程验收要求。本轮只能检查输入到后态与重复拒绝；不能声称已经验证生产存档。未来保存失败须遵守既有“已提交内存结果不自动回滚、不重跑玩法”的边界并显式提示，不能通过自动重发治疗来补保存。

### 5.4 药物不会失去职责

世界内药品负责让角色活到真实出口；积分服务不从深处接走角色。绷带可及时止血，避免每个付精力行动的流血损失和下一夜2HP；急救包用于真正需要的HP与合格轻伤；消毒剂减少未结算暴露，抑制剂只延缓增长。

- 例：HP4／感染25，先用绷带到5后仍报价40。为未来反复跨HP档节省40的路径已经移除。
- 例：HP11且无伤势／病原负担，花18购买并使用一份绷带达到12，可免20身体服务而保留2积分；这是明确允许的实物替代。HP10需要两份36才补满，直接20服务更便宜。已有绷带的机会成本是少一份下次急救品，不是“免费+1”。
- 例：感染0／暴露1，尚未用当日消毒剂且有旧药，可先清暴露，把40档降到20或无需治疗；用掉真实药且计当日次数。已有感染不能这样倒退，抑制剂也不会降低既成报价档。
- 新伤势仍存在时，绷带只处理伤口而不删除伤势记录；即使HP已满，本期完整身体服务仍可报价20。不能为省钱假装伤势已经消退。

## 6. 钱不够时：静态窗口、真实下一日与风险

中枢没有现实倒计时。阅读、报价、取消、关闭页面、加载结果、整理、合法药食及购买／维护本身不推进日期，不触发离散病程。主推荐没有免费稳定服务、自动赊账、负分处死、自动卖物或充值复活。

**任务间生命周期Draft。** 正常成功／失败在真实角色日D返回，保留D的精力、药效、日次数与标志额度。可先领已经合法提交的收入，再明确治疗、用药、进食和维护。接下一委托前须显式进行一次中枢休整：按[终局稿](reviews/endgame-candidates-v1.1.md)的流血→感染增长及HP损耗→饱食顺序结算；实际仍活才结束药效、刷新日限与标志额度、角色日+1、精力目标100。休整不回血、不自然消伤、不修装备。

该完整日结算一次提交后可以继续静态整备，再到新委托的真实H0起点。新任务显示Day1只重置本次任务期限，不重置角色日、疾病、物品或刚建立的额度；不再发初始装备和绷带。若Day7截止已完整执行同一日健康结算并将角色日推进，则已满足这次换任务的日推进，不再额外补一晚。任务Day8始终不存在。休整后再耗用的日医疗次数／精力保持真实值，出发不会再刷新一次。玩家若主动再度休整，必须明确选择另过一个真实角色日，再承担一次相同健康顺序；旧休整请求重放不能自动多过日。

## 7. 最小目录、解锁与等级选择

| 候选项 | 本期地位／价格 | 资格 | 实际得到什么 |
| --- | --- | --- | --- |
| 完整身体恢复 | 主推荐首期服务，20／40／80 | 当前角色仍活且正式返回中枢，无成功门槛 | 第5节明确身体效果；无实物赠品 |
| 一份绷带 | 主推荐唯一首期商品，18 | 该角色至少一次正式完成本委托；真实结果可派生，失败／只取样不算 | 现有 `consumable_bandage` 一单位，正式存入中枢真实库存 |
| 一份急救包 | **未来OPTION，45，不开放、不计当前战力** | 候选为同角色两次真实成功后开放，尚须任务供给审定 | 沿用正式急救包1×2、重2、不可堆叠；不能沿用有限旧夹具中简化的1×1尺寸 |

购买按单单位进行，检查资格、明确商品、足额余额及合法目标容量，18积分与一个真实物品在同一操作提交。余额17、未解锁、重复旧请求、目标不能接收或过期选择均不扣钱、不产生半个物品。没有退款、卖回、随机商品、每日免费补货、贷款或玩家交易。目录可连续按真实钱购买，不以隐藏限量保平衡；任务内不能远程购买。

首次120成功收入确实在当前版本解锁绷带，并能立即支付18；资格不会在买完／治完只剩0时回退。历史中别的角色曾成功不替当前角色开放购物，死亡后也不把旧余额或旧商品继承。账号可展示历史成绩，但“已看过图鉴”不等于可用家底。

本期不建设等级／经验。当前只有一个资格门槛和一项横向准备物，真实履约已能解释何时开放；加经验条只会多存一条可漂移的成长真相，不能补充独立玩法。以后若确有多个能力路径、节奏或反复练习需求，应另外提出机制与证据，不先填空等级字段。

## 8. 装备准备与正常净所得

身体服务不负责装备。生还后可在中枢使用[05的维护候选](05-resource-economy.md#hub-maintenance)：0E但真实支付材料，机械金属1恢复总计15、布1恢复外套6、电池1补手电4、金属1＋电子1恢复工具箱3，各到上限且不复制恢复量。该终端服务是明确新增的中枢候选，世界内的6／4／8E维护仍有效。0E不增加精力、不推进日、不等于材料免费。
