## 2. O1：拟采纳的规则范围

### 2.1 单精力与动作资格

同一驻留共用一份精力。一次合法移动边、搜索或明确互动，只在开始时精力为正且其他必要条件满足时启动；成本可高于余额，动作完成后精力截为0，不形成负数、未来扣债或额外生命罚。多边队列必须逐边重新验证，不能整体包装成“最后一动”。

E0不取消已经触发的战斗、流血与立即结果，不允许用睡觉或召回跳过。免费行为不自动获得资格：整理、拾取、药食必须处在对应合法稳定上下文，检查真实目标／实例／容量／限次；任务提取不能改名为拾取。世界内维修／充能、NPC交付交换、装接仍需正精力。中枢服务和材料维护的具体合同继续留到相应经济／内容阶段，不把世界内成本直接移植为中枢限制。

休整地点资格来自正式内容与真实到达／清除危险条件，不是任意房间都能休整。A/C的作用只表达不同精力重设目标；具体节点清单和开启条件不由本次G1纯核心注册。

### 2.2 身体与角色周期

流血、伤势、暴露、感染进展、饱食各司其职。合法周期检查先验证完整前提，再按流血→感染→饥饿处理；任一阶段HP降到0立即形成死亡结果，后段不执行。HP为0才实际死亡，不将感染达到120单独当作死亡。

仅活着才结束本周期镇痛／抑制药效、重建约定药品及标志行动额度、推进角色周期并重设精力。休整不自动回血、止血、治伤、修理、充电或补给。合法致死是已经执行的规则结果，不是允许撤回的非法请求。

### 2.3 任务日、正常返回与截止

角色周期与当前委托任务日分开。跨图、现实等待、读取、Task Day1编号均不创造新周期。正常返回（含Day7）无附加夜，进入静态中枢；未来实际存在不同可接委托时，才在完整合法出发边界按最新整备状态完成应有衔接。

Day7明确异地稳定截止先结本期身体后果，活着才失败召回、完成本周期衔接；不生成旧任务Day8，不把同周期再结一次。ready必须引用最新期限关闭、执行和已结周期；首次ready只在真实首次D1。已消费之后的新周期仍有自己的后果。当前只有一份委托，没有后续内容则不出发、不消费ready，也不因无内容制造伤害。

这些行为承接已有确认；R1的start/end周期与bridge是实现组织建议，生产阶段以最小唯一事实与严格绑定为准，不能建立第二关闭账或永久免检布尔。G1只处理自身纯规则／时钟职责，不拥有全角色历史或安装权。

感染公式：`I' = I + max(0, b(旧I) + 20×待转换暴露 − 当期实际抑制)`；清已转换暴露，再依新I'扣HP。典型见证：I59→69；I89→104；I110→130。使用实际抑制15时，I110→115，病程损2而非3；不保证任何药物都能救活。

以下依然是Draft或后续待审，**不随本次批准**：`prices`逐行动地图费用、`load`负重分档、`movement_contusion`倍率、`combat_energy`及其defense_divisor、`limits.grid/max_weight`的新版本内容采纳、`rest_nodes`地点清单、`medical`整组、绷带治疗量与口粮恢复量等具体使用效果、具体装备参数。既有旧医院参数继续按原版本生效，不因列为新版本后置而被删除。

G1的通用cost参数可用2、8等明确测试夹具验证取整、零值和透支；这种单元夹具不把“某条医院边价格为2”或“五图移动均为8”正式化。其他相互依赖的内容参数应在对应接线前按一批集中审定，不要求Owner逐项手算。

`failure_penalty=20`是已确认的当前委托条款，不是本次新选定的全局默认；G1不实现扣款。成功120、服务20/40/80及商品价格全部排除。

## 4. O2：持续现场、可知信息与恢复合同

### 4.1 玩家层面的局部规则选择

同一个活动执行内，内容明确的道路／安装成果、具名敌人剩余生命／下一意图／风险进度、一次性来源、已揭示地面剩余物和已获知识跨图跨夜持续。结束过的战斗临时CTB不自动带入下一接战；仍在进行的战斗也不能借跨日刷新。已获知识记录合法观察，不显示远程未观察位置的最新精确危险。

地面物可作为当前驻留内留置物，回去仍须真实路径、稳定节点、合法实例和容量；不会自动送回背包或中枢。正式成功／主动失败／期限失败关闭后，原地面与现场只有历史含义，不能继续拾取，不能由另一委托的同名地点重新访问；合法携出物保留真实状态。

这是对新连续驻留版本相关旧Scene结束边界的**局部采纳**，不倒改旧医院DEC-045／048、存档或既有测试含义；不把世界内临时留物推广为跨委托仓库。它会降低同一驻留内跨夜遗失压力，但保留一次性来源耗尽、运送成本和委托关闭损失。

### 4.2 工程合同选择

冷启动没有现存内存历史，不应伪造“独立当前期望”。允许新增受控冷候选解析入口，使用严格根角色、受控内容／规则声明与整档内部一致性检查；返回候选，没有安装权。原 `restoreMissionCandidate(raw, expected, scope)` 及K18/K19同进度恢复要求保留，expected不能改可选，也不从候选复制一份冒充独立证据。

唯一应用状态持有者负责一次bootstrap／完整校验／一次安装；只有真正成功读取null才能进入无档首次创建路径。损坏、不兼容或读取失败不得兜底重建角色。已有当前状态时禁止第二bootstrap、旧快照replace及重建空事实绕过关闭。

规则体系在明确、有序、确定性的编排中提出计划，由唯一入口合成完整身体／物品／周期／任务后态；涉及经济和终局的入口，必须等真实业务全部可完成后再开放。不能先提交closed再依赖监听器补奖罚。一次完整提交、一次保存尝试、一次只读通知；写失败保留已提交内存并单独报错，不重放玩法。

冷候选、单owner或Object.freeze均不是绝对离线防篡改／防回滚。多标签与浏览器IO必须在公开接线前实际验证；首批headless支持矩阵可以显式拒绝未支持阶段，但不能永久删除战斗保存、终局或角色延续责任。

O2批准的是上述规则与合同边界，不是提前创建完整Profile、通用任务SDK、跨世界供给、全量存档架构或新增玩家入口。具体新接口名、版本ID、文件路径以对应工程任务明确为准。
