# 终局资格与完整清算候选

**DESIGN DRAFT / 待采纳。** 来源状态逐项见[来源表](01-source-and-adoption-map.md)；本页不是生产支持声明。字母C为本批条款定位，不是DEC编号。当前内容为《封锁区·未完成的转运》，五图结构不变。

<a id="C01"></a>
## C01 成功与返回资格

推荐由受控任务内容生产者持有供电设施、转运进度与指定样本绑定；实际移动生产者持有当前位置、合法到达结果及待立即结算危险。命令只表达“交付／撤出”意图与身份、revision，不接受success/dead/supported布尔证明。UI不能填目标完成或隐藏感染值来取得资格。

完整成功同时要求：当前角色这份具体委托active且执行一致、HP>0、当前H0电梯前室、合法移动到达已结算且无战斗／立即结果、任务要求的供电与本地转运完成、指定来源和实例的样本在实际背包。无需访问酒店，不按访问地图数或普通战利品数量发奖；重伤不减声明奖励。路径合法性由G2受控提案保证，不由终局重新搜索五图。

| 样本状态 | 结果 |
| --- | --- |
| 地面、NPC／已交付、真实毁失 | 无本次完整成功资格；拒绝成功意图，保留前态，可在合法H0选择失败撤出 |
| 实际背包但其他目标未完 | 同上；不能凭样本单项领奖 |
| 同名假物、错误定义／来源／执行或错误ItemState | 非资格凭证；校验失败零副作用 |
| 正确背包实例＋全部目标＋合法H0稳定生还 | 完整成功；交付一次，按声明全奖 |

实际G4只实现普通物拾取；五图任务件生产者尚缺。近期纯核心可使用明确标记的受控内容夹具，不开放请求写facts。源码探针不证明这些内容已经生产可用。

<a id="C02"></a>
## C02 生还失败与单次关闭

当前Owner已确认：合法失败返回收入0、扣一次 `min(P,20)`；P=0扣0，P=19扣19，P=20及更大扣20，不造债、不自动卖物、不叠旧粮金罚或来源罚。普通合法携出与旧中枢家底保留。失败判定本身不致死，委托关闭而生还角色继续。

推荐正常H0意图分流：完整资格时交付成功；不完整时明确“放弃并失败返回”。具备完整成功资格时拒绝失败意图，避免误弃奖；这是本轮局部Draft，不是新增失败处罚。合法退出结束委托，不是任务可续做的中枢往返。没有下一份真实任务时停留，不伪造继续入口。

<a id="C03"></a>
## C03 Day7稳定截止

沿用DEC-050与003D：异地稳定节点明确截止（当前不在H0）；H0改走正常成功／失败返回，拒绝截止意图，不以截止额外结夜。待战斗／立即结果先解决，精力0和现实时间不自动触发。周期生产者先验证输入与所有算术，再按已批G1血→感染→饥饿及HP0短路；活着才完成当前周期、刷新一次额度并产生deadline-ready。委托仍以第7日结束，不生成旧任务第8日。

HP0直接death，无奖励、无罚20、无召回／复活；保留导致死亡的实际身体和效果，D不虚增。活着则deadline-failure收入0扣一次20上限，连同物品处置进入living-hub。正常已返回者不再进截止入口。

<a id="C04"></a>
## C04 正常返回和静态中枢

正常H0成功／失败，包括Day7正常返回，采用现有normal-return生产者：不补夜、不推进D、不刷新额度，产生return-due（绑定本次关闭身份、结束D/T）。先完成全部终局清算才发布中枢结果。中枢查看、整备和结果摘要不结病情、不自动治疗或进食。

deadline-ready仅证明来源关闭所标的同一周期已结过；未来实际合法新出发只消费该一次性来源，不重结或重刷。以后新周期仍须正常结算。当前无新任务时，due/ready均静止。下一次明确出发前读最新状态解释可知风险并允许返回整备，不要求全满；本批不实现提示。

<a id="C05"></a>
## C05 真实死亡的消费

动作死亡消费G2已生成、绑定完整前态的一次提案（含动作效果、物品变化、位置与HP0）；休整死亡消费G2 `planResidenceLocationRest`已校验地点后返回的LocationPlan（内部G1结果不重新获取）；正常返回／截止则由受控组成直接调用G1一次，绑定完整前态后交给终局核心。不得重跑动作、随机来源、流血或感染，也不能把已经执行的合法死亡当非法请求恢复HP。非法／伪造／过期提案仍应在提交前拒绝。

**R1输入边界：** 已执行、尚未关闭的死亡提案须在原值尚存时完成专用校验：完整结构、所有原数值、角色/任务/执行与独立current绑定、阶段及尚无终局凭证、生产者无权改写的钱包/关闭账/既成历史。允许真实HP0，不临时改HP、phase、mission或revision来套用生还校验；验证后复制提案再清退，最终dead聚合另验。steps须先非空、元素为字符串且序列/来源相符，之后才能取末项；普通异常不算语义Reject。

有限模型现有producer只改变`body.hp`，`snapshot.revision`保留current原值；其他body/现场/实例/状态/容器/历史均保持独立current。固定流血来源另核前态HP位于可致死范围，仅作范围比较，不重新执行伤害。合法死亡消费再递增一次。此为固定夹具原有语义的严格化，不是实际G2 LocationPlan格式或签发证明：真实G2已有动作revision与效果，工程须消费其一次结果。

本期活动内死亡后，这份active任务以death关闭一次；当前可用积分归零、角色现有可用物品进入不可继承记录；此前成功、交付、安装、消费与已扣罚不改写。留地物归不可访问历史。新角色不继承旧家底；本轮不创建新角色入口。未来实际新出发在激活新任务前死亡时，旧任务结果不改、新任务不得虚构death关闭；该跨委托协调不在本期单任务模型范围，须后续专项验收。未来任务中死亡不能重写本任务旧成功，有限模型仅用历史清退子组件见证此原则，不伪称第二任务已经实现。

## C06 实物分层与推荐处置

生产候选沿用ItemInstance＋ItemState一一关系、真实容器引用和实际剩余资源；定义／来源决定任务用途，显示名不决定资格。一个实例仅一个位置，既有消耗、安装等是事实历史，不是可用库存。资源范围按各定义校验，不能统一恢复满耐久／电量。收藏品／纯情报不混入普通携出；收藏提取当前未支持并留内容Gate，已有收藏历史不得倒改。

| 终局时归属 | 生还后态 | 死亡后态 |
| --- | --- | --- |
| 背包／装备／快捷位普通合法物 | 实例、数量、耐久、电量与效果原样留在角色；不额外清空 | 当前可用物转不可继承，保留原实物记录 |
| 旧中枢普通家底 | 不额外没收 | 当前角色家底不向新角色继承 |
| 携回指定样本 | 成功正式交付；失败推荐记部分交付且收入0、不可领回补做 | 当前未处置件不可用，不伪造曾交付 |
| 未安装任务专件／当地权限 | 推荐交回／失效，不转永久普通资产 | 不可用 |
| 地面及未实际携出 | 原世界不可访问历史，不能在中枢复制 | 同左 |
| 已交付／安装／消费／毁失 | 保留原历史、不重生、不允许补另一轮成功 | 同左，死亡不得改成统一“本次丢失” |

任务件具体交回／部分交付／失效是Draft（O2），普通物保留及不改历史是既定方向。提前交样后不可重接补齐，不引入保管重领。生产“不可用历史”不是无限背包，也不新增物品ID或正式清单。

## C07 四结果互斥与一次资格

| 结果 | 合法前态／意图及事实 | 规则顺序 | 完整后态 |
| --- | --- | --- | --- |
| success | active；H0交付；C01全部真实事实 | 正常返回不结夜→样本交付及任务件清退→全奖→关闭 | living-hub、body/D不变、due、普通物不变、一次收据 |
| voluntary-failure | active；H0撤出；不完整但合法生还 | 正常返回→任务件清退→0收入／一次扣罚→关闭 | living-hub、due、真实普通家底、失败收据 |
| deadline-failure | active Day7异地稳定截止；周期后HP>0 | 一次G1日结→任务件清退→0收入／一次扣罚→关闭 | living-hub、ready，D前进一次、T终止于7 |
| death | active真实动作／日结结果HP0 | 消费已结效果→可用资产不可继承→0收入→关闭 | dead、真实死亡body／周期位置、无召回、历史完整 |

上述顺序在临时完整候选中计算，只有一处提交；“先关闭再监听补钱”不合法。同一意图不能既成功又期限失败；命令串行，旧revision／已closed重复直接拒绝。换execution、标题、刷新终态或重造unaccepted不能再奖罚、再交付或重开。只读摘要来源为已提交收据，不调用结算。

## C08 严格恢复及历史

见[恢复合同](03-state-ownership-and-restore.md)。根角色、声明全集、任务事实、完整身体、cycle/clock、钱包收据、实例位置和任务处置联合核对。closed不是active轻改phase；dead不是HP0的living。既有历史用独立expected恢复；冷档内部自洽不证明历史真伪，不承诺防用户离线回滚。已有current拒绝二次bootstrap／replace。原始active＋HP0只在受控提案校验内部短暂存在，不能冷恢复或安装；最终dead仍要求完整清算。

<a id="C09"></a>
## C09 完整事务、故障与保存

1. 在任何抽样／周期执行前检查命令形状、安全整数、身份、revision、阶段与受控生产者前态绑定；此阶段错误为零生产者调用、零提交、零写盘、零通知。
2. 生产者在私有输入上执行一次。先按C05校验原始提案，拒绝时记录已调用一次，但current/disk和原提案对象不变、提交/写/通知均0；`plans=0`仅表示无完成计划。通过后才复制、清退、构造关闭/钱包/收据并验证完整后态；不重算伤害、随机或物品效果。生产者内部不得先改变current。
3. 会话唯一所有者原子替换完整current；保存完整新格式，再通知只读结果。不得分钱包与任务两次安装。
4. write失败保留全部已提交内存、标记未存；重试只写最新快照，重复点击不能再结算。重入在busy阶段拒绝，通知抛错不撤销已提交结果。
5. encode/语义校验失败属于提交前错误，不能先装一半再发现不可保存；新格式支持须先于会话准入。真实崩溃跨进程只能恢复最后成功持久化记录，本地存档不承诺反回滚或跨设备恰好一次。

<a id="C10"></a>
## C10 必要数值与溢出

[配置候选](config-candidate.json)仅四数值：120成功、初始0、2147483647上限是Draft；失败20是Owner已确认当前条款。金额、revision、D/T、物品量及运算输入必须非负有限安全整数，排除bool；body与资源遵守各自边界。输入非法不能因最后HP0／清零／扣至0而被洗成合法；原提案revision等字段在覆盖前严格排除负数、bool、小数、不安全数及NaN/Infinity，合法但越权的数值变更也不能靠范围检查取得权限。

主推荐沿用旧Draft的接取前“预留空间”语义，但只作容量守卫，不新增冻结资金或第二钱包：确认本次声明reward后，在G4 launch调用内容工厂、结周期、抽样与提交前要求 `P <= max - reward`。活动期间当前无其他积分收支；恢复active也验证该不变量。当前合法active据此必能全额成功结算。完整success余额等于上限可接受。

替代“终局才检查上限”会让合法成功卡在结算，截奖／先closed后错均不可取；无界整数需另改表示和格式，不在本期。外来高余额非法active拒绝恢复，绝不悄悄裁剪。若未来加入世界积分收支须另批空间策略，不把本候选当永远通用。
