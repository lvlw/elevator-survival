# 新感染驻留：完整终局与关闭态恢复补充合同 v1.0

状态：已批准边界的正式定稿；未实现完整终局恢复，不是生产开工任务书。日期：2026-10-04；归档任务DOC-WORLD-ENTRY-003。

依据：[获批稿](../../design-drafts/world-infected-001/entry-003/adoption/inputs/WORLD-ENTRY-003-ADOPTION-owner-review-v1.0.md)第3—4节及[Owner实际批准](../../design-drafts/world-infected-001/entry-003/adoption/inputs/OWNER-approval-WORLD-ENTRY-003-ADOPTION-v1.0.md)。正式玩法见[DEC-051](../../05-design-decisions.md#dec-051)；本合同补充[原O2恢复合同](runtime-restore-supplement-v1.0.md)，不替换原首身份契约、G1契约或G1—G4历史支持范围。

## 1. 唯一所有权

会话持有唯一完整current。角色／规则／配置绑定、任务事实全集、钱包、身体与周期、真实位置／现场／任务进度、实例及资源、已发生处分各有唯一事实所有权。终局收据只记已发生结果、金额与实物引用，不成为第二份可用余额、库存或接取资格。

原`restoreMissionCandidate(raw, expected, scope)`的expected来自独立现存权威，不能可选、从同一候选抄出或靠换ID绕过。冷启动确实没有内存历史时，受控冷候选只能证明独立声明下的整档内部一致，不能伪造已有expected，更不承诺防用户离线回滚。

规则体系可以在明确、有序、确定性的编排中提出效果，由唯一入口组合提交。展示订阅／提交后通知只读；不以多个异步监听器分别发奖、扣血、移物和保存，不建通用事件总线或完整Profile框架。

## 2. 四类后态和联合验证

| 状态 | 必须验证的关系 | 不得冒充 |
| --- | --- | --- |
| fresh-hub | 真实首次创建条件、正确根身份、声明全集；初始钱包0；无已有关闭被抹去 | 清空旧角色、坏档重建或给旧角色换初态 |
| active-world | 仅一份活动执行、完整身份／版本／目录绑定、合法D/T、身体／现场／容器及全奖空间；可保留真实先前关闭历史 | 活动HP0中间提案、两活动、遗漏声明、换执行重开 |
| living-hub | HP>0，本次任务与收据已完整清算并关闭；最新合法source匹配；正常return-due对应结束周期，期限deadline-ready对应已结周期之后且任务日终止于7 | 只改phase的旧活动态、无账关闭、旧ready免新后果 |
| dead | HP0，实际死亡来源及已结效果完整；当时活动任务死亡关闭；当前可用余额／资产不可继承，历史处分保持 | HP0的living、复活／召回、未清算的活动提案、给未激活任务伪造death |

根角色、规则版本、G1配置身份和终局配置身份须分别严格绑定。终局配置是独立依赖，不取代已有CharacterCycleState.identity.configurationId中的G1配置，不复制其34项数值。具体字段组织可在工程详细设计中确定，但不得缺失可验证绑定、持久化派生缓存或新增第二真相。

声明与生命周期值齐备，无同角色具体委托重复、无两活动、无交叉执行；旧成功与新活动及后续死亡的两声明完整历史仅用原生测试夹具验证，不注册第二份玩家任务。新任务激活前出发日结死亡另有后续Gate。

钱包与本次收据金额、唯一清算键、结果和关闭身份相符；每个真实实例与ItemState对应且仅一个归属。资源上限按真实定义，不照抄有限模型统一100。已交付／安装／消费／毁失保持原处分，任务件不能泄漏为永久普通物，未实际携出物不可在中枢访问。

## 3. 死亡提案不是存档阶段

真实G2 LocationPlan已包含动作revision、身体／实物／现场后果和签发来源，终局消费不能重跑行动或多加一次revision。G2休整也返回LocationPlan，不能丢掉地点资格另调一次G1。正常返回／期限才由受控组成私下调用G1一次，并将结果绑定完整独立前态；结构上像CyclePlan不等于有来源权限。

先对收到的原提案做完整结构、原数值、身份／前态、非自有字段及步骤校验，再复制和清退。允许受控内部存在尚未关闭的真实HP0，不改HP、phase、mission或revision来套生还校验；最终dead另验完整清算。步骤必须在索引前有合法非空序列／来源，错误不能靠普通异常、覆盖后归零或最终合法值洗白。

有限模型producer只改变HP、保留输入revision的约定不是真实G2契约。工程必须验证真实来源、实际前后态和各生产者职责，既不放过畸形提案，也不一律拒绝合法死亡。不得给G1当前不支持的CycleClosure凭空加death或构造假active使命骗过恢复。

## 4. 新技术格式及旧接口隔离

主线依获批稿第4节授予的技术定位范围，在本合同明确采用：

```text
format = elevator-survival.residence-headless
formatVersion = 2
terminalConfigurationId = infected-terminal-core-test-v0.1
```

`formatVersion=2`是同一headless格式家族中的独立新语法，必须有并列的新验证／编解码入口，不能让原v1接口同名悄悄接受终局或补字段。它不是有限模型标签`WE003-finite-model-v2`，也不是旧医院浏览器保存版本。这里只定技术定位，当前文档任务不创建生产注册表或实现。

不在这里发明第二个玩家rulesVersion字面量。沿用现有受控依赖的rulesVersion值并全链严格绑定；未来正式工程任务明确受支持的受控组成值及来源。格式版本和配置ID不能替代角色／具体委托／执行身份，也不能因版本变化解除关闭。没有真实新内容时不注册玩家规则版本或扩张版本通配表。

新v2接口明确拒绝v1和未知版本，不默认升级、不猜钱包、不补关闭记录、不自动新建。工程B仅新增并列接口，原v1验证／编解码和现有G4消费者保持原语义及测试。工程C在B实审通过后才显式采用新组成；旧headless开发夹具需要新格式时只允许明确新身份、无current的隔离重建，不冒充旧角色迁移。

旧医院浏览器入口／旧槽的保留、备份、清理和发布期限仍待后续决定；本合同不承诺永久维护两套产品，不允许在本次清档、静默迁移或改变用户保存数据。

## 5. 一次完整事务与故障语义

| 顺序 | 责任 | 拒绝／失败时行为 |
| --- | --- | --- |
| 1. 前置 | 严格意图、身份、revision、阶段、来源权限及launch全奖空间 | 未合法执行前错误：零provider／规则／随机、零提交／写入／通知 |
| 2. 正式结果 | 在私有输入上执行一次合法生产者，或消费受控已签发的一次结果；原提案覆盖前验证 | 提案校验错：如实记录已发生调用，current／disk／原提案不变，零提交／写入／通知 |
| 3. 完整终局 | 身体／现场／物品变化、任务关闭、钱包和被动收据一起构造 | 不部分应用；合法死亡保留，不为通过校验修值 |
| 4. 预编码 | 整个后态通过严格聚合及序列化，后续可恢复 | 编码／语义错误在安装前阻止；受支持合法结果不能因此卡死 |
| 5. 内存提交 | 唯一入口一次替换完整current | 不出现半closed／半钱包；每个用户操作只推进一次适用revision |
| 6. 持久化及展示 | 一次完整write尝试，一次只读通知分发 | 写失败保留最新内存，监听抛错隔离，不撤销结果 |
| 7. 重试与继续 | retrySave仅保存当前最新完整状态；后续命令读最新current | 不重激活、抽样、伤害、周期、交付、奖罚或玩法通知 |

bootstrap只在无current条件下做一次完整安装；真正读取null才允许显式首次创建。读失败、坏档、不兼容与无档分开，不回退空对象。无current的恢复故障重试须有明确生命周期与诊断，不能重新创建角色；已有current后不得第二bootstrap、replace或createFirst。

读取／工厂／provider／规则／写入／通知期间的写操作重入拒绝。查询与订阅取消不产生游戏结果。真实进程丢失只能恢复最后成功持久化的完整状态；不把单进程幂等包装成跨崩溃、跨设备或对用户离线回档的绝对恰好一次。

## 6. 工程与验收边界

[A契约](terminal-core-contract-v1.0.md)只生产纯完整计划，无安装和保存；B负责本合同四阶段严格编解码；C负责真正会话消费。次序及Gate见[批次计划](terminal-batch-plan-v1.0.md)。每批交付后准确SHA实审，不自动连跑。

B至少验证：四状态合法roundtrip，真实两声明历史夹具，遗漏声明、两活动、错身份／版本、缺账／错金额／重复键、实例双归属／资源越界／任务件泄漏、错误最新source和D/T、phase与HP矛盾、未关闭HP0提案、v1／未知版本均拒绝。候选解析、读取与序列化无安装／写入／清算副作用。原expected独立性与冷档非防回滚边界均有实际断言。

C至少验证：首次出发容量不足在provider前拒绝；四终局与动作／休整死亡一次完整提交，due／ready冷恢复不重结；保存失败后新内存继续／仅重试保存，重复和过期请求、重入、关闭降格、监听异常拒绝或隔离；无真实新任务时静态中枢不推进后果。

完整CTB、医疗、真实五图任务件／设施生产者、三专长／工具箱、安全提示与UI、浏览器／多标签、旧入口发布和Owner试玩仍有独立Gate。当前文档与有限验证不宣称这些支持。
