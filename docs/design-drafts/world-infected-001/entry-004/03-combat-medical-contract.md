# D02／D03：战斗、医疗与真实物品合同

DESIGN DRAFT / 待Owner采纳。已批G1能量和日级公式不变；数值均引用[候选参数](parameter-candidate.json)的ID，正式34+4仍在两份只读配置。这里提出真实行为和恢复边界，不是字段即授权。

## 战斗调度与身体时序

推荐：遭遇由G2到达/触发生产，进入前处理该动作的真实立即后果；若已HP0只交A死亡，不再开战。尚活且pending战斗时不能移动、日结、截止或回H0绕开。E0不新发起探索，但已触发战斗必须结。

战斗采用既有CTB先后及敌人意图模块。玩家每次合法战斗行动先主要效果（包括实际用药、装备扣耗、伤害/控制），再应有动作流血；死亡立即短路。敌人行动保留原伤口/暴露抽签顺序，不让退却取消已经到期的结果。药物必须真在快捷槽；绷带/镇痛走`bandage.ctb`/`painkiller.ctb`；背包药不能战中直接越过装填条件，急救包/食物/消毒/抑制/维护只在战外稳定点。

一次胜利或合法退却后才扣本场`max(combat.minimum, ceil(elapsedCTB/combat.ctb_step)*combat.energy_step)`，截零，无旧Scene Time超时债。退出扣E不是额外动作，不再次扣流血；死亡仍保留本场真实经过和消耗，不等E结算复活。战中不日结；恢复活战斗不补夜。代价是长战消耗后置、玩家须读预估/后果；替代逐招扣E需另审，不与本方案同时存在。

退却返回本次战斗入场前实际节点；代价按`retreat.*`及真实伤口/负重，镇痛只抑制指定惩罚，不治伤。保留敌HP、当前意图、已执行行动计数和风险游标、是否交战/击败；跨图与休整不回血、不刷新。再进入重建当前队列`reentry.player`/`reentry.enemy`，不重送首次迟缓，也不复用上场防御或逃跑进度。C4旁路不会凭空把C2置死。

`enemy.*`与旧医院敌人档案只说明参数出处，不宣称新L/C敌人已在生产注册。`pipe.*`、`wear.pipe.*`沿用物品角色，蓄力日额度仍读G1，不按退却恢复。

## 保存与唯一所有权候选

当前B仅稳定四态，C遇活pending拒绝。未来必须对真实可停留的active-combat提供严格有界schema：当前身体/装备唯一投影、当前队列/时钟、敌意图与持久敌人、风险随机游标、退却目的地及已耗额度。不是另一份旧医院runtime，不在本轮创建schema字段或版本号。

受控战斗生产者签发不可伪造的plan，校验基态绑定/revision与原始数值后才能覆盖；不能靠覆盖非法HP、补steps或清pending通过。G1仍拥有日结；战斗身体步骤按获批CTB语义验证。A当前`verifySteps`针对G2付费伤害/休整死亡，不能假定兼容先治疗再受伤的新步骤，须最小新增受控来源类别及独立验真，不能全面放松老分支。正常H0 steps=[]保持；真实死亡非空且消费原提案一次。

B验证联合来源和战斗投影；C唯一安装current，先全部验真并可编码，再提交，再保存。存储失败保留已提交结果，retrySave不重新用药、抽签、伤害或奖励；坏档blocked，不自动新角色。未来版本须另批：推荐显式新格式/受控兼容入口；旧v1/v2继续按原reader严格解释，不猜缺省活战斗，不静默迁移，也不承诺永久双产品。已终局历史只读，不能因新载入恢复原委托入口。

## 最小药食和维护

所有意图指定具体instanceId、使用位置、数量及合格目标；不是按名称找免费物。先校验HP>0、阶段、任务/角色绑定、唯一容器、ItemState、可消费单位、额度、目标及数值，再原子消费一次。战外稳定点药食`medical.free`，E0合法；不会额外触发付费动作流血。满值或无合格目标整笔拒绝，不消费储蓄溢出。以下在新驻留适用仍属Draft。

| 对象 | 合法目标／主要效果 | 额度/战斗及边界 |
|---|---|---|
| 口粮 | 饱食未满；`ration.satiety`封顶 | 不回血；战外；真扣`unit` |
| 绷带 | 受伤、流血或未处理开放伤口；`bandage.hp`并止血；有未处理伤口须明确选一处处理 | 战中限快捷；生存首次优惠见D04，不清其他伤口 |
| 急救包 | 受伤或合格轻伤，`firstaid.hp`；选一处伤口/挫伤处理 | 战外；不能凭空清全部轻伤；HP0不可用 |
| 消毒剂 | 实际pendingExposure>0；`disinfect.exposure`，不减既成感染 | 战外；G1日额，真实日结才刷新 |
| 抑制剂 | 已感染或有待暴露；设置已批suppression，不直接治愈 | 战外；G1日额；中枢静态不刷新 |
| 镇痛 | 未生效且有挫伤/未处理伤口；抑制指定时间/撤退惩罚 | 可快捷；不治疗、不抹伤口，周期清除 |
| 机械/织物/专业维护、充电 | 真装备资源未满；`maintenance.inputs`实际材料足额 | 付`maintenance.*`/`recharge`，E0拒绝；`restore.*`封顶、溢出失去 |

机械金属恢复池最多`restore.metal_pool`，显式分配给合格管/撬，总和不能每件各得一池；有限模型只验证单目标这个子集。工具箱必须金属和电子同时足额；电子被维修消耗后不能拿去安装。电池只充兼容设备，不从金属生成电。库存拆分快捷不自动补满，资源始终读取既有ItemState；耐久最后不足额可截零，电量必须足额支付。中枢商城/身体服务尚未接线，不由这份世界药食合同顺带批准。

## 有限来源分配证据（候选，不建通用事件系统）

每个已签发来源输出锚定commission/execution、地点、来源、ordinal、定义和原始数量；初始实物另有受控发放锚。剩余分配覆盖地面/背包/快捷/仓库，每一单位只在一处。消费/安装/交付/毁失形成不可用处分份额：`已签发数量 = 活单位 + 各已处分单位`。数量和ItemState联合验，未知来源、丢失输出、重复份额、错执行、资源超上限都拒绝。

拆分产生受控子身份及不重叠来源份额；合并只同定义/资源兼容，保留各份额而非另造物。任务件不堆叠，保留原指定身份，不能用新子ID冒充样本。证据仅覆盖本委托受控动作，不记录任意完整事件流或第二钱包；不能删除B现有整输出检查而没有替代联合约束。

证据见`split-merge-consume`、`missing-output`、`duplicated-unit`、`consumed-unit-not-usable`与原生`B-source-output-removal`。有限模型单位列表是隔离检查表达，不是推荐生产保存字段。原生结果确认旧B拒绝“输出消失”，尚未实现部分消费reader；这项unsupported不能计为实现通过。
