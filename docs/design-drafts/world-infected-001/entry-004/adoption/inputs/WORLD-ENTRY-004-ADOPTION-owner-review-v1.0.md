## 2. D01：真实任务生产与物品归属

拟采纳24节点、29双向连接的医院／酒店／供电／物流／通信候选图与已声明动作。地图数不是未来世界的硬上限。酒店不是通关必须访问地。

P1供电为当地设施作业，不产生跨世界通行能力。L2控制组件与C3启动模块真实提取，先验条件和放置再产生取得。H8安装真实消耗本执行两任务件和声明材料，形成一次设施完成事实；不能按名称扣除后又保留可用原物。指定样本必须来自本次H5真实来源，携回H0才满足相应成功资格。

任务件不是ordinary物品；需受控任务搬运，不能让普通pickup全面接受任意任务件。允许同次活动驻留内合法留置、回访再取；关闭后不能再进入旧现场取物。永久丢失不补发，但保留合法失败止损。

工具箱首次H1开门采用候选10E、工具耐久1，并产生电子1的独立一次来源，留地面待显式拾取。撬门／门禁卡有各自候选成本与前置；先用其他方式开门不能再补领专业电子。专业维修和H8安装竞争真实电子，不能双花。

酒店T1交易为一次真实绷带＋消毒剂换口粮，先验输入和结果空间，整笔消费与取得。H2随机消毒剂不是保底；无该物时交易不成立，可走其他真实食物来源。

玩家只能提交意图、方法、实例、目标与放置等受控输入，不能提交completed／reward／authority／任意后态。来源、身份、数量、空间与安全数字必须在副作用前检查；非法原值不能被最终合法后态覆盖洗白。

## 3. D02：CTB、退却和活战斗保存

拟采纳当前战斗调度方案及对应试用参数，不同时采用逐招扣探索精力的替代方案。

已触发战斗不能用E0、移动、休整、截止或H0返回跳过。入场前动作已造成HP0时，消费该真实死亡结果而不再开活战斗。玩家每次战斗动作先主要效果，再应有动作流血；敌方伤口／暴露保留真实顺序；HP0立即短路。

胜利或合法退却按上式结算一次探索精力，不另补动作流血。战中不推进任务日，不自动日结。退却回实际入场前节点，保留敌人HP、当前意图、已执行行动及风险游标；再次入场只按候选队列边界重新排队，不刷新敌人、身体、装备、日额度、来源或首次状态。

战斗药物限真实快捷槽的绷带／镇痛；急救包、食物、消毒、抑制及维护按候选只在战外稳定点。不能从背包隔空使用或自动补快捷槽。

拟采纳“后续必须支持真实可停留活战斗的严格恢复”责任，不声称当前v2已经支持。消费证据与活战斗需明确新技术格式／受控入口；旧headless v1/v2保持原reader含义，不静默填字段或迁移。具体新格式编号、字段和兼容接缝在相应正式契约确定，不能把本稿原则当任意改格式授权。

只读恢复不重放用药、伤害、随机或终局；C仍是唯一current持有者，完整验证与可编码先于提交。A仅新增与真实新来源相适配的窄验证，不放松旧G2死亡或正常H0空身体步骤。

## 4. D03：药食、维护及有限来源证据

拟采纳六类药食的候选目标资格与效果。常用首轮参数为：绷带基础恢复1HP；急救包恢复4HP；口粮补2饱食；消毒处理1次待暴露。HP、饱食上限和既有日额取已批准配置，不新增另一份body或日计数。

绷带有实际伤害、流血或未处理伤口时可以使用，有未处理伤口须显式选一处。满HP不自动意味着无目标；仍有流血／合格伤口时按相应条款处理。没有任何合格目标时整笔拒绝，不消费或储备溢出效果。急救包只处理所选合格目标，不凭空清空全部伤病。

消毒不减少既成感染；抑制剂不直接治愈；镇痛不抹伤口。HP0不能用药复活。稳定战外自救允许E0且不额外触发付费动作流血。固定一次用药省略数量或明确整数1，其他数量拒绝，不在本期创建批量治疗。

维护／充电须资源未满、材料足额、付费资格合法。机械维护的15点恢复池是总池，允许按契约显式分配，不能给每件目标各一池；完整多目标实现仍须后续测试。工具箱消耗金属＋电子，手电消耗兼容电池；不从金属制造电。耐久按获批方向允许最后不足额截零，电量必须足额。

拟采纳有限来源分配守恒：已签发单位＝当前各互斥容器活单位＋已处分单位。真实ItemState与实例对应，拆分子身份与合并来源份额受控；消费／安装／交付份额不再成为可用物。任务件不堆叠，不用新子ID替代指定样本。旧普通合法资产不因本期校验被强制改成本执行。

这是替代B“所有原始输出必须全件仍在”的最小有界扩展方向，不是删除校验，也不是搭建通用事件溯源系统。Python逐单位列表不是已批准生产保存结构；完整原生A/B/C接线、故障和恢复仍须工程实审。
