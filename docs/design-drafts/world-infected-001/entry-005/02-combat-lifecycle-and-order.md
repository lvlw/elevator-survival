# W1 — 真实CTB时序合同候选

依据[DEC-052](../../../05-design-decisions.md#dec-052)D04/D05、DEC-031/035/036既有CTB及终局顺序；新世界的精力／周期覆盖优先。这里确定技术编排，未新增玩法参数。

## 触发与入场

1. 稳定active-world验证当前执行、完整before、revision、合法可知边及正E移动资格；玩家只提交edgeId。锁定实际from、目标to、移动前敌人state，交真实P/G2完成移动及G1立即后果。
2. 先验原动作步骤、原始HP及来源，不能用合法后态覆盖非法before。移动后HP0只消费原移动死亡，不能开战、回血或等退出E结算。最后一次正E移动可在E0触发活敌；不能因E0忽略pending。
3. 活pending只在同一同步组合内存在。EntryWitness绑定原完整计划、from/to/edge、执行、enemyId、移动前encountered、移动后revision；不是命令字段。G2到达已经标encountered，首入判断必须用witness的前值。
4. 首入玩家0，敌人读取每敌first（70/150/60）；再入玩家0、敌人50。每场相对CTB重新从0计，battleId由执行＋入场revision＋敌实例稳定产生且不可复用。敌HP／意图／循环／count／risk全部承接，临时防御、延后和逃跑进度清除。本期数据首入均玩家先；敌先响应在行动后调度中真实发生。
5. 组合完成第一玩家决策点再提交。若后续合法profile使敌时点早于玩家，则必须同步drain到真实决策／死亡，不保存未结敌行动。当前批次不新增这类profile或重排现有first。

## 每个动作与同点排序

| 段 | 精确顺序／短路 |
|---|---|
| 玩家普通攻击／防御／快捷医疗 | 严格意图及可用资源→锁定主效果→真实消费／耐久／治疗／伤害／控制→应有动作流血一次→HP0则死亡→敌HP0则胜利→其余按动作CTB安排下一机会 |
| 同点 | 已开始动作完成（含逃跑完成）→玩家机会→敌机会。完成主效果不跳过流血／死亡；玩家、敌同归0是死亡，不是胜利 |
| 敌响应 | 只处理enemyNext严格早于playerNext/escapeComplete的行动；防具／临时防御及资源→直接伤害截零→HP0即停，不再抽伤势／暴露或推进意图；活者依次伤势risk、原本存在的暴露risk→状态→意图／循环／行动数→下一敌时点 |
| 伤势 | 挫伤通过既有minorContusions原语；撕裂／咬伤通过稳定伤口ID和bleeding。风险降为none仍按旧风险调用约定记录，原始无暴露不额外抽暴露；不能因为抽签失败把同一行动复抽 |
| 防御 | 先外套减伤，再剩余伤害50%向上取整；伤势风险再降1，不降暴露。只抵一次合格攻击，未用在下一玩家机会到期；稳定决策点defense=null |
| 退却准备 | 选择时锁定负重＋已有未处理伤口－镇痛修正，期间玩家不能另行动；严格早于完成点的敌行动照结。新伤不追溯延长本次准备；同点先完成，再一次动作流血／HP0检查，活者才退却 |

普通动作的主效果发生在当前玩家CTB，不为致胜一击虚等整个恢复时间。例：当前CTB100的主效果击败敌人且玩家活，elapsed为100；并非再加基础攻击100。退却结束点包含其实际准备时间。敌方直接致死的CTB就是该敌行动点；不再推进后继队列。

新三个敌人当前没有新增的逃跑中断技能；不凭空增加隐藏失败概率。挫伤不延长普通战斗CTB；当前逃跑只读现有负重／开放伤口／镇痛规则。各敌准确表及旧profile缺口见[05](05-approved-data-and-gaps.md)。

## 胜退费用与持续现场

elapsedCTB=`exitCtb - entryCtb(0)`，仅本场。胜利或合法退却在完整战斗计划尾部扣一次 `max(combat.minimum,ceil(elapsedCTB/combat.ctb_step)*combat.energy_step)`；当前6/100/4，99→6、100→6、101→8、201→12。E截零，E0也结算合法结果；无Scene Time/debt、逐招E、退出追加流血或日结。

ExitReceipt绑定battleId、entry/exit revision、执行、enemyId、结果、elapsed及E前后；同battle只有一次。fee不能成为可调用命令；重复旧计划、已有退出收据或旧revision均拒绝。死亡不走生还胜退扣费入口，但已发生的身体／实物／风险／时间写入真实death结果，不返还消费。

退却回witness.from（不能硬编码H1或H0），敌人持续值回写原site同一条目；胜利保持敌处节点、敌HP0并生成其真实解除危险事实。不能把旁路或撤退写成enemy-cleared。去别图、休整再入仍同执行同敌，下一场elapsed从新0开始，不重复前场CTB；首次迟缓不重送。HP0优先于退却点返回、危险解除收益、任务成功和奖励。

## 稳定点与中枢

稳定点才能休整、战外医疗／维护、物品整理、正常返回或截止；战斗中不日结，deadline不能抢过应结战斗。正常抵达H0且合法生还按旧A判断成功／失败，G1真实steps=[]，第七日正常返回也不追加过夜。异地第七日合法稳定截止先结身体后果，HP0死、尚活才失败召回；同周期衔接不重扣、不刷新第二次日额。

首绷标记跨战／战外／休整／读档，pipe_signature只由真正G1周期刷新。失败关闭不重接；生还无下份任务仍在静态中枢。active restore不重放动作、伤害、随机、费用、夜晚或奖励。上述入口的技术joint checks见[03](03-single-truth-and-effects.md)、[04](04-active-combat-save-contract.md)。
