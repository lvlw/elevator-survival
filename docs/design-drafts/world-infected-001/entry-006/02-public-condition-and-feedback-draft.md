# 当前身体提示与知识边界

状态：AUTHOR_DRAFT。当前已批准展示和新增待采纳映射严格分开；不修改参数。

## 盘点与可用提示

| 信息 | 当前正式来源／owner | 玩家界面可用边界及操作意义 |
| --- | --- | --- |
| HP/max | playerSupplyFacts → body.hp | 精确展示当前值；0 读取正式 dead，不自己创建死亡 |
| 流血 | body.bleeding | 明显状态、止血方向；不靠显示层计算下一行动 HP |
| 开放伤口、挫伤、镇痛 | body.wounds/minorContusions/painkillerActive | 共享顺序与 opaque 目标；说明治疗与镇痛不同，不展示 woundId |
| 精力 | body.energy、正式 cost/qualification | 当前余额、已知成本；E0 不免除已触发战斗，不能自动休整 |
| 饱食 | body.satiety | 当前数值、周期消耗机制；不计算本次未来日结结局 |
| 日额 | body.quotas | API 是“剩余”，不能错标“已用”；用药后最新值变化可反馈，不自行重置 |
| 已发生可观察暴露事件 | 当前 PlayerExecution 无专用安全事件 DTO | 已发生不等于当前已向玩家公开；不能从 raw pending 差分伪造暴露日志。未来确需事件须有正式安全投影 |
| 潜藏暴露 | 内部 condition.pendingInfectionExposures | 不显示数量、按钮差异或颜色；消毒 Preview 保持 unknown |
| 感染进展 | 内部 infectionProgress | 当前不显示精值、比例、排序或可用性推断；抑制 Preview 保持 unknown |
| 当前病程／未来周期 | G1 已批准内部规则；公开阶段缺口 | 当前只给 unknown＋机制解释；不把旧医院终末阈值变成新死亡开关 |

已有依据足够的短说明不需要新增 Owner 玩法决定：流血与 HP 独立；休整可能触发身体周期但不自动回血、止血、治伤、维修、充电或补给；暴露与既成感染不同；消毒处理合格待暴露，抑制不直接治愈感染；返回是否成功依据正式资格，不依据“还有几天”。

可用于现行 unknown 的文案：“感染情况尚无可公开分级；暴露可能在身体周期推动病情。消毒与抑制针对不同正式目标；当前预览无法确定是否有目标。”这是不新增知识的机制解释，不是宣称安全。

明确尝试医疗使用同一按钮／排序／unknown 提示；正式执行后可以观察真实消耗／日额变化或无目标拒绝。N08 证明执行结果可以不同；不承诺玩家通过任何行为都无法推知隐藏状态。拒绝不消费，保存失败不等于没有用药。

## D1：建议采纳的当前病程负担（新增公开映射，未批准）

主推荐是粗粒度当前负担，而不是精确 infectionProgress、潜藏暴露数或“今晚必死”。纯 core owner 从已批准[配置](../../../content/infected-residence-core-test-config-v0.1.json)的 `health.infection_damage` 选择当前所属区间，输出固定 label，不向 UI 交内部边界。当前配置起点为 0／60／90／120；这些数值已用于结算，**将其用于公开分档本身仍是新的知识选择**。

| 当前所属配置段（仅技术审阅） | 建议玩家标签 | 不得暗示 |
| --- | --- | --- |
| 第 1 段 | 未达病程损耗档 | 未感染、潜藏暴露为0、下周期安全 |
| 第 2 段 | 低病程负担 | 下周期只扣固定值 |
| 第 3 段 | 中病程负担 | 无法成功返回或必须用药 |
| 第 4 段 | 高病程负担 | 已经死亡、感染120即死 |

这不是未来周期预测：周期会先处理真实流血、增长／暴露／抑制，再按正式顺序检查，不以当前档保证之后仍是同档。生命是否归零仍由正式执行决定。不公开基础增长表或隐藏 exposure 总量。若批准，则同公开档不同隐藏进度仍应非干涉；跨公开档的变化才允许不同。

代价：公开大致进度区间，会改变现有全视图非干涉的等价类，需限定更新查询合同／安全 metadata 与配对测试。不能仅改 Tooltip 就宣布修复。备选是当前 unknown，或设计全新症状／检验系统；后者无已批准来源，明确 DEFER，不推荐新增该系统。

## 仍是工程而非新玩法选择的缺口

现有 Preview 只给资格与 cost，没有完整命令死亡三态、实际暴露事件、全部治疗／维护效果或当前敌人美术 key。不得借 23 个 supported 就声明完整 Ghost／动态死亡保护／结果 Feed 已具备。基础准备候选须盘点可由既有公开事实和正式纯 owner 得出的 metadata；不能在 React 写损耗公式、调用 resolver 或借 unknown 冒充非必死。需要新增隐知识的子项仍停审。
