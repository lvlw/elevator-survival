# 低资产首玩流程合同候选

状态：AUTHOR_DRAFT，不是 UI 实现或 UIR 新批准。依据 UIR-010—012／015 与现有安全查询。

## 状态—视图—操作

| 应用状态／完整停点 | 主要画面／安全数据 | 明确操作／刷新边界 |
| --- | --- | --- |
| unbootstrapped／锁申请中 | 正在准备，非死亡 | 应用 bootstrap 一次；无 gameplay 按钮 |
| 无 current 且真实无档 | Setup；setup 的三工具／三专长说明 | 玩家分别选择后确认创建；catalog 不发物；不自动出发 |
| first-hub | 锁定真实初配、背包／装备／快捷、出发说明 | 明确出发，仅一条 depart；不再改选或重发 |
| stable-active | 当前房间主舞台、公开身体／E、来源／地面／任务、Travel Cluster | 正式单边 move；搜索方案；真实拾放／拆合／快捷；药食／维修／充电／休整 |
| battle-decision | 当前公开意图、正式敌阶段、相对顺序、行动条、快捷位 | 仅 combat.actions；不用背包药物、整理或移动跳过战斗 |
| living-hub | 已提交 success／voluntary-failure／deadline-failure 摘要及保留身体资产 | 无真实后继则只读静态中枢；无自动出发／新日／免费治疗 |
| dead | 正式 death 摘要与 HP0，不可用资产不伪装仍可操作 | 无本委托继续／复活；不照搬医院 Failure New Run 按钮 |
| read-error／load-blocked | 未加载、保留原字节；不是空档 Setup | 允许受控 retryRead；不清槽、不发初配 |
| projection-unavailable | 已提交状态展示受阻，旧操作不可用 | 受控同步重建展示；不再执行命令／保存 |
| save-failed（ready 的反馈） | 最新内存＋醒目“操作已提交，未保存” | retrySave；不重执行动作，关闭／刷新有丢失未保存进度风险 |

四领域 phase 与五停点不混同。active-world 的稳定／战斗切换使用 `point`。生还三种终局摘要共享布局但不合并成“死亡”；成功取得样本、安装、携到 H0、交付是不同事实。

## 完整意图与分级确认

- L0：Hover／Focus／地图／物品信息／Preview，0 gameplay、0 IO；缺少未来安全 metadata 不画假 Ghost。
- L1：已有完整意图的单边移动、出发和普通战斗行动一次执行，不统一大弹窗。
- L2：方案、数量、格位、旋转、源／目标、材料和维修总池分配在对象旁明确选择。缺输入不默认首个实例、最大数量、材料替代或自动填槽。样本／任务提取、交易输出仍明确 placement；放不下显示正式拒绝，不整理背包。
- L3：主动失败返回、明确截止、任务关键物留置／破坏性系统操作采用居中保护，绑定原请求及重要安全事实。当前新 facade 未提供完整命令必死三态，不得拿旧医院分析器套新状态或宣称动态必死保护已完成；基础准备工程必须用正式安全 owner 补齐适用保证，信息不足仍 unknown，不在 UI 造公式。

普通已揭示整实例 pickup 可沿用 UIR-015 便利：玩家点击且已明确数量语义后，以未旋转、y再x 的候选锚点逐一调用安全 Preview，首个合法位置形成同一正式请求。无合法位置回手动旋转／放置；不自动旋转、拆合、换物或发送整理。当前新 P 是整实例拾取，不能借旧医院“优先堆叠”文案新增自动合并。task-transfer、任务生成、交易、安装材料不适用 first-fit 扩张。

背包／快捷图标缺图用占位，>1 真实堆叠才显示数量；右键及键盘等价菜单就地选择。装备只展示实际支持操作，不冒出新换装／交换命令。战中只读携带不等于可以整理。

## 可复用与不能直接复用

实际 `presentation-assets.ts` 有 Hub、急诊大厅、隔离走廊、护工五阶段、六物品、火门与样本目标图；`item-placeholder.svg` 可作缺图占位。旧 content adapter 绑定医院 ID，旧 Shell／TimeBudget／死亡分析器绑定旧 Scene／StableRun，不能直接塞入新状态。

保留可替换布局、图标／Tooltip／居中确认／Feed 的实现经验；不整包复用旧 registry、Store 或生产 bootstrap。新安全 DTO 没有当前敌人名称／美术键和全部对象视觉键：首轮可以用“当前遭遇＋公开阶段”的通用占位，不按节点／意图猜敌人、不把搬运工画成护工。未来合法的 content-side 安全视觉 metadata 可在受控侧绑定；不让 UI 索取真实 definitionId。五图未有图的房间用中性功能框，不补路线文字／医院 lore。音频新制作、最终美术和未来 Timeline Ghost 均不阻塞首轮，也不在本批启动。

## 结果与恢复

执行返回 ready 后先替换展示，再播放轻反馈／追加已提交公开差异。普通拒绝不记成功 Feed；保存错误独立。现有返回没有完整实际结果事件，不能从 raw commit／previous current 补洞；当前只消费可见 HP、物耗、任务等差异，补充事件须经基础工程安全投影。

刷新只恢复正式保存停点，Feed 新会话从“已恢复当前状态”开始，不重建旧动作历史。全部对象草稿在新 current／恢复／phase 变化后失效；重开用新选择，不静默换目标续交。细节见[更新合同](06-integration-ownership-and-error-flow.md)。
