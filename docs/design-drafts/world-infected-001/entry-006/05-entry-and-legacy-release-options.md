# 入口与旧槽发布选项

状态：AUTHOR_DRAFT；O3 OPEN。当前生产入口和 `elevator-survival:active-run` 仍是旧医院语义，未修改／清理。

## 近期推荐与公开发布分离

近期推荐 D2：DEV-only 显式新世界入口、独立命名空间和独立 composition。路径或 query 参数只是候选，不在本任务注册。原默认医院入口、旧 rulesRegistry、旧存档 reader 和医院 New Run 保持；新 v4 绝不交旧 reader 自动猜格式，旧槽不当新世界无档或新角色素材。

新入口首次运行不扫描、导入、删除或覆盖旧槽，也不自动把旧医院失败视为新角色创建许可。DEV 页面可告知“当前为独立封闭试玩，旧医院数据未改”，不能写“旧档已迁移”。这不是永久维护两套产品的批准。当前新委托结束后无后继，不能照搬旧医院 Failure 的 New Run 重开本角色同委托。

## O3 公开发布前的真实选项

| 选项 | 行为 | 成本／必须再决定 |
| --- | --- | --- |
| O3-A 推荐研究方向：新产品默认入口＋显式旧档处理流程 | 新命名空间；先解释版本差异，旧字节原样保留或由玩家明确导出／删除 | 导出、提示、删除保护、损坏档和回滚发布都需实际工程与验收；不承诺自动转换 |
| O3-B 有期限的旧版只读／独立旧入口 | 明确标注旧版，可查看或暂续旧流程；新世界另进 | 双版本维护、安全依赖及文案成本；必须明确期限／支持范围，不默认永久双入口 |
| O3-C 明确不兼容的切换 | 阻塞旧档并说明不能导入，旧槽仍保留，清理须明确确认 | Owner 数据损失感知与服务支持；不能静默删除或把旧角色数据伪装新数据 |
| 自动迁移 | 本轮不推荐／未授权 | 身份、日级 Scene／驻留、病程与任务实物不等值；需独立转换规则与反例，不能通用字段拷贝 |

推荐现在不决定 O3，先完成不碰旧数据的封闭首玩，取得信息清晰度／操作负担／分段突破反馈后再定公开默认入口和兼容承诺。原有旧代码存在 clear() 不代表新世界可以复用清槽按钮；外部备份／恢复也不是玩家任意回档许可。

## 发布前与回退 Gate

公开之前核验：旧槽有档／空档／坏档的路由；新旧命名空间隔离；升级／降级应用版本；新 checkpoint 不支持时阻塞而非覆盖；明确删除的字节范围与不可逆确认；旧版回退不会写坏新槽。回退发布包不应自动读新 v4 为旧 StableRun，更不能因此创建替代任务。

本轮以上浏览器行为全部 NOT RUN，没有发布 URL、操作 Owner 存档或注册第二委托。
