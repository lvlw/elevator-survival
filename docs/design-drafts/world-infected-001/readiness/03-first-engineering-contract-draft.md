## 2. 唯一当前首工程契约（获批稿B1—B10）

<a id="b1"></a>
### B1. Goal 与可交付能力

**Goal：具体委托身份与关闭资格纯核心。**

在不接入玩家入口、不改变旧医院生产行为的条件下，交付一个可独立验证的纯 TypeScript 边界。它能读取同一权威生命周期事实，判断首次资格、同一活动执行的继续资格、已终止不可重接及当前没有真实可接委托，并完成窄的首次激活、受控终止与严格值恢复。

这是一次完整工程 Goal：Codex 可在授权路径内自主完成详细设计、类型组织、实现、正反例测试、自查和修订，不拆成让 Owner 分别指挥查询、激活、终止和恢复的多个小任务。

“首次资格成立”仅表示通过本模块负责的身份与生命周期条件，不代表完整出发已经合法。身体、装载、任务前置、周期衔接及当前应用是否可出发，必须在后续正式协调边界另行验证。

<a id="b2"></a>
### B2. 输入与唯一事实所有权

| 输入／事实 | 唯一职责与本工程边界 |
| --- | --- |
| 经验证的角色引用 | 说明事实归属哪名角色，不复制身体、钱包或完整角色对象；不提供换 ID 继承旧角色的操作 |
| 只读版本化委托声明 | 明确世界、模板、具体委托和规则／契约版本的绑定；由受控内容依赖注入，不由 UI 的标题或任意字符串声明新任务 |
| 该角色该委托的唯一生命周期值 | 表达未接、活动、终止的互斥状态；活动与终止保留必要的同一次执行绑定；不能另存一份可修改 closed／claimed 全集或任务完成勾选作为第二真相 |
| 一次执行引用 | 复用已有 RunIdentity 的 runId、seed、rulesVersion 语义，不把它兼作角色或具体委托身份；不修改旧 RunIdentity 实现 |
| 明确操作意图 | 首次激活、继续查询或受控终止；不接受 UI 传来的任意后态、成功勾选或重置指令 |
| 恢复候选及期望绑定 | 待恢复值与受控边界提供的角色／委托／版本等期望上下文分开；不能全部从候选值自身派生后再声称通过独立绑定验证 |

核心拥有的是这一份生命周期事实的规则与转移，不拥有长期运行 Store、浏览器持久化或全角色所有委托的完整数据库。后续实际接线必须由唯一应用状态 owner 持有当前已提交值；本工程不为此提前创建完整 Profile 或应用 Store。

只读声明只需满足当前资格核心。不得顺带建立世界内容 SDK、通用任务供给框架或完整奖罚声明系统。额外不同委托只在隔离测试中显式声明，不进入生产内容注册表。

<a id="b3"></a>
### B3. 必须具备的行为

#### 只读查询

同一合法输入反复查询，得到语义一致的结果；查询不改状态、不抽随机、不生成身份、不取系统时间、不保存、不通知、不推进日期，也不建图、补货或刷新来源。

缺少必需生命周期事实、出现未声明委托或绑定不一致，不能默认为“首次可接”。非法输入应按项目错误约定明确拒绝；合法但当前无可接任务则返回空结果，二者不能混淆。

#### 首次激活

验证全部本模块前提后，仅从合法未接前态生成一个完整、不可变的活动后态，绑定传入的合法执行引用。活动或终止前态均不能再次激活为另一执行。

身份材料由受控调用边界提供；本核心不调用 Math.random、系统时间、UUID 或环境熵，也不创建医院 New Run。实际玩家接取与出发的 UI 分步、完整前置验证及身体衔接时点，不在本阶段决定。

#### 继续同一执行

仅为指向当前活动执行的请求给出继续资格。继续不是重新接取，不重新创建执行、来源或初始值，不恢复精力、身体、装备或其他资源。

#### 受控终止

只接受受控协调边界给出的、与当前活动执行严格绑定的明确终止结果，生成一个完整、不可变的终止后态。成功、主动失败、期限失败以及实际死亡导致的当前执行关闭须能够区分；这是接收结果，不是本模块自行判定它们成立。

本模块不校验样本是否携回、不计算设施成果、不裁定期限或死亡、不发奖、不扣罚、不转移实物。正式成功结果将来必须由完整终局协调器依据真实成果产生；UI 只能表达行动意图，不能提交 `completed=true`、任意成功结果或下一状态。

同一终止请求再次提交、换结果再次终止、未激活即终止及跨执行终止，均拒绝且不修改输入。不能用“幂等”名义重复应用终止效果。

<a id="b4"></a>
### B4. 严格恢复的范围

严格恢复只针对本工程的窄生命周期值，不是浏览器 Run Save codec，不等于已实现真实存档加载或防回滚。

恢复至少拒绝：缺少必需字段、未知字段（含嵌套身份字段）、错误类型、空或非法身份、未知版本、角色／世界／模板／具体委托／执行交叉绑定，以及未接却带活动执行、活动却带终止结果、终止却缺少必要执行或结果等不可能组合。

最终表示中若存在集合，须拒绝重复或冲突引用；本要求不意味着必须为单个委托创建全集或多余列表。不通过补默认值、丢弃未知字段、类型强制转换、重建空对象或自动改版本把非法数据修复成合法前态。

已有 `createRunIdentity` 使用普通 Zod 对象及字符串 trim。新窄边界必须先执行自己的严格输入检查再复用合法值；不能因为调用了已有工厂就宣称已满足新合同的严格恢复，也不为此修改旧医院工厂的既有行为。

规则版本变化不能自动重新开放同一具体委托。缺少另行批准的版本映射时明确拒绝，不默迁移或重新初始化。具体版本标识与结构格式在实际工程中按已批准边界确定，不在本稿注册新生产 rulesVersion。

<a id="b5"></a>
### B5. 信任、关闭事实与防旁路边界

#### 首工程必须守住

所有资格判断和转移使用受控调用边界提供的当前权威生命周期事实。首次初始化只属于该事实首次建立的受控路径；缺记录不等于从未接取，更不能在恢复失败时退回空值。

构造一个结构合法的“未接”候选、给对象做深冻结或成功解析 JSON，都不能授权它替换已经活动或关闭的事实。不得提供普通 reset、reopen、任意 replace 或 UI 可调用的 setCompleted 入口。

恢复是校验候选值，激活是从权威前态做合法转移，两者不是通用状态替换命令。公共 API、导出面和测试必须体现这项区分，而不是仅靠“UI 不会这样用”的注释。

#### 首工程不能伪称已经解决

一个纯函数只看到一份自洽候选值时，无法凭该值本身判断调用方是否丢弃过更早的关闭历史。TypeScript 品牌、Object.freeze 或状态字段形状也不证明输入来自最新的可信存档。

因此本工程交付的是窄规则保障及明确受控调用合同，不是全局防篡改、跨存档防回滚、身份认证或全角色聚合系统。不得用本段限制作为允许正式调用路径重建空事实的理由；正式接线时仍必须证明当前已提交事实不会被初始化或恢复旁路覆盖。

后续接线前必须明确并验证：谁持有唯一当前事实；谁有权首次建立／恢复并安装它；谁核对跨全部委托的活动唯一性及身份复用；谁产生合法终止结果；谁负责旧存档、损坏档与最新稳定边界。第一核心仅做局部校验，不能被报告成这些聚合门槛已经通过。

测试中的协调 harness 只能为验证上述接口约束提供显式受控调用，不得打包成生产调试入口、额外状态仓库或第二份关闭账。无需建立密码学签名、持久化权限令牌或通用安全框架来填充首工程范围。

<a id="b6"></a>
### B6. 体系规则响应、统一提交与只读通知

展示订阅和提交后通知只读，不能在多个异步监听器中分别扣血、发奖、扣款、修改关闭事实或保存。

这不禁止体系协作。相应规则体系可以在明确、有序、确定性的正式编排中响应日期、终局等规则事件，读取正式前态并提出效果／计划，由唯一协调入口组合验证，形成一个完整稳定后态后提交。响应发生在受控规则编排中，不是让已提交状态的订阅者回头补结算。

首工程只有纯转移，不需要事件总线，不实现日期编排、终局协调器、保存或通知。后续接线应保持一次完整规则结果、一次保存尝试及一次 Store 后态替换通知；保存失败保留已提交内存事实并独立报错，不能重跑玩法。

不能先单独提交“本委托已关闭”，再指望未来监听器补发奖励或补做身体、财物处理。首工程返回的窄后态只是未来完整事务的组成部分，不自带生产事务提交权。

<a id="b7"></a>
### B7. 复用与隔离

复用已有纯 TypeScript、deepFreeze／DeepReadonly、项目错误约定及纯 resolver 模式。复用 RunIdentity 作为执行引用，但不扩写其角色或任务含义。

保留旧普通命令禁止改变 runId／seed／rulesVersion 的连续性检查。不得以支持生还角色未来接续为由放松旧 executor；不得调用医院 Scene Launch、Daily Settlement 或 hospital-new-run-transaction 来完成新资格。

候选实现目录为 `src/core/mission-lifecycle/` 及其同目录测试／模块出口。它尚不是本轮写入白名单；正式工程任务另行锁定允许路径。不得为了候选路径便利修改全局架构校验、依赖、保存注册表或玩家入口。
