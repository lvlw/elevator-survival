## 0. 要交付的结果

把现有连续角色循环补成一版可实文件审查的具体设计：

**完成当前委托并生还 → 积分与合法实物实际结算 → 静态中枢中治疗、吃饭、购买基础补给、利用世界成果开放的医疗目录、维护和装包 → 明确确认下一任务 → 执行一次应发生的衔接状态检查 → 生还进入新任务。**

同时为失败生还给出一份比“按新旧来源没收全部未用新物”更轻、可解释、可核算的推荐。允许合理止损有收益，不要求所有失败收益清零；要明确是否仍鼓励反复低风险失败来完成主要整备。

五地图、主线、现有基本行动与宽松维护方向不重写。重点产物是收敛的主案、少量实质替代、实际联合账和剩余风险，不是更长文件或更多绿色计数。尚未批准的细节用Draft／OPTION／ASSUMPTION先推进，不因普通疑点停止整个Goal。

## 3. 工作包A：基础目录与医疗成果解锁

### A1. 给出一套小而完整的推荐目录

- 将**口粮、金属零件默认可购**作为本轮主推荐Draft；默认资格不等于默认赠送、零积分也能买、每日补货或自动装包。
- 比较布料和电池是否需同时首期开售，依据外套与手电的连续续航，不让基础配装必然依赖反复刷感染世界。工具箱／电子的供应缺口也要说明；不因此默认五种材料全部上架。
- 医疗目录推荐以**该角色正式完成当前整个感染世界委托**为解锁来源，不是到过医院地图、只取样或失败返航。比较“首期开绷带”与“同时开急救包”两种小范围，选一份主案；不沿用无必要的两次通关门槛。
- 采用现有物品及规格。急救包仍按正式1×2、重量2、不可堆叠读取，不能因检查器方便缩成1×1。用户说“急救箱”不授权新建另一种医疗物品。
- 身体服务的结构继续保留：合法生还后足额可用，不以成功解锁为前置；金额可检验，不随钱包和受损情况提高奖励以保证净赚。
- 本轮不加角色等级、经验、新货币、随机目录、卖回／回购、贷款、玩家交易或大型商城。

### A2. 填实每项商品的条件

说明商品标识与原物品对应、单价、单位数、资格依据、是否限购及理由、实际接收位置、空间／数量／余额校验、购买后可如何食用／使用／装包。给具体工作值和根据，不留下全部“待定”。

禁止用无依据的限购／高价把边界问题遮掉。若认为必须限购，单列玩法取舍，不默认藏入目录模块。世界内不能远程买；不自动吃、不自动装备／补快捷位。买到东西与发生使用效果是不同操作。

解锁只决定中枢购买，不禁止未通关时使用在世界中取得的合法绷带／急救包；也不让其他世界永远不能产生这些普通物。余额花光不清资格，资格本身不发物。角色死亡后的可用权限归属继续与角色家底方向一致，账号历史不充作继承钱包。

### A3. 三种准备方法要在同一张账里比较

比较中枢买入、当地搜索、酒店NPC换粮。使用相同准备目标、相同起点和实际药／食／金属，区分积分、探索步骤、路程、风险、负重和净带出，不能把它们随意折成一种虚拟币。

固定世界来源以196d4bf当前05为参照：可搜口粮6；酒店另有需真实交付的一次2。医院无固定口粮，不从更早工作稿免费恢复食品柜；新购食物也不算第二次世界来源。

中枢金属若适配配方，可用于本地装接，不加“必须本地图产金属”的便利门槛。由此减少必跑搜索是允许评估的成果，不要为了保住旧路线增加第五把钥匙。

零积分首次入场／首次失败时，默认目录没有解决实际购买力；必须给世界内已可达补给或明确风险，而不是“商店有卖所以无软锁”。治疗和进食的现金竞争必须进入账：能付身体服务但买不起口粮，不能被写成已经准备完毕。

## 4. 工作包B：静态中枢与下一次出发的一次衔接

### B1. 本轮主编排

正常合法生还返回不追加日级危险；正式所得先入账，玩家可在静态中枢治疗、进食、购买、维护和装包。**将原独立强制hub_rest步骤移到明确的下一次出发操作中；不能只改按钮名字却仍保留必先休整的隐藏门槛。**

查看、等待现实时间、关闭页面、报价、购买和整理不触发病程。世界内原位休整照常，不能借本调整删除世界内饱食／流血／感染后果。

出发前验证任务确可接、政策、执行身份、携带与相关必要条件；查询、取消、过期／非法请求不先扣状态。合法提交按整备后的最新事实处理一次应有衔接，活着才建立下一任务活动起点。致死是该已确认动作的正式结果，不回滚成“出发取消”，也不留下可玩的新任务。

### B2. 不偷加／漏掉第二个周期

明确区分：任务内日期、角色经历的状态检查周期、上次返回事实、下次任务起点。描述谁拥有何种事实即可，不预建生产类型、计数集合或复杂事件总线。精力、每日药效／用量及标志行动额度都要有唯一刷新边界，不能在衔接和新任务初始化各刷一次。

新角色第一次进入第一个任务与同角色再次出发分开，不把“下一次出发”扩成零经历者开场先损一天。声明有限证据如何处理这一差异。

**末日仍待审。** 正常早返、Day7在H0正常返、异地截止三种路径分别写完整时间序列。截止是否执行日级危险、是否召回、是否抵扣随后衔接不是本轮默认批准；选一份明确Draft主案并仅保留必要替代，标出每一次检查的周期来源。不能无条件双扣同周期，也不能把不同周期改名绕过。末日政策的不确定不阻塞已明确的正常返回＋出发方案。

### B3. 修正旧连续账的隐藏时序前提

v1.2十成功账采用“中枢先过夜，再从bank吃两份口粮，随后launch”。新流程中，日级衔接并入launch后，不得继续在已进入世界的位置消费中枢bank。

需要把食物明确安排为出发前吃，或实际带入后在合法位置使用；分别计入饱食上限浪费、真实单位、负重与背包空间。不得直接沿用旧期初饱食6和782余额而不重跑。出发后吃的食物必须来自实际随身，不是远程自动补足。

同样，不得把返航时感染作为出发结算输入：治疗清除了病因，就读取治疗后的状态。若仍饥饿，饱食后果照实处理；服务不包口粮。HP0不能治疗，HP1且高感染的合法成功必须有先领积分、先治疗的机会。

## 5. 工作包C：较轻失败政策与重复供给

Owner接受的是**继续比较较轻政策，暂不批准全部未用新物没收**。不是已批准零罚、固定30罚、入场费、无限委托、死亡或自动救援。

### C1. 一份主推荐与一个对照足够

形成一份不依赖新旧来源没收的较轻主候选：以普通合法携出与真实身体／装备延续为起点，给出公开积分代价等简明处理及其理由。具体罚额仍为Draft，可对比v1.2没收方案；不为比较建立几套并行世界全文。

列明有钱、刚好能付、差一点、0积分、已投入大量主线工作后的诚实止损，及故意短程退出。没有赚到成功奖只是机会损失，不能单独冒充实际处罚；0余额实际扣0要如实说明，不假称每次都罚满。不能为了强行确保人人受罚新增债、负分处死、自动卖物或隐藏提取税。

不倒扣已发生治疗、饱食和维修；物品已用不是仍在背包待回收。不采用来源罚时，可收窄仅为该罚增加的混堆消费规则，但必须保留真实物品身份／数量／ItemState、合法原有堆叠与守恒。不把“不要没收”误解为“可以重建装备”。

### C2. 两条失败路径必须在同一检查器可复现

- 20E药房：H0→H1→H2，暗搜12，取绷带，再H1→H0失败。
- 50E物流：H0→H1→H7→L0→L1，单程14；手工开柜14、搜索8，实际取绷带1＋口粮2，按实际目标使用；原路14返回失败。无战斗、无撬棍消耗，单程真实路线和知识应来自现有内容。

将评审者独立50E模型迁入仓库当前的共同有限行动检查，不继续只在孤立公式里算。指定10份不同任务身份、相同供给是假设，不是无限重开世界获准。新旧供给、前态和政策分别记清，不偷偷调整源库存或加怪使反例消失。

对正常成功、诚实受损止损、反复只拿物、先使用药食／维修再失败做同条件比较；至少覆盖无感染低HP、已感染、有／无旧积分，有条件再覆盖现有生存专长候选。保留比较目的，未覆盖不当通过。

**不要求“任何失败收益都为零”。** 区分：实际物资复制／重复发奖的错误，公开规则产生的合法止损收益，以及是否鼓励枯燥重复的产品风险。能靠多轮安全失败恢复，不证明在积分／解锁上优于成功；有成功正利润，也不证明玩家不会把失败当主要整备。

接取费／有限供给若仍有必要，只作明示替代，并展示0积分重试受阻的代价；不得默认采用来让主案全绿。若更轻政策仍有无法同时消除的取舍，交出推荐、量化风险和核心选择，不无止境扩机制或要求Owner填写所有细节。

## 6. 工作包D：联合账和扩展性验证

现有四条具名五图路线和关键反例继续有迹可查。不变世界内规则不强迫重写路线；购买替代导致实际路径变化时，新增具名变体而非静默更改基线。

至少交出以下几组有实际输入／动作／预期／输出的见证；可用表驱动而非大量相似文件：

| 组 | 要验证的实际结果 |
| --- | --- |
| 首次角色0积分 | 默认可购但买不起；初局来源和药物使用合法；不提前损一个未知日 |
| 首次完整成功 | 真实奖励、医疗解锁、买食物／适配维护料、治疗、装包、下一次衔接与起点；每项消费有实物和现金 |
| 世界成果解锁 | 仅进入医院／只取样／失败不等于完成；合法完整成功后同角色可兑换；未解锁不禁止使用拾取药；余额花完不丢资格 |
| 准备方式 | 当地取得 vs 中枢购买 vs 条件成立的NPC换粮；金属用于安装还是维修；布料／电池基础配装连续性 |
| 受损与贫穷 | HP1高感染有合法收入先治后发；钱差1／0、有旧药／无旧药、已治感染但饥饿；无安全续行解必须说清 |
| 出发合法性 | 预览取消、无效任务、非法携带、过期确认零变化；合法衔接致死没有新活动任务；重复提交不重复扣日／状态 |
| 末日关系 | H0正常返、异地截止，逐项标周期来源；未批准召回作为条件分支，不混作所有任务默认 |
| 同角色连续 | 成功→失败→成功至少三份实际接续；至少10份成功与重复失败对照，明确购买一次还是每轮购买、食物在何处消费、维护是否真的支付 |
| 历史去向 | 上次交付／回收／消费／安装／扣罚已终结事实不被以后死亡改写；仍拥有家底确实失去 |

| 小范围可扩展 | 商品增减、价格／休整目标或期限的局部扰动有来源；查询／实例状态不复制；无需第六地图或新生产世界 |

价格和症状阈值集中在版本化参数。先独立建立预期再运行，避免脚本把计算结果直接写回expect。完整路径、仅末端夹具、手工CTB轨迹和不支持操作各自分类，不声称全随机／全策略验证。

连续账比较同样的终点：已返回、已治、已采购、已维护、已衔接或已进入下一世界必须明确。不能一条停在发奖瞬间，另一条已经付完下一次成本。至少同时报告净积分、库存、装备缺损、HP／病程、饱食、日期及探索量，不把每件物按假定卖价换算现金。

原62／112／782保留旧参数和购买口径出处，不直接继承为新成绩。新商品只要还未开放，就不能提前计入路线的实际帮助。

## 7. 工作包E：修F-02与维护证据可靠性
