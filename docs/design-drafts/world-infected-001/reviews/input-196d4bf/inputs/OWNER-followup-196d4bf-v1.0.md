## 3. 已核对的当前文件事实

本轮通过GitHub连接器按上述完整SHA读取以下实际文件；不依赖报告猜测当前配置。

### 3.1 世界中已有食物来源，但属于完整世界草案

依据 `docs/design-drafts/world-infected-001/05-resource-economy.md` §3：

| 来源 | 当前Draft固定数量 | 必要区别 |
| --- | ---: | --- |
| 物流登记室前区物资柜 | 口粮2 | 开柜、搜索、显式拾取；不需先击败装卸场敌人 |
| 物流装卸场来源 | 口粮3 | 对应危险解除后搜索及拾取 |
| 通信检修间生活柜 | 口粮1 | 独立搜索与拾取 |
| 酒店林岑交付 | 口粮2 | 一次绷带1＋消毒剂1换取；独立支线库存，不计入固定可搜6份；不能假设必有消毒剂 |

固定可搜口粮为6，另有满足条件的一次交换2。总量不是自动收入、玩家已知全图、按日刷新或生产游戏已经接入的证明。当前这张来源表的医院区域没有固定口粮，不将较早工作稿中的医院食品柜重新补入当前事实。

### 3.2 当前中枢目录尚无口粮或材料

依据 `11-points-hub-recovery.md` §7：当前首期候选为身体服务和首次完整成功后可购的绷带；急救包为未来OPTION。口粮、金属、布料、电池等尚未成为该稿已开放商品。

因此需区分：世界内取得来源已写入Draft；中枢付费食物／材料供应尚待补齐。不能说整个世界设计完全没有食物，也不能说中枢现已能购买食物。

### 3.3 旧稿已保留治疗窗口，本轮修改的是衔接触发方式

依据 `11-points-hub-recovery.md` §6：v1.2本来就允许正常返回后先领收入、治疗、用药、进食和维护，再显式中枢休整，之后接下一任务。它并非正常返航立即追加致死结算。

Owner本轮进一步选择：不在中枢另设一次必须先完成的独立日结算操作，将相关衔接归到下一次进入任务世界的明确出发流程。不得以旧稿已有静态窗口为由忽视这一修改，也不得将旧稿误述为返航先杀死玩家才准治疗。

## 4. 主线推荐：基础目录与世界成果目录分开

以下为设计建议，未批准为正式商品和数值。

- 口粮：推荐默认可购的基础补给。购买得到真实物品，不直接补饱食、不自动吃、不自动放进快捷位；正式食用另行执行，是否带入世界由真实携带决定。
- 金属零件：推荐默认可购的通用机械维护材料，不以完成某个特定世界为资格。默认可购不意味着免费领、每次出发补满或0积分也能支付。
- 布料、电池：需与外套、手电等基础装备的连续续航一起检查是否首期开放。不能只照顾金属管而让其他基础配装永久依赖回刷感染世界；本轮不直接确认这两项同时上架。
- 医疗物资：以完成感染世界本次委托作为医疗兑换目录的候选解锁来源。绷带／急救包首批范围和顺序由下一稿比较，不预设“急救包一定第二次成功才开”。
- 完整身体服务：仍建议对合法返回且存活、足额支付的角色开放，不以首次成功为门槛；失败者有旧积分也应有被设计支持的治疗选择。

“世界解锁物资”指中枢兑换资格的来源，不等于该物品只在那一世界出现、不允许未解锁者使用、只有在指定世界才能带入或发挥作用。第一次成功前在世界里取得真实绷带，仍按物品本身资格使用，不因中枢商品未解锁而禁用。

不为此引入角色等级、经验、第二货币或大型商品注册框架。目录按真实成果判定资格；余额、资格与真实库存分别由其正式状态负责。

通用材料若符合任务配方，可以来自合法中枢购买或合法世界取得；不得为了保住某次必跑搜索，暗加“只有本地金属才能安装”。确有专属来源要求的任务物需单独在任务内容中声明。

## 5. 正常回归—中枢—下一次出发的候选编排

### 5.1 必须保住的玩家窗口

当前任务完成必要的行动后果并合法生还返回 → 正式终局与奖励／允许实物交接 → 静态中枢整备 → 玩家明确选择并确认下一次出发 → 处理一次应发生的衔接状态结算 → 生还才建立下一任务活动起点。

中枢的“静态”只指不因停留、现实时间、关闭页面、阅读、购买、治疗和整理推进日级危险；不等于不能通过明确治疗、用药、进食等操作修改相应状态。

出发结算使用治疗、进食与整备后的真实状态，不重放上次返航快照。未发生的未来疾病损耗不补扣到上一任务成功之前；已发生HP0不因返回、积分或治疗撤回。

### 5.2 下轮必须写清的边界，非本轮擅定新规则

1. 明确出发前先验证可接任务、身份、政策、携带方案和其他必要合法条件；查看、预览、取消、无效接取不能先扣状态。
2. 合法确认导致的衔接检查若使HP0，按一次正式死亡处理，不留“已进入下一任务但尚未结算”的活动状态；不能因死亡而偷偷取消该已确认后果。
3. 衔接检查成功才建立新任务的日期与允许精力；不先发精力再恢复旧医疗次数或叠发角色初始套装。
4. 同一衔接只能执行一次；重复确认、过期请求、保存失败、读档恢复不得重扣。生产保存语义必须仍区分已提交状态与持久化写入失败。
5. 世界内正常休整与其已确认的日级后果继续保留；本次调整只针对任务间中枢衔接，不是删除所有饱食／感染推进。
6. Day7截止流程是否已结算某一周期、下一次出发是否对应新的周期，需要明确对照方案；本轮没有批准“所有截止自动抵扣下次出发”或“截止和出发无条件双扣”。已处理同一周期不能重扣，另一个周期也不能靠改名免费跳过。
7. 新角色首次进入第一个世界与连续角色下一次出发需分别说明，不把“下一次出发一次结算”擅自扩成新角色尚未探索就先挨一天消耗。
8. 取消独立强制中枢休整按钮后，不保留隐藏同功能扣款／日推进步骤。临时日药效与每日限额怎样更新，要与这一个真实衔接绑定并记录。

### 5.3 需要覆盖的典型见证

- HP1、严重感染、合法成功：正常返回不追加未来伤害，合法奖励到账，足额治疗后清病因，再以新状态进入下一次出发检查。
- 同样状态但支付不足：中枢静止可查看和使用真实旧药；不按现实时间死亡，主动继续时真实后果需可预览。不得伪造免费治疗或用“可暂停”宣称已有可生还路线。
- 感染已治疗但饱食匮乏：身体服务不包食物，进入下一任务仍按真实食物状态处理；需要可实际获得／买到／用得起的准备路径。
- 取消出发、无效任务、过期确认：身体、积分、日期、物资不变化。
- 状态结算致死：唯一死亡，无可活动下一世界；已完成上一任务仍保留真实历史，不能改写已交付／已回收物为本次死亡遗失。
- 截止已结算的角色与普通早返角色：分别列出周期来源，证明未将同一危险阶段处理两次。

这些是待实现／待重算的预期，不声称本轮已经执行通过。

## 6. 失败政策的准确处置

Owner“按你说的来”对应上一轮评审建议：暂不批准新旧来源没收作为主政策，交Codex比较更轻方案。不能解读成已批准零罚、固定30罚、死亡、接取费或无限供给。

上一轮50E物流前区“药＋食物”无战斗补给转化反例继续纳入。积分能购买口粮或金属，不会自动消除零积分失败补给动机。需要用相同供给、身体起点、装备、可接取任务和结算口径比较成功、诚实止损与重复失败，不能用更高没收比例倒扣已发生治疗或维修。

即使不采用按新旧来源没收，仍保留真实ItemInstance／数量／ItemState与容器迁移；放弃一项处罚政策不等于放弃物品身份和守恒。

## 7. 下一轮限定设计工作，不扩大成全世界重写

- 新增基础可购补给候选，与感染世界医疗解锁目录分层；填写少量真实价格和默认资格，不照搬小说价格。
- 依据正常回归后的静态准备和明确下一次出发结算，修订当前日级接续与终局候选。末日政策保持待审，不用新流程倒逼批准召回。
- 将口粮／材料购买加入正常成功、受损失败、成功—失败—成功和有限重复任务账。原62／112／782仅为旧采购安排的条件结果，不宣称已经支付新增商品预算。
- 对照世界搜索、购买、NPC换粮及任务装接。允许玩家用积累减少搜粮／搜材料的重复劳动；也检查低价商品是否让所有相关探索毫无价值。不暗加必须搜索、特殊货币或购物次数门禁。
- 初局／首次失败零积分不能用“目录开放”冒充实际供给；检查普通医疗未解锁、无旧粮或缺维修材料的角色仍能理解可采取的路线。
- 追踪上一轮有限检查器死亡清理误改历史物去向的问题，随修订补测；本轮不改脚本，也不新增生产测试。
