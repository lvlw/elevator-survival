## 4. 主要发现

### R1 — 必修：一日一主要区域被错误重建为当前主方案

**定位：** `02-seven-day-structure.md`“一天怎样发生”、 “转移未抵达”；`03-location-design.md`“区域连通与每日承诺”；`10-decision-queue.md`“每天一个主要区域的承诺”；`04`四类路线明确“每个箭头进入下一游戏日”。

**实际内容：** 一天只能在一个主要区域进行实质操作；来源区只能通行与随身自救；已搜索/交付/工程后不能把另一地区作为同日探索；目标未抵达仍占日承诺。

**与输入的关系：** 新设计用单一精力共同覆盖地图内外移动与探索，并已经围绕“医院工作后同日去物流做准备”继续展开。附件v0.5 §18明确访问箭头不等于跨日。旧任务书反而强制保留DEC-003的旧门禁，使Codex为兼容它产生更多来源区/目标区/过境限制。

**根因责任：** 主线助手的委托书错误/冲突输入。Codex在02和10明确说明遵守任务书，不应被指控为暗改。

**修订要求：** 在新连续世界草案中，以单精力、实际路线/位置、已知信息和已声明危险作为同日跨图条件；撤掉从旧任务书重新引入的日区域承诺。原医院与仓库正式DEC不修改；拟覆盖关系单列。若设计者坚持限制有价值，可提出完整替代候选，但不能继续把它标为不可讨论的Owner硬要求。

**验收：** 能表达“在医院做一次合法调查→有精力且路线成立→同日抵达物流并做一次合法核验”；不能靠区域计数器拒绝。批量移动仍逐正式动作扣费，归零和立即危险边界不取消。

### R2 — 需要比较：五地图底稿被压缩为三地区，内容与体验损益未验证

**定位：** `01`“世界特殊性与范围”；`03`“五区域愿景的保留位置”；`10`“支线交付、报价和地图规模”。对照附件v0.5 §16—18。

**实际内容：** 酒店/供电所功能折入物流，医院从十一地点候选缩为九地点；三地成为主案，五图降为后续OPTION。

**判断：** 草案自主权允许提出这种整合，而且Codex留了记录，因此不是未经授权修改正式规则。问题在于它影响Owner刚要求的空间层次、人物地点、独立供电与休整路线；目前没有在新单精力条件下比较损益，不能仅以“首包只需三个”作为默认答案。

**修订要求：** 先撤R1门禁，然后以五地图工作底稿比较三地区整合。不要同时写两个完整大世界；用一份功能迁移和路线对照即可。说明少一张地图省去了哪些操作，也失去哪些真实选择；独立酒店/供电所新增的价值不能只是更多步数。医院地点数量不设机械指标。

**验收：** 具有可核查的推荐及玩家体验理由；不以旧的一日一区推导“五图必然需要五天”，也不以“地图越多越好”推导五图必做。

### R3 — 后续实施前需补齐：终局仍缺一套端到端候选

**定位：** `04`“成功、失败生还与死亡的终段”；`10`“最终回归、期限与失败生还”“角色家底、任务失败与死亡”。

**实际内容：** 正常回归点和零精力返航有具体草案，但异地期限失败后的角色去向、处罚、家底和下一任务交接继续交给未来契约处理。两种终局选项都留有相似空白。

**判断：** 明示未决是正确做法，不能因为没有批准就强行正式化。但新设计自治授权允许先形成有标记的候选与条件核算；“待后续设计”不宜成为整条结局的默认替代。

**修订要求：** 给出一套推荐的完整Draft，以及仅在关键分叉处的备选；覆盖完整成功、主动失败生还、到期异地未完成、实际死亡。每种说明人物位置、先决条件、物品去向、可用家底变化与下一活动阶段。核心新规则清楚标OPTION/ASSUMPTION/待Owner审定，不写新DEC，不写运行时类型或存档代码。

**不许更改的方向：** 死亡不能被完成任务覆盖；死亡失去角色家底；普通合法生还实物可延续；失败生还有真实代价；不免费治疗或复制物品；不生成Day8自由探索。不得只为把候选写完整而把活人直接改判死亡。

**验收：** 可以拿一名具体的角色和一份真实携带清单走到每种候选结尾；未批准条件在账本和摘要中显式可见。不能只写“返回系统会处理”。

### R4 — 必修的小一致性错误：三日账在C3匹配，事件要求C1匹配

**定位：** `06-event-pack.md`“现场匹配启动模块”：匹配在通信档案室，提取在机房且已匹配。`03`通信C1/C3。`08-balance-budget.md`§5三日路线Day2：进C3后“快核4、提模块10”。

**问题：** 总精力79可以加对，但列出的行动地点与事件前置不一致。不是已经证明整条路线合法。

**修订：** 将这次快核放到此前实际经过的C1，或明确提出允许C3核验的候选并统一全部规格。前一种预计不必改变同样动作的精力总和，但仍要重放完整操作顺序。不能只在算式中保留4而没有合法行动来源。

**验收：** 路线检查器应检查动作地点、前置、已知信息和是否重复，不只求和。把原错误路径作为预期拒绝样例保留。

### R5 — 可测试性欠账：可复算表格不等于可复跑验证材料

**定位：** `09`末尾“2026-10-02实际检查”：一次性PowerShell算术/几何检查，命令未保存。`08`说明未运行resolver/模拟/随机采样。

**判断：** 没有修改生产代码，未跑npm测试不是本任务缺陷。文档也诚实区分了纸面算例。需要补的是设计数字与验证输入的可追踪、可重跑方式，而不是拿2153个旧测试制造新玩法通过印象。

**修订：** 在授权设计子目录保存候选参数、具名路线输入、无新增依赖的轻量检查脚本和原始输出。它是设计证据，不是第二个生产规则引擎。明确脚本覆盖和未覆盖的规则；关键具体预期来自独立核对，不能只让脚本运行结果自己当标准答案。

**至少验证：** 精力最后行动、原位休整、相同位置下A/C比较、物品真实取得消费、一次性来源、背包占格/负重、生命/食物/暴露、行动前置与当前已知路线。比较正常、调查/早取样、受损止损、至少一种替代工具；补一条误用材料或低精力边界。完整风险树/所有专长不是本次必须穷举，但必须清楚哪些分支只是假设。

### R6 — 队列分类需要收紧：未落文不等于方向重新待选

**定位：** `01`长期家底处置；`10`十三项决策，尤其家底、每日区域、维护方案、身份与长世界来源。

**修订：** 分开记录：①已确认方向待落文；②授权内Draft默认；③有条件推演的未决机制；④真正需要Owner选择的产品取舍；⑤后续工程契约。不要让Owner再次选择“是否普通实物延续/死亡失去家底”，也不要把类型名/所有者拆分作为Owner产品决策。

把“恢复旧低耐久每日免费维修”“伪装Return生成Hub”“每天重刷柜子”等已与边界不符的做法列为排除方案及理由，不作为等待Owner选择的对等选项。核心队列每批摘要聚焦少量事项，详细队列保留，不因数量要求隐藏阻塞。
