## 2. 本轮Owner原话

> 当前《封锁区·未完成的转运》，采用“允许承担代价、失败生还返回”。
> 这里，既然提到了关于“主神空间消耗积分恢复状态”的例子，正好我们设计上缺了一环，是什么让玩家有动力完成一次世界任务，我们之前提到，积累，家底，但是这不够具体，如果只是单纯带回一些有用的物品，用于下一次进入其他世界的消耗，这看起来说得通，但是这有些属于强加给玩家的包袱了。玩家没有一个最根本的继续玩的动力。所以我建议，参考无限恐怖的设定，我们可以增加积分体系，每次完成世界任务，任务奖励正好是我们还未详细设计的，玩家可以带回允许范围内的数量限制的当前世界物资，但是更重要的是任务完成积分。积分可以在中枢用于恢复身体，也能兑换一些物资，这些物资由经历的世界，角色等级等因素逐步解锁（我们体系还没有角色等级，这个你看看是否需要提前增加）。有了积分这个体系，以后也会成为一种交易货币，我们当前阶段可以建立雏形，哪怕只是用于恢复全状态也是可行的。
> 如果你认同，我们可以让codex按照这个思路，在下一轮设计的时候，设计一版看看，可以参考《无限恐怖》，我们之前整理过这部小说的参考资料。

## 3. 主线推荐，不冒充Owner已定细则

1. 第一轮围绕“完成任务获得积分—实际生还结算—选择身体恢复—保留净积累／选择下一次准备”设计。积分不能只成为自动扣掉的治疗税；正常合理路线需展示可理解的余量或真实新机会，但不保证每次冒险都盈利。
2. 先不增加经验条与角色等级。比较依真实任务成果／明确里程碑解锁的极小目录；有资格兑换不等于自动得到实物。日后若需要等级，另作机制扩展，不预建空字段。
3. 可消费积分余额建议归同一角色历程，不归可继承的账号钱包；消费不倒退历史成果／已取得资格；历史累计、评分、等级与可花余额不是同一值。不必为此先建大型事件溯源系统。
4. 第一阶段可只交付积分与一项中枢身体恢复服务的候选。仍须用少量具体未来购买目标说明积累用途，并比较是否值得在首个可玩版本加一个最小兑换项；不默认全部上线。
5. 中枢治疗是明确付费操作，不是返回时自动发生。建议合法成功积分结算后即可用于同次中枢整备，不要求先付治疗费才能领本次成功所得。具体先后必须写成可测试规则。
6. “全状态恢复”必须有覆盖清单：HP、流血、伤势、感染与暴露分别说明；饱食、精力、镇痛／抑制、每日医疗次数与标志行动额度另列，不以一句reset-all默默刷新。装备耐久、电量、库存、任务进度和已消费实物不是身体恢复附赠。
7. 当前失败生还政策已定，但正常失败、到期异地、失去关键物等具体回归仍需完整Draft。旧“最多1粮＋1金属”及“保三槽召回”均未获批准；积分加入后要比较，不能未经说明叠罚。
8. 余额不足不是即时死亡判据。禁止现实等待/离线/阅读时间掉血；不给未批准免费治疗、贷款、自动卖物或复活。必要时设计标明OPTION的有限处理，并给出实际后继选择和致死检查点。
9. 允许世界内积累与有限带出。Owner本轮没有新增独立提取配额；先用实际装备／快捷／背包及既定物理约束核算，额外数量上限只能另列候选。
10. 任务失败不获得完整主线成功积分；是否有明确部分成果报酬、失败扣分、任务接取成本和供给限制，由本轮提出候选。不能用“少了成功奖励”假充Owner已要求的明确失败惩罚。

## 4. 不得复活的旧默认

- 一日一区、来源区只通行、每天回真正中枢、两根探索预算。
- 世界内睡觉回血、自然治好感染、换任务名清病、下一任务重赠初始套装。
- 感染120即宣告仍有HP的角色死亡、通用末日救援、通用失败必死。
- “全恢复”无条件刷新日次数、蓄力、装备、电池和库存。
- 用历史Profile永久成长措辞把该角色积分变成下一角色继承财产。
- 因设计脚本通过、Owner未挑细节或原型可运行，就宣称正式批准／体验通过。

## 5. 仍交给设计Agent具体化的事项

任务基础积分与有限附加成果；何时兑现、失败如何处理；完整身体服务及报价、低余额方案；积分归属与重复结算边界；感染产生HP后果的阶段/量/顺序；当前委托末日异地返回；可消费余额与解锁资格；最小购买目标；反复成功／失败的经济与可玩性。

在边界内拿不准时，选一套明示主Draft并记录替代；不要把每个数字都重新交给Owner。新的重大产品取舍留在精简队列，原型设计可以继续，生产实现与正式落文必须另获授权。
