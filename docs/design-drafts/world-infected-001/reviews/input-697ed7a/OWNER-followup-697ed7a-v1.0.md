## 2. Owner 原始反馈

### 2.1 本地主线

> 1. 恢复本地运转，本就是当前世界的主线任务。

### 2.2 五图与扩展

> 2. 暂且用五地图作为设计基线；虽然我想增加丰富度，但是，我们既然采用了既定主线+核心路线+独立体系的设计方式，那就代表着，后续如果想增加天数，增加地图数，在整体串联来说，也是相对可控，所以我并不会说一定要现阶段既要超过5地图。只是我说的这种可扩展性，要确保不能在某个设计过程中被严重降低了。

### 2.3 任务相关的返回要求

> 3. 关于异常召回。我理解，我们可以根据世界剧情类型，主线任务类型来设定，当前世界执行当前任务（保留后续进入同一世界不同任务的情况），玩家可能接到必须完成任务才能返回，未完成任务就必死的任务。

### 2.4 感染、生还与治疗参照

> 4. 感染终末，如果在设计层面上，可能有后续手段恢复，那我们就不用结束角色，我们可以设定，角色死亡的情况是什么，比如HP=0才叫做死亡，感染只是在扣血，如果还没结算到HP=0，那就该角色可以存活，比如感染到最后阶段，HP=1，如果再进行一天，则HP=0，但是此时玩家完成任务，顺利返回中枢，那就没问题。我记得《无限恐怖》中有个设定，即使角色面目全非，但是还有一口气，回到主神空间，则可以利用主神空间的手段，消耗积分来完全恢复，只是消耗积分不同而已，也可能出现没有足够积分消耗的情况导致回了主神空间也只能等死。

该小说例子作为Owner表达目标体验的参照，不是本轮完成原著核验，也不自动把小说的货币、价格和治疗例外移植为游戏规则。

## 3. 需要分开的四项判断

### 3.1 世界内容与本次任务

世界提供空间、设施、人物、资源与环境问题；本次任务指定目标、期限、完成条件、合法返回入口、主动止损资格和失败后果。

当前地点与主线可以共用既有构件，但不能从“世界ID相同”推出“每次任务回归与失败政策必定相同”。也不能从允许日后同世界不同委托推出旧场景实例必须永久保存或无限重置。

第一版只需完整实现将来获批的当前合同。不为此预建全部未来任务类型、巨大规则编辑器或运行时占位字段。

### 3.2 活着与有权离开

HP仍大于0，不等于已满足本任务的离开条件。

完成任务，也不等于人在任意地点都能立即返回。

正式生还返回需要同时满足：人物尚未实际死亡、本次任务的返回要求成立、必要位置与动作已经完成，且当前必须执行的真实后果没有导致死亡。

未来可能出现任务明示失败必死。这是任务政策的明确致死后果，不应推广为普通失败一律死亡。若采用统一HP死亡方向，任务致死也应通过同一正式健康／死亡结算产生一致结果，不在任务模块里单独清家底、留下可行动活人状态。此处理为主线建议，致死形式与触发点仍须针对任务确定。

### 3.3 重病与实际死亡

感染体系负责病程事实及声明的症状／生命损耗；健康体系负责实际HP与死亡判定。不能让感染体系独立终止角色历程或清空中枢家底。

新稿不得继续把“感染进展达到旧120阈值”默认当作独立角色死亡／本次Run立即终止。旧DEC-033明确存在感染120触发Run失败的版本规则，因此新的方向需要显式局部覆盖；不能声称只改了界面标签。

Owner的“末阶段HP1，再过一天会到0”是时点示例，不是冻结成危重感染每日固定扣1，也不是保证所有HP1者能走到H0。实际移动中的流血等已声明后果仍要结算。

允许的目标体验：当前尚活、任务与返程条件成立，赶在下一次致命病程结算前返回；不得为了执行“未来可能死亡”而额外补一次未发生过夜。已发生HP0则不能用返回、奖励或治疗撤销死亡。

感染是否仅危重阶段扣血、扣多少、是否仍有其他阶段效果，以及先增长后扣血还是依据原阶段扣血，下一设计稿应给具体推荐、理由、版本差异和测试。不得既保留旧感染硬失败，又叠上新的扣血造成重复致死。

### 3.4 返回与治好

返回时保存真实生命、病程、伤势和损耗，不免费翻新角色。

中枢可具备世界内没有的治疗能力，但必须作为独立的合法服务或操作存在。恢复HP与去除病因需分别说明；使用治疗能力不等于删除所有日级状态、装备磨损或任务历史。

本轮并未确认：用积分结算、统一货币、治疗价格、免费全恢复、债务、无条件部分治疗、治疗前自动暂停病程或余额不足立即死亡。

“钱不够只能等死”不能仅写成结尾文案。必须定义中枢中哪些游戏内操作或时间推进会使病程再次结算、支付不足有什么合法选择，且不能偷偷使用现实等待、阅读时间或离线时间杀死角色。

任务中断、成功结果与恢复付费要共同核算：合法成功所得是否可立即用于治疗；失败者能否使用旧家底治疗；既成感染不因任务名称切换而消失。已确认的失败生还与死亡失家底方向继续保留。

## 5. 扩展性应当怎样被实际检查

下面是主线建议的设计／工程验收方向，不是新地图或新期限的上线授权。

1. 地图数量改变不要求精力、休整、库存、通用健康规则知道每张地图的名字。
2. 任务期限是本次委托内容，不把七日写死进感染或精力算法；不同期限仍须重算供给和机会。
3. 同一世界可在独立候选夹具中替换任务目的与退出政策，不依靠改变世界ID伪装成新规则；不因此复用旧任务完成事实、重复领取来源或泄漏旧地图知识。
4. 任务失败、退出结果、人物存活与资产去向分别有明确事实及一次正式组合路径，不能各自订阅后分别终止和清库存。
5. 病程阈值与死亡边界分离。新增病因或治疗来源可经声明的输入输出协作，但不能直接修改HP或角色存活的第二份真相。
6. 第一版不必实现所有替代政策。通过最小内容替换／参数扰动见证说明哪些是配置，哪些仍需新增机制；不以接口名字稳定声称任何扩展都无需重新设计。

## 6. 下一轮应形成的具体候选与可检验例子

下一轮设计会话可以在授权范围内先给推荐并保留替代，不为普通疑点中断任务；涉及当前任务是否失败即死的核心选择不能自行正式化。

建议集中产出三块：本次任务回归契约；高阶段感染损血方案；最小中枢付费治疗与资金不足去向。继续使用五图，不另写整部新世界。

需要的有限测试或推演（本轮均未执行）：

| 情境 | 要核对的边界 |
| --- | --- |
| HP1、重度感染、已满足任务且实际到H0 | 正常返回不额外执行未发生夜晚；病程保留，不按旧120阈值自动杀死。 |
| 同一人物仍在任务深处 | 不能用HP>0或任务栏完成替代返回位置；实际移动、危险仍有效。 |
| HP1、下一次明确感染损耗致0 | 正式检查点死亡，后续召回／治愈不复活。 |
| 病程已到高阶段、当前HP仍大于0 | 可用操作由实际健康与任务资格决定，不独立删角色。 |
| 合法返回且支付足够 | 实际扣费、恢复目标与病因处理一致，不能免费多治或重复扣款。 |
| 合法返回但支付不足 | 拒绝／部分方案／延后各按明确候选处理，不产生半结算；具体下一步不能留成“未来系统处理”。 |
| 同世界两个示例任务，退出政策不同 | 读取本次任务规定；不保证都可召回，不把失败即死推广至全部任务。 |
| 当前任务失败可生还 | 继续真实角色和剩余家底，不重赠开局套装，不借任务切换消除疾病。 |
| 五图或期限试作变化 | 查询、路线与条件无硬编码地图数；预算重新计算，不自动扩当前实际可玩天数。 |
| 原20精力失败取药反例 | 连任务供给、退出代价、成功收益、中枢治疗共同比较；不把临时隐藏致死作为通用防刷补丁。 |

## 7. 本轮剩余的一项立即产品选择

当前《封锁区·未完成的转运》具体属于哪一种任务：

- 允许在规定条件下承担代价、失败生还回归；
- 必须完成主线才能返回，并明示失败会致死。

Owner提出两类任务应能按内容设计，并未明确当前任务采用后一类。主线目前建议首个完整感染任务保留有代价的失败生还，以便验证家底和治疗的连续作用；末日是否提供召回、召回保留范围与处罚继续单列候选。此推荐不是Owner确认。
