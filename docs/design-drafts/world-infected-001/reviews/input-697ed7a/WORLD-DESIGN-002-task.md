## 0. 要交付的玩家体验

把现有《封锁区·未完成的转运》从“完成一局、留下耗损物资”补成：

**进入任务 → 完成有价值的世界委托 → 真正生还返回 → 获得明确积分与合法携出物 → 选择付费恢复、保留积累或为后续能力/物资作准备 → 同一角色继续下一次任务。**

当前世界允许付出代价、失败生还；失败可能消耗旧家底，死亡终结该角色可用积累。积分主要来自真实履约，不应只是进图提款或治疗税。无须本轮建设完整商店、等级树或第二世界。

目标是交出 **Draft v1.2及可复查证据**，不是把所有新规则直接冻结。边界内不确定时可以选具体候选继续模拟，或保留少量方案；留下假设、影响和待审状态，不因普通疑点中断整个Goal。

## 3. 工作包A：积分体系与任务奖励

给出一个完整推荐Draft，可用少量替代解释核心取舍。

### 3.1 清楚区分事实

- 可消费积分余额、任务评级/历史成绩、兑换资格、角色等级/经验不是同一事实。
- 主推荐：积分归同一角色历程，是可用家底的一部分；死亡不能给下一角色继承。历史记录可以留，不能再次领取。正式架构将来可有摘要/凭据，但不要先建两份独立可改余额。
- 第一版以单一积分货币为主，不照搬支线等级代币、六项属性或双货币。积分账户不认识某床位、病种、地图；其他体系通过有来源、金额、原因、前提的请求协作。
- 余额必须有明确合法范围/数值类型。小数、负值、重复请求和不足支付怎样处理要写清；不得隐含负债或余额0即死亡。

### 3.2 收入与兑现

为本次委托填写可评审的基础成功积分，以及必要时的少量可选成果奖励；说明何时公示、何时实际记入、哪项资格不可重复。

正式生还与必要目标成立后，结算才兑现完整任务积分；不是看到箱子、装好设备或打开结果页就发。当前任务死亡、主动失败、期限失败、部分成果分别有明确结算；不偷把普通失败改为成功，不重复支付同一履约成果。

给出主推荐：生还结算所得能用于紧接着的中枢治疗，但治疗仍需玩家明确选择。不能“先付治疗费才能领取本次救命奖励”，也不能先用奖励复活已死角色。

奖励实例应绑定本次实际任务执行与结果，而不是仅按world名称或客户端按钮。相同世界的新委托不继承旧完成事实；加载结果页、保存重试或重放同一结算不再支付。第一版可以用既有唯一执行标识设计幂等边界，不预造不必要的运行时集合。

### 3.3 为什么值得完成

同时列出：任务总所得、身体治疗、装备/准备投入、失败代价、净积分、可用实物变化、首次可用的新准备选择。

合理的普通成功应有可理解积累/用途；高损耗成功可能净收益较小甚至用旧家底补，不保证所有路线固定盈利。不要按玩家余额/损伤偷偷提高奖励以保证净赚。

至少比较“只做积分＋治疗”的最小范围，与“治疗＋一个或极少量可兑换准备项”的小范围。后一方案是设计候选，不要求全部实现。第一种若只能表达修补成本，要明确动力验证仍未完成，而非宣传已经解决所有重玩意愿。

## 4. 工作包B：中枢身体恢复、费用与支付不足

设计一项第一期可用的身体恢复服务主案，必要时只提供一个不同收费/覆盖方式的对照。不要扩成诊所建设、复杂医学模拟。

### 4.1 覆盖清单与时序

必须逐项写：HP、流血、开放伤口/既有伤势、感染进展、未结算暴露；以及饱食、精力、镇痛/抑制、每日医疗次数、标志行动额度是否影响。

“完整身体恢复”可以明确覆盖本期身体损伤与疾病，但不是对全部状态执行reset-all。装备耐久/电量、物资数量、已消费药品、任务完成/奖励状态、当前局势不附赠重置。精力/日期若涉及本期仅休整恢复与下一任务额度，需独立说明，不把身体服务变成当日无限蓄力刷新入口。饱食及药效如何与全恢复协调给明确Draft，不能漏项。

区分返回交接与主动治疗：返回时真实健康保留；报价、扣积分、各健康效果和结果为同一次治疗操作。余额不足或过期状态拒绝不能半扣费半治疗，取消报价不生效；完整治疗后再次提交要拒绝或明确无消费no-op，不能重复收费/领奖。

可设计“按损伤分类报价”与“一种简单总价”的对照，选择一套推荐；不要抄原著价格，不按钱包余额报价。价格应能由少量真实状态解释，避免每滴HP引发无穷微优化。

### 4.2 支付不足必须具体

覆盖差1积分、0积分、有旧药物、无药但有其他家底、HP1/流血、重病尚活、已有本次成功奖励等情况。

余额不足不自动判死，也不先免费恢复再追债。写出可执行选择及下一次危险检查点。可以把有限稳定/部分处理列为OPTION以推进设计，但不能静默启用免费兜底、自动卖物、贷款、积分负数处死或充值救援。

不用现实时间、关闭页面、阅读/报价刷新导致病情恶化。中枢是否有离散时间推进、什么操作触发病程、缺钱者是否只能带病出发等，必须给具体可审候选及利弊。不得只写“交给未来治疗系统”。

### 4.3 世界内药品仍有职责

中枢治疗只在真正返回后可用，不远程替世界内急救。验证本世界药品能帮助活到出口、减少损伤或降低回归费用；不能为了积分服务，把绷带变成永远不值得使用的物资。自用药与服务治疗之间的价格关系也要测。

## 5. 工作包C：感染、死亡和本次任务退出契约

### 5.1 感染新版本

废止本新Draft中“感染>=120即独立终结仍有HP角色”。给出病程阶段到生命损耗的具体推荐：生效检查点、先增长还是先按原阶段判断、伤害量、抑制作用、正常返回和中枢治疗的关系。

不得同时保留旧硬终止再加HP伤害；也不得到旧阈值就强行HP归零来回避Owner要求。病情高但HP>0可以被救治，实际HP0不可救治；任务返回条件仍必须成立。新旧语义差异在DEC-028/033等拟覆盖表列明，旧医院不改。

所有既有跨日生命后果由所属体系参加同一次顺序明确的结算；不能“先发奖励/治好，再回头判断角色其实已死”。正常合法返回不追加下一晚损耗。

### 5.2 当前退出政策

本次委托已明确允许有代价失败生还，不能再提交“当前失败必死”与之平级。正常H0成功与主动止损继续按实际位置处理；到期异地、关键成果不可恢复丢失等补齐完整候选。

是否末日异常召回、保什么物资、是否执行末日疾病损耗等仍为待审政策。至少给出一套可算到中枢的推荐，不把它当所有世界统一规则；其它任务的失败必死只作为接口/职责对照，不新增完整任务内容。

积分纳入后重新设计明确失败代价。比较新罚与旧最多1粮+1金属，说明替代还是保留某项，禁止不解释地叠加积分罚、实物罚、失物与治疗税。少了成功奖励不等于全部已满足“失败要惩罚”。低余额尤其要说明真实后果。

### 5.3 跨任务接续

成功/失败后，谁活着、积分多少、哪些实物和疾病持续、当前任务日期和角色日级次数怎样衔接，写到下一次真实起点。

不得用新任务刷新精力而顺便刷新尚未到期药效/医疗次数，亦不能含糊保留旧日导致治疗有钱却永久无资格；选择一套有理由、可测试的生命周期Draft。不要让任务Day1冒充角色经历从未发生。

## 6. 工作包D：解锁与等级的阶段选择

主线推荐：暂不建角色等级/经验条。用既有真实成果或明确里程碑作为极小目录资格的候选，例如实际完成某委托或安全带回经确认研究成果；不要把单纯进入地图、当前钱包够多或一条UI日志当作永久许可。

必须区分“可购买”与“已购买/实际拥有”；积分花掉不应使已经获得的资格回退。两类事实仍有各自唯一来源，历史累计可派生时不多存一条可改经验真相。

给出少量具体目标：一个服务和一至两个可能的普通准备/横向用途，标明第一版最小实现与未来候选。可引用既有物品，不强制新增强力装备、技能或角色属性。解锁若依赖仅本轮未开发的新世界，不能声称本轮已经兑现收益。

评估是否真的需要等级；认为需要时提出机制Proposal和最小证据，不直接添加运行时等级。本轮不画大型树、不设计完整商城/随机商品/玩家市场；积分接口留可扩展职责不等于承诺后续全部兼容。

## 7. 工作包E：把经济和证据真正接起来

### 7.1 先修上一评审F1

- F1a：伤害变化令敌提前失能时，后续预写敌人/玩家动作不能继续执行。明确拒绝已失效轨迹并要求新轨迹，或另声明正式截止算法；保留独立预期，不静默改预期使旧轨迹通过。
- F1b：首次/再接战适用条件显式校验。已接战但HP/意图未变不能套首访慢起手。不得仅以HP相同判断首次。
- 不要求重建通用CTB调度器。有限验证就是有限验证；已覆盖之外必须标NOT RUN/不支持，不能映射成生产游戏禁止。

### 7.2 联合核算，不只加一张积分表

复用现有具名五图路线与真实收支，更新感染/结局改变的结果。至少包括正常完成、早样本/调查、受损止损、工具替代，以及以下组合：

| 检查主题 | 最少需要的见证 |
|---|---|
| 本次奖励能救治 | 初始0积分，合法生还成功后入账，再显式付费治疗；不能倒借尚未获得积分 |
| 回报有正向意义 | 正常成功治疗/准备后还剩什么；严重成功需要旧家底时说明代价；首次实际可用购买目标 |
| 失败与底蕴 | 成功→失败→再成功至少三次连续账；积分/健康/实物逐段继承，不重赠起点 |
| 余额与消费 | 差1、恰好、0、负/非法请求；重复治疗、重复奖励、取消与过期报价；无重复变化 |
| 病情与生死 | HP1高感染合法回归并能治；HP0不能治；同一病人在明确检查点扣到0；未来风险不提前结算 |
| 全状态边界 | 感染/暴露/伤势清理覆盖；装备和库存不变；每日次数/药效不被无意刷新 |
| 失败刷物 | 20E药房取绷带后失败，实计积分、罚、健康、物资与再次接取前提；零余额反复至少10次，不能用“单源一次”掩盖新任务循环 |
| 故意失败与成功对照 | 相同可用任务供给/角色起点，比较多次完成与多次撤出的真实收益；已禁止的世界重入不要作为默认，允许的重复任务也不能隐藏 |
| 确定性与身份 | 相同输入/参数两次复跑；相同任务结算不可重复、同世界不同任务不串任务成果；余额变更不通过展示订阅 |
| 解锁与当前余额 | 获得资格后花积分不丢资格；满足资格不发免费商品；购买拒绝不扣钱、不生半个物品 |
| 非万能扩展 | 同一世界两个任务政策的极小独立夹具、期限/地图增减的局部扰动；不新增真实第二世界或全策略遍历 |

连续账可以是明确任务供给的独立测试夹具，不能声称已经实现多世界。可用少量程序化序列重复，不必输出20万行每步全快照；保留可重建输入、摘要、变化记录和关键完整状态即可。

如果只有治疗无兑换，仍要用具体可核算的未来准备候选说明余量的购买能力；不要把未开放商品当成当前取得的战力。

如循环仍存在稳定故意失败套利，给出主推荐与替代（任务供给/领取条件/失败政策等）的真实代价和受影响范围；不得偷加当前任务失败必死、账户永久限制、自动补给或隐藏扣款。允许承认当前方案尚未闭合，但不能只写“未来考虑”。

### 7.3 证据纪律
