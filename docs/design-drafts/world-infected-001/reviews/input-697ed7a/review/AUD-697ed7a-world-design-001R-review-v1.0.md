## 3. 新发现F1：固定战斗轨迹的适用性检查不足

**等级：设计证据补修；不直接构成生产玩法漏洞。**

定位：

- `evidence/check_design.py::combat`，Git blob `1d85dd1dc8f812870ace3037752ad698193eac9f`。
- `evidence/parameters.json::traces.L_full`，Git blob `21bbef5086741df7f085a2c2aeaa6cf3b0ef8a6f`。
- 规则对照：07 §5区分从未交战与再接战；evidence README §验证合同5—6承认给定轨迹且参数导致轨迹不适用时需要另给轨迹。

### F1a：伤害改变后，敌人已提前失能，后续轨迹仍被执行

当前循环只检查事件时点非递减与玩家死亡；直到全部事件结束才比较`enemy_end`。由于攻击把敌生命截到0，提前击败与原最后一击击败都满足`enemy_end == 0`。

复现：使用原L_full（敌16，基础0、防御100、重砸150、基础180/280/380）。

| 输入 | 观察结果 | 问题 |
|---|---|---|
| 基础伤害4，原基线 | 接受；HP9、管26、E消耗16 | 与原轨迹相符，作为控制组。 |
| 仅将基础伤害改6 | 敌在CTB280已为0；仍执行380的基础攻击，管仍耗4、E仍16，未拒绝 | 原轨迹已不适用，却继续出具完整结果。 |
| 仅将基础伤害改16 | 敌在CTB0已为0；仍执行150的敌重砸，人物仍掉3HP，随后继续攻击 | “敌人已失能后攻击玩家”的错误输出。 |

这些参数修改仅是审查压力输入，不是建议改变金属管正式伤害，也不证明当前四条原参数路线数值全错。它证明检查器不能仅依最终敌HP来判断轨迹仍适用。

建议最小修补：发现敌人在非预定终点已经失能，拒绝原轨迹并报告需要新轨迹；或采用一个明示的结束算法并重新独立计算预期，但不得悄悄截短后把旧预期算通过。不要求建设通用CTB引擎。

### F1b：首次接战轨迹可错误用于已交战对象

当前只在轨迹含`requires_reentry`时检查`engaged`，没有对L_full等首次接战轨迹作反向限制。相同敌HP与意图并不能证明是首次接战。

复现：保持原参数，仅令L敌人`engaged=True`、HP16、下一意图smash，再使用L_full。函数接受，并继续使用敌150的首访时点。新稿07 §5要求已接战后的再接战使用0/50，未造成伤害就逃跑也算已接战。

这个前态可表达曾进入后立即脱离、敌未受伤的情况；本审查把它作为明确独立夹具，不宣称已经完整模拟了该逃跑前缀。

建议最小修补：为轨迹记录显式接战适用条件（首次/再接战/明确可共用），执行前校验。不以名称猜测，也不要求生产代码增加字段。补“已交战但HP/意图仍等于首访”的负例。

## 5. 产品审查：有价值的部分与风险

### 5.1 本地转运任务

建议继续采用“样本实际携回＋恢复当地转运”作为待Owner确认主案。设备线由当地实际需求连接供电、物流与通信，不再解释为普通金属制造跨界能力；无需追加护送AI或更多必战。

这不是既有医院主线自动升级，应明确批准新目的。样本仍是独立实物，不把NPC交付替换方案混入当前成功条件。

### 5.2 五图的空间价值

建议以五图作为下一版可玩设计基线，三图保留比较，而不是冻结最终节点数。五图为24节点、三图21节点；T和P各2节点，主要增量是人物/休整与供电的地理分工和西侧环路，不是新增很多内容或战斗。

比较过程公平保留了C0—H0普通通路、相同物资和敌人，承认三图原来也能先供电。这比“更多地图必然更好”有依据。

但主线代表路线不使用酒店交付，A/C例也不证明新增酒店是必要或最佳选择。不能把42→46这个差额当作已经证明好玩；试玩仍需观察酒店是否被合理利用、P是否只是多走路点两次按钮。

### 5.3 期限召回

主案允许最后一日结算后仍活且未感染终末者被召回，丢包和两个快捷位、保三个已装备槽，并执行有限罚。正常成功/主动失败仍要求到H0、不补夜。这已经是完整可选规则，而非写到“未来系统处理”。

该机制能保留失败生还角色，但改变撤离压力。空包且穿好装备者可能故意省掉返程。稿件已披露，不判为作者隐瞒；Owner需要明确接受还是改用更严格的保留范围，不能由审查者默认批准。它不能用于战斗中、提前异地或实际死亡后的救援。

### 5.4 当前失败罚不足以证明长期经济成立：20E药房反例

在终局稿当前用于验证接续的“下一次同规则感染任务”候选下，构造无流血、无日级危险即时结算、旧仓无口粮/金属的角色：

`H0→H1(2)→H2(2)→无照明药房搜索(12)→显式拾取固定绷带(0)→H1(2)→H0(2)→主动失败返航(0)`。

合计20E、无需战斗或过夜；不依赖随机附加。合法带回绷带1，失败只尝试扣口粮和金属，各自无库存则额外罚0。下一任务候选重新建立E100而不赠装备，仍足以再次产生这个问题。

本审查实际执行的是这段成本与库存罚则的独立算术，不是完整跨任务系统重放。是否永远能重复接到相同任务尚未正式确认，不能推导整个未来产品已经存在无限刷取；但当前候选若允许这样接续，单次正收益路径已经可具体指出。

此风险在原稿已留痕；本审查补一个更小的见证。不要求取消失败生还、普通物延续，或暗加必死惩罚。应连同任务供给、成功收益、真正失败成本及起点健康继续验证。“口粮1＋金属1”不应现在认定为长期罚则已解决。

### 5.5 感染终末不是可以埋进召回表的普通细节

旧世界硬失败与连续角色历程结束不同。稿件清楚标记“感染达到终末但实际HP可能仍大于0，也结束角色历程并失全部家底”为新OPTION，这是正确的留痕。

Owner若采用，应明确它在本感染世界中表示什么不可逆后果，并通过规则说明/阶段预警表达；不得伪造HP0，也不得推广成所有世界威胁失败都删除角色。审查建议单列决定，而不是把它随“同意召回组合”一起批准。
