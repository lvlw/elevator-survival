## P02. 唯一参数与真实初始状态

生产配置只从本次103键试用值及原38值组合，受控验证键全集、值类型和版本引用，不复制第二套默认。原候选、有限模型和fixtures不可作为运行时配置来源。H2必须使用choices／weights／unit，禁止额外grant.H2-random保底。

初次专长和工具选择锁定到本次驻留；侦察、工程、生存的战外效果实际接线，普通替代和不叠加保持。读档、休整不能刷新选择／首绷标记；战中首绷在E02复用同一事实，不另计一次。不建立未来委托改选接口。

## P03. 任务生产与搬运

受控内容动作覆盖：门／柜／旁路与调查知识、P1供电、L2核对／固定解除／控制组件、C1匹配及C3启动模块、H5真实样本、H8真实材料安装、T1一次交换和H1工具箱一次电子。动作前置和结果来源均读正式内容，不接受客户端completed或任意setFacts。

动作意图只指定方法、当前绑定／revision、实例／数量、合格目标和明确格位；实际返回的计划名称与模块分布可在工程范围内设计，但须有只读普通入口与窄受控签发边界。文档中旧planResidenceTaskAction等名称是候选，不要求为了凑名字改动旧精确导出测试。

任务提取先验资格、全部输入及放置；真实输出及资源与来源绑定，不能同名替换。留地面／拾回／搬运用任务专门协议，与G2 ordinary通道隔离。安装将本执行两件任务件和实际材料移为不可用处分并一次形成transfer；样本真正回H0才交给A完整成功消费者。错误执行、原份额、地面或已交样均不能成成功凭证。

门卡、工具箱和撬棍保持各自前置；先别法开门不得补电子。工程优惠和已获方法不能相加，普通手工及撬棍耐久替代保留，不由UI重算最优成本。样本两种方式按已批准风险及防护语义处理，不能把有限模型的谨慎外套正例当作禁用直接提取的依据。

## P04. 真实单位、拆合与维护

将本期受控初始／固定／随机／任务来源落实到有界份额证据；按来源分别验证已签发＝活单位＋已处分。真实容器与ItemState互斥、一致；普通历史来源不强制改为当前执行。任务件不堆叠、不用拆分子ID顶替指定实例。

显式拆分和合并保留不重叠份额、合格资源与合法空间；操作不能自动补快捷、合并不兼容资源、扩包或从远程地面付款。来源完整输出被部分消费后，有真实处分才可成立，不能直接删原B校验。任务来源无领取记录、错ordinal、错执行、复用已处分份额均在结果前拒绝。

每次药食按具体实例消费1单位，原始数量非法不得忽略；目标和日额先验。E0稳定自救合法，HP0不可用药。绷带处理一个明确合格伤口／止血，不清其他伤口；急救、消毒、抑制、镇痛和口粮各守已批资格与效果。真实使用修改同一身体和日额；不在医疗模块重复计算日结。

机械维护的15恢复总池须有真实多目标正反例，不能只验证单目标却宣称完整支持。专业维护、织物修复、充电按足额材料及合格目标处理；正E最后超额、耐久不足额截零、电量不足拒绝按既有职责，E0付费拒绝。满资源或不存在目标不消费，溢出恢复不变成额外资源。

## P05. 计划、死亡与旧核心接缝
