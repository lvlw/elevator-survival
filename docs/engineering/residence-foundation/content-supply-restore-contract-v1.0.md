# 来源消费与恢复接缝补充合同 v1.0

状态：依Owner已采纳WORLD-ENTRY-004-ADOPTION和[DEC-052](../../05-design-decisions.md#dec-052)由主线定稿的工程边界；未实现，不是生产开工或发布承诺。旧[A](terminal-core-contract-v1.0.md)、[B](terminal-restore-contract-v1.0.md)、[O2](runtime-restore-supplement-v1.0.md)在其原版本保持含义。

## R01. 支持对象和版本定位

来源锚、份额分配、真实任务动作、药食／维护、初始专长与工具选择是E01的新数据责任。E01仅稳定四态：首次中枢、活动世界稳定点、生还中枢、死亡。活着的pending combat仍须由后续E02完整协调；不得仅清pending令其可存。新来源的合法死亡必须能形成完整死亡值，不把HP0活动态硬塞旧reader。

本合同在获批新格式方向内，**将E01来源／稳定态技术格式定位为`elevator-survival.residence-headless / formatVersion=3`**。这是主线技术定稿，不是声称Owner单独指定了数字3，也不是本轮已经注册。旧v1/v2入口和原数据语义保持，v3不静默接受或迁移v1/v2；旧reader拒绝v3。E02的活战斗格式／允许保存点在其契约中另行明确，不悄悄给已定稳定态v3增加另一解释。

具体字段名与类型必须依据E01-P实际纯值，在E01-R开工任务中一次锁定；本文件固定所需语义与联合不变量，不冒称已经存在TypeScript模块或schema。若届时版本号已被别项占用，应报告具体提交和冲突，不覆盖。该开发格式安排不决定浏览器槽路由、旧医院入口保留期限、自动备份／清理或O3；不承诺永久维护所有开发格式。

## R02. 唯一事实所有权

| 事实 | 唯一所有者／职责 |
| --- | --- |
| 角色、具体委托、执行与关闭资格 | 原mission-lifecycle；身份、模板、声明、执行不可混用 |
| 身体、精力、日周期／日额 | G1唯一身体及既有周期，药食／战斗提案不得保存第二份可独立修改的身体 |
| 位置、来源领取、知识、设施／任务事实、持续敌人 | G2现场或其窄扩展，事实由明确内容生产者形成 |
| 实物、资源与来源份额 | 当前互斥容器拥有真实实例；ItemState拥有资源；来源分配记录只解释可用与已处分份额，不是第二库存 |
| 当前选择及已用专长效果 | 受控选择／执行记录；只保存必要原事实，不保存另一套派生效果或可随意刷新额度 |
| 钱包／终局及既往处分 | A及其新来源窄适配；不因扩展新增第二余额或再次结旧奖罚 |
| 聚合、字符串恢复 | B职责的显式后继；纯验证，不执行玩法、发奖或修复来源 |
| current与提交／保存 | C职责的单一后继owner；旧／新入口同域只能一名写入者 |

## R03. 来源锚与守恒

来源输出锚包含其声明、具体委托／执行、原来源及ordinal、定义和原始数量的确定绑定；初始发放单列受控锚。不同执行同名来源不能互换。实例迁移保留真实ID、数量和ItemState；拆分的子身份和合并的来源份额必须可验证而非按名称重造。

每个来源独立满足：已签发数量＝所有合法互斥容器活单位＋不可用处分单位。不能仅对全世界总数求和，不能用另一来源补足缺口。跨地面、背包、装备、快捷、仓库、安装／消费／交付／毁失联合查重；已处分份额不能再次参与修复、安装或成功判定。

任务件必须联查本执行、真实领取、声明原输出和当前原实例。样本不通过子ID、同名对象或错误ordinal顶替；任务件不普通堆叠。普通既有合法资产保留原来源，不被全局当前execution条件误拒绝。跨全部任意历史的认证仍不是局部冷自洽能保证的能力。

原B的整输出检查不能单纯删掉；v3有完整替代约束后才支持部分消费。旧v2整输出规则及反例保持原义。来源模型只需有界领域证据，不建通用事件溯源系统、通用补发框架或任务SDK。

## R04. 原始字段、提案和窄死亡消费

命令只含对应意图、绑定／版本／revision、真实实例／数量、合法目标／方法及明确格位。禁止用户传入authority、completed、支持开关、伤害或任意后态。按每种意图分别限制必需和可选键；在默认、封顶、复制、清退或覆盖前验证原始数值和选择器。

合法业务结果通过受控能力签发，绑定完整独立前态和规则／配置／内容版本。结构相同、克隆、JSON来回或旧revision不得冒充能力；恢复值也不自动取得动作提交权。检查过程不得修改或冻结调用方原对象。

新任务／维护付费行动产生的死亡、新供给／战斗身体步骤，分别由真实来源校验器验证，不能全部套用旧G2单调扣血步骤。A只通过明确的新来源受控入口消费原计划一次，既有G2死亡／正常返回分支不放松；验证不重跑动作、伤害、日结、随机或用药，不额外增加revision。

正常H0返回保留G1真实`steps=[]`；实际日结有应有顺序；死亡必须具有与原生产者、HP0及短路相符的非空真实步骤。免费且无身体变化的合法操作不应被强加假伤害或假步骤；它是否产生操作记录须与实际受控协议一致。

## R05. 严格编解码与独立expected

v3先验证格式、规则／三份参数引用、内容、角色和声明范围，再联合核对身体、任务、来源分配、实例／ItemState、专长选择及消耗、钱包／收据、终局历史与phase。坏值、未知版本、额外字段或不支持状态明确拒绝，不补缺省、重新发初始包或自动清档。

同进度恢复继续需要独立expected；不能从候选自身生成expected作自证。首次冷解码与已有current恢复安装必须分开：冷值自洽只形成候选，安装要由受控owner验证其启动阶段和权限；已关闭事实不能被新建空对象、重复bootstrap或任意replace降格。

冷恢复不重放抽取、用药、移动、周期、安装、任务关闭或奖罚。旧收据和处分保持原历史；后续死亡不把此前成功改成失败，也不重新没收已交物。完全伪造但内部自洽的离线历史、跨设备防回滚不是本接口保证。

## R06. 安装、保存故障与通知

完整计划验证→完整后态严格聚合→预编码→唯一current一次替换→一次保存尝试→一批只读通知。原始非法请求在生产者前拒绝；生产者已调用但结果不合法时如实记录调用，仍零current、零写入、零通知。不能用统一“零调用”掩盖实际执行阶段。

保存失败保留已提交的最新身体、来源、消耗、关闭与余额，明确报告save-failed。retrySave只编码并保存最新current，不回读旧档、不回滚、不补动作／随机／药物／奖励、不重复玩法通知。现实崩溃只能恢复最后真正保存成功的记录，不承诺跨进程绝对恰好一次。

写入口重入保护覆盖read、factory、执行材料、生产者、编码、write和通知。展示订阅只读且异常隔离；规则系统可在有序确定的编排中提出效果，由唯一入口组合，不使用异步监听器各自扣值、结奖和保存。新旧入口同技术domain共同占用，不建立第二current；这不是浏览器跨标签锁。

## R07. 活战斗后续责任

E02须明确active-combat真实可停留点、队列／CTB、敌意图／持续状态、风险随机游标、身体／装备唯一投影、退却原节点和已耗日额的完整关联。旧临时战斗runtime不能作为另一份可用状态并行保存。

恢复已开始战斗不免费退场、不补夜、不重抽、不刷新敌人／日额／首次效果。胜退只结一次本场E，已结记录与实际轨迹联合验证。新格式和与稳定态的交接需准确SHA独立实审；不因本合同采纳就声称现有B/C已支持活战斗。

## R08. 验收与停止门槛

E01-P先交纯生产者和守恒／死亡适配真实值；E01-R据其实际类型完成四态新codec及独立expected；E01-S再接唯一会话与保存故障。每项完整任务含正反例、跨模块链、自查修订和最终check，但分别提交停审，不把它们包装为一个巨大Goal自动贯穿。

E01-R必须测试已消费／已安装／已交样、错误来源、旧格式双向拒绝、两声明历史、非法数字和零规则重放；E01-S必须从真实read-null起步，独立计数用药、安装、任务及来源随机的失败后重试，验证一次current及关闭不可重接。正常空步骤、合法死亡和实际周期回归不能删。

技术文件与版本变更路径在各工程任务精确列明；本合同不授予生产目录白名单、不运行源码测试。浏览器IO、多标签、UI安全投影、O3和Owner体验仍有独立门槛。
