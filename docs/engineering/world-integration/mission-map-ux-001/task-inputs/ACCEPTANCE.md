## 二、原生画面只交四张，不能靠静态原型或注入地图验收

1. 任务详情：优先真实“样本已携带、供电/转运尚未完成”的代表状态，完整显示说明和当前线索。
2. 医院本地地图：原生探索出较完整的已知医院关系（含分支/回路），同屏读得清，左栏不被图例占满。
3. 酒店本地地图：入口、已知安置点和已知对外出口。医院房间不混入；注明已知出口目的地。
4. 世界地图：原生路线已知的建筑层关系；展示一次任务定位/层级返回。尚未发现的区域继续不出现。

使用本任务独立origin，保护Owner原存档。浏览器真实操作不得注入完成facts、测试checkpoint或修改规则；自动测试可用明确标注且由正式生产者形成的夹具。无需走每个素材状态、每种屏幕或重复拍几十张。截图是实际原图，记录CSS viewport、固有尺寸、SHA256和来源SHA；可直接上传四图或仅视觉ZIP，不包重复源码。

## 三、针对性负控

- 故意让隐藏节点/跨建筑房间漏进本地/世界图，确认具体业务断言失败。
- 故意把“样本carried”改为可交付/完成或令地图定位调用移动，确认状态/零dispatch断言失败。

变异只在测试隔离副本，逐字节还原，最终check在还原后运行。负控、定向集与全量不累计包装为新增数量。

## 四、不能接受的交付

- 任务内容仍只有两个标题＋“尚未观察”，详情只是放大版。
- 新图仍靠双滚动、持续缩字、删路线或用“展开看”掩盖小图不可读。
- 两层只是Tab名，实际仍绘制全世界所有房间。
- 地图自动知道未知房间/材料/怪物，或“世界地图点击”成了传送。
- 静态稿漂亮，原DEV游戏仍用旧组件；或测试绿但原图仍是本轮反例。

Owner当前不需要重复摸索旧版本。全部完成后先由主线审代码和这四张代表画面。
