# 内容与公开信息合同

## 1. 始终能读到的委托正文（本轮定稿文案）

**封锁区 · 未完成的转运**

当地急救转运已经停摆。你需要让转运设施重新运作，并取得指定的密封病原样本，亲自带回医院电梯前室交付。

**恢复当地急救转运**
先恢复相关供电，再完成医院转运设备的装接。恢复供电只是其中一步，不等于转运已经恢复。现场记录与设备信息可以帮助你查明所需工作。

**携回指定样本**
找到并取得任务指定的密封病原样本，保留原物，最后携带它回到医院电梯前室。拿到样本不等于委托完成；样本留在现场也不算交付。

**完成与返回**
当地供电、转运恢复均已完成，指定样本正在携带，且合法回到医院电梯前室后，使用原“交付返回”操作。其他情况下主动结束会按失败止损，不存在离开整备后再续做本委托。

期限、成功奖励及失败规则直接复用现有正式配置/公开brief和已批准文案，不硬写第二份数值。死亡、截止、保存失败的原提示优先。

这是把已有目标说清，不是新增要求；不得要求酒店交易、访问所有建筑、集齐日记、读完剧情或击败所有敌人。

## 2. 线索披露与取舍

### 明确区分三种信息

- **委托要求**：上述结果与返回点可常显，无需先阅读日记。
- **已知空间/事实**：仅map公开节点/route、tasks状态、narrative已有事实和当前合法动作；可定位。
- **待调查方向**：可以基于公开房间用途说“查看后勤区域记录”“调查已知供电设备”，措辞保持调查性质，不能宣称已知道隐藏答案。

禁止从完整catalog定位未发现的样本、部件、材料来源；禁止剧情书签解锁指引；禁止按是否隐藏感染或未来敌情改变建议。不要把“可能”当作泄漏隐藏精确位置的免责词。

### 具体方向选择（显示规则，不是玩家路线限制）

1. 已有合法原生终局结果：呈现已结局事实，不建议继续旧委托。
2. 已处于战斗：保留任务说明/已知地图，短句提醒先处理当前遭遇；不显示可立即移动的假按钮，不提供最佳战术或保证安全。
3. 已在合法返回点且原terminal.eligibility.deliver为真：提示可以交付；仍由玩家点原入口并经过原保护。
4. 任务未完成：优先列当前地点可见的相关调查/处理，再列已知地点中尚待推进的目标；提供多条可选线索，不锁唯一顺序。
5. 没有精确目标知识：显示真实已知区域或下一处可调查的入口，不画虚构目标房间，也不只返回“未知/请探索”。

当前精力/风险可能限制行动；路线的“上次观察可通行”不能包装成即时执行许可。可看地图不意味着现在能走。

## 3. 示例状态矩阵（禁止把示例写成固定玩家状态）

| 公开输入 | 任务应如何表达 | 不能做 |
|---|---|---|
| 首次进入，无调查 | 目的与两个最终要求；先查看医院大厅/已知后勤区域的现场信息 | 首屏公开所有房间、敌人和组件源 |
| 已知医院后勤控制间，工单未调查 | “可调查：医院·后勤控制间。查看现场记录，查明转运停摆的原因。”定位只在该节点已知时开放；在当地对应“调查停用工单” | 自动展示周衡署名/正文；到达即算调查 |
| 工单已查 | 可摘要已有停用/隔离信息；显示仍未完成的供电与装接；列已知相关区域 | 把工单扩写成未获信息的全套材料攻略 |
| 已知供电所区域但未发现柜房 | “可调查：供电所。查找相关供电设备。”定位区域 | 提前画出转运支路柜 |
| 已知转运支路柜，尚未调查 | 具体位置可定位；当前现场“调查供电”与提示一致 | 宣称已经查清恢复办法或具备资格 |
| 已调查供电，未恢复 | “供电已核查，仍待恢复”；若当前正式动作可见，写清同名行动 | 把“已观察”当成“已恢复” |
| 供电已恢复，转运未完成 | “供电已恢复，转运设备仍待装接”；定位已知医院转运平台；在可访问的正式说明中查看装接需求 | 称主线已完成；猜材料足够 |
| 已有公开的装接/提取行动说明 | 沿用该说明的物品名称和需求；能引用的数量只从正式安全元数据读取 | 用背包名字自算任务件身份/完成与支付资格 |
| 样本已携带，其他未完成 | “样本已取得，待完成转运后携回交付”；不再指引重复提取；优先剩余相关线索 | “样本已交付”或重复拿样本 |
| 样本留置 | “样本留在现场，返回前需取回”；只有已有公开位置才定位 | 猜样本地面位置，重新生成样本 |
| 转运完成，样本未取得 | 保留已完成成果；样本具体位置仅按既有公开地图/现场信息给出 | 强迫重访供电、物流或酒店 |
| 三项都满足，人在酒店等远处 | “可准备返航：携样本回医院电梯前室”；定位已知返回点 | 隔空交付、自动结束 |
| 无有效地点/旧视图失效 | 清除失效目标选择；保留可说明的委托事实/终局事实 | 将旧动作绑定到新地点或新owner |

对Owner截图这类状态，至少必须明确：样本在身上但委托未完成；还需恢复供电并完成转运。具体“下一步”从实际已知地图选择，而非把截图当完整存档。

## 4. 本批技术实现约束

默认不修改PlayerReadyView协议和core。现有tasks完成状态、sample分类、narrative.workorder/powerSurvey、map及可见动作已足以完成基础说明、剩余目标、知情线索和定位。Guide是可丢弃派生展示，不写入存档。

不要求本批另做跨所有任务的组件/材料实时清单。若缺乏足够公开输入，准确显示“需到设备现场核对”，而不是编造0/1计数或修改核心来凑丰富度。该克制不能作为不交任务正文或不显示已知可调查地点的理由。

静态copy可以设在专用展示内容模块；不导入整个玩法catalog到React。动作名仍由现有content labels提供：补workorder的明确映射；必要的既有相关名称可以窄改，不能增加新的行动。
