# UX合同｜先把目的和空间讲清楚

## A. 本轮体验验收标准

玩家不看设计文档，打开任务应能回答“要做成什么、现在还缺哪类事情”；看地图应能回答“我在什么建筑的哪个房间、这里有哪些已知相邻方向、通过哪里能去别的建筑”。不要求玩家学会图论、不要求全图滚动找自己、不默认给完整攻略。

此前要求“小图也展示所有建筑全部已知房间/所有原始有向线”的呈现方式，本轮被两层展示局部覆盖。知识、方向、回访、单向和旧观察的语义不变；不是把合法路线删成一棵树。

## B. 任务：摘要与详情各司其职

### B1 左栏跟踪

显示《未完成的转运》、紧凑的当前成果摘要和最多一条选中线索。例：
- 转运恢复：供电未恢复／装接未完成（真实状态，不把两者混成同一完成条件）。
- 指定样本：已携带，待交付。
- 当前线索：供电所的供电设备（目标精度取决于真实已知地图）。

可显示来自正式配置的任务第N/M日，不显示现实倒计时，不用“剩余M-N天”误表达第七日边界。摘要默认不展开全部教程、技术图例和历史记录；任务详情按钮常驻。

### B2 详情

不是旧摘要放大。固定层次：委托目的 → 两项最终要求及供电前置 → 当前真实成果 → 可追查的已知线索 → 返回点、期限与结束说明。必要文本常显，不能靠点叹号才能读。

每条线索写“地点＋可做的调查/处理＋为什么相关”；只有公开依据足够时给具体节点。对新发现但未访问的地点写“可调查”，不谎称已查明任务答案。用户可以自由选择追踪不同线索，切换追踪只保留在UI会话内。

完成状态来自正式tasks/terminal，不从背包名字、日志、书签、截图或路径推断。仅到达一个地点不等于调查完成；样本持有不等于交付，旁路不等于击败敌人。

### B3 地图关联

“在地图查看”打开对应地图层与目标高亮。全名歧义、端点缺失或目标不可知时保留文本，不定位任意第一个对象。查看详情与定位不会调用执行/保存/熵。

## C. 地图：两层不是两张独立数据表

### C1 本地地图（默认）

- 标题为“医院内部”“酒店内部”等当前公开区域名；当前房间另有清晰标记。
- 仅画该区域的已知房间和区域内已知通路。
- 本地主图不塞别的建筑里的房间。跨区关系用接在真实源房间旁的出口短标签表达，例如“去往医院”，选择后可看公开目的端“医院 / 电梯前室”。这只是说明，不是移动按钮。
- 入口已发现但未去过的房间可用低对比边框；当前位置用明显轮廓加“当前”文字/形状，不能只靠色彩。
- 完全未知的房间/连接不画；不留带问号的空位、不显示未来房间数，不画未解锁捷径轮廓。
- 所有当前建筑内已知节点在同一主图可见；不能默认只截当前节点和两个半节点。

### C2 世界地图

- 单节点代表一个已知建筑/区域，不再包含其房间。医院、酒店、供电所、物流、通信也只在实际公开地图出现后显示；不得首屏自动画齐五图。
- 只从真实公开跨区route推导区域联系，区域内route不变成自环。
- 区域节点注明当前区域或已发现入口。点击区域的含义是“查看内部”，不是“移动”。
- 选择一条跨区联系，可以查看真实起止入口及各自观察状态。多出口可以在世界图合并为一条区域关系，但详情必须保留每个公开出口，不能用其中一个可通行出口证明全部出口实时可通。
- 世界视图不证明区域内能从入口A走到出口B。节点合并不能制造跨区捷径或自动寻路。

### C3 切层

本地标题栏提供“世界”；世界图点某建筑可查看它的已知内部；“回当前位置”永远只恢复当前区域/房间展示。真正跨区移动提交后，默认切换为实际到达建筑的本地图。医院内移动不重新随机排版。

查看其他区域时标明“正在查看：X”，当前位置另保留，不把查看位置当玩家位置。进入中枢/终局后不留下声称仍可行动的旧世界指引。

### C4 路线和布局

- 使用清楚的房间矩形、小量统一图标、短标签及直线/直角折线，不再使用每条边都弯曲的箭头毛线团。
- 同一房间对的双向边视觉上可合并为一条通道；双方状态和观察时间不同时必须保留方向差异。不得从一个方向推断反向或从旧观察推出实时安全。
- 已知受阻、未知通行、上次观察分开表达。精力为0或战斗中，地图已知通路不代表当前能执行移动；地图始终不下命令。
- 线不穿文字/节点；交叉不可被误认为有路口；长名称最多两行，完整名称可focus/hover查看。不得删额外真实已知连接来凑树。
- 允许有限的纯展示布局配置，不建立物理比例、楼层、距离等新玩法事实；不得把布局元数据当全世界知识来源。运行时给出同样公开输入必须有同样有序输出。
- 未预设的公开节点/重复全名必须有可读文字退路；不能崩溃、偷偷选一节点或静默丢路线。

### C5 尺寸与图例

主桌面沿用原三栏，不侵占战斗主舞台。本轮可重分左栏：压缩重复状态/长说明，把地图本身放大到有效可读区域（建议可用高320—380px，根据实际内容定）。当前有限区域最多九个房间，必须证明同屏可读，不使用极小字号凑全图。

硬标准：地图主画布无横纵滚动条；完整已知本地节点、当前节点及明确出口可见；正文/节点主要标签按主桌面不小于14 CSS px；四周与装饰边框有安全内边距。世界图同样一屏显示当前已知区域。展开地图提供更大的可读空间，但不是修补小图本身不可用的借口。

主图例最多“当前／已到达／待探索”一短行。方向、旧观察和阻塞的详细解释放在对应节点/连线详情与可访问帮助，不再让五行图例挤掉地图。

只读完整路线表可以保留作按需详情，但不在左栏默认展示。任务详情允许合理局部滚动；小地图画布不能靠拖动/双滚动才获取基本拓扑。

## D. 明确不做

不新增快速旅行、地图点击移动、路径批量执行、世界传送或自动选入口；不把酒店入口改成酒店大厅；不改移动成本、探索揭示、节点连通、任务资格、物品来源或病程。不增依赖、全功能图编辑器、通用任务SDK、新存档字段、手动回写知识、广泛响应式适配。
