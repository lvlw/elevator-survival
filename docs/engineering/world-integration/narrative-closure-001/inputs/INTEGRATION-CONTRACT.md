# 接入与安全合同

## I1. 沿用一份真实游戏状态

原core、S/current、reservation/checkpoint/v4、BrowserOwner锁、原行动/Preview、物品实例、奖励与终局为唯一真相。文稿不是另一套状态机。UI不能读raw current、fact表、内部身份、seed、旧日志字符串来推出剧情资格。

只允许在已校验状态的可信适配层投影本批有限公开状态；如周衡现场是否可交谈、工单已调查、已正式获得method、供电/安装成果、样本公开现状、正式结局类型。引用明确的原事实/动作语义，不按短地点名猜人、按图片猜阶段或扫全部档案猜过去。

## I2. 会面、阅读与行动不同

当前L5、存活、有效owner、稳定且无战斗/原立即结果时，主动会面可用。可以不谈、可以略过、可以提前结束，所有原合法行动保持可达。

谈话、翻卡、选择追问、回看、关闭只影响呈现和受控附属阅读记录；零玩法dispatch、零checkpoint、零熵、零消费。原method或install等行动不能被“继续对话”隐式执行：明确选择原动作入口后，原参数/确认/提交链只走一次。

不要将“谈了周衡”变成得到技术优惠、识别任务件或成功的前置。不要根据玩家选项增加好感、情绪数值、宽恕或隐形奖励。

## I3. 本次提交见证与静态成果分开

当前首段ExplorationReceipt只覆盖departure/move/search/pickup/door/workorder；旧B1是战斗动作呈现，两者不冒充平台安装事件。允许新增窄closure回执，或在明确兼容测试下增加受支持种类；采用哪种由Codex在M1定位，旧字段/种类语义不变。

即时演出须绑定本次真实受控提交、同一执行、原revision、原命令和结果；facade/controller直接返回，必要的临时scope/序号独立使用。不订阅状态变更猜“刚装好”，不从Feed文本或两个UI快照反推。

安装成功且仍活、稳定H8、成果成立、控制未失效，才能自动呈现首次恢复。提交造成死亡或终止时，结果优先，普通剧情不再显示。query、预览、取消、拒绝、save retry、冷恢复、重新挂载都不签发首次动作；失败/异常也不补发物品或重做操作。

已恢复后冷进入或回访，只显示静态已恢复及可主动查看的公开说明，不重新播放“最后一道固定件落下”，不凭成果写“你听见远声”。

## I4. 原保护不松动，终局专用呈现

原use-entry-story对dead/living-hub的撤除保护继续；新终局短呈现通过专用consumer或明确分型，绑定本次真实终局及有效owner。死亡中不得显示NPC继续/安装胜利/生还召回；成功或失败后不得继续原活动委托命令。

原L2参数/L3保护、待战斗、立即后果、程序错误和保存失败反馈优先。终局文字旁始终能看到真实清算和保存状态；不能把“不隐藏存档错误”变成长篇工程术语。

成功、主动失败、截止生还失败、死亡分别来自原结果；不得只看当前room或样本缺失猜结局。重伤不减奖，死亡不额外套失败罚；所有金额与物品去向只显示原已生效结果。

## I5. 有界阅读记录，不扩主存档

复用现有BrowserOwner下的有界附属记录；允许有限新增片段键及必要校验，禁止独立writer/第二锁/React直接localStorage。主存档格式及身份规则不改。

保持read/skipped/dismissed不同；未实际播放不能标read，翻页不保存玩法进度。NPC可交谈、主动读过、正式method已做不能合并成一个flag。

本批不要求跨会话的角色关系或完整对话树进度。旧记录缺新片段正常；坏JSON/版本不识别/绑定不符只降级阅读辅助，不清游戏档、不重新发初配、不补播序章。任何阅读版本兼容处理须明确写在报告；不作静默玩法迁移。

游戏已提交而保存失败：可显示一次实际行动反馈，阅读标记暂留内存；retrySave仅保存，不重新安装、交付、发奖或演出。附属记录失败不反向把原成功checkpoint判失败。失权/retired controls/timer/Promise不能写入或复活旧叙事。

## I6. 不复制已解决的界面

继续复用底部短反馈/最多三卡、已修任务详情、两层知识地图、Hover/Focus轻说明、真实物品与原行动输入。地图只读，原任务指引继续作为下一步方向来源；不在剧情里新造另一个攻略面板。

主视口固定1920×1080 CSS；小范围样式只为新增节点就地整合，不重做侧栏、地图、整个按钮体系或多分辨率。保持原reduced-motion路径；不把系统媒体/真实zoom的历史NOT VERIFIED写成这轮PASS。

平台状态可使用已有场景与代码绘制的小型灯态/面板，不采用未批准的玩家v2、实验版全局皮肤或新素材。没有已获准人物图时，明确角色名和现场关系，避免开发占位说明；不以补美术拖延真实接入。
