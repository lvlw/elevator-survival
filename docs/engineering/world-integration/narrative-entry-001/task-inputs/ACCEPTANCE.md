## D. 一次主视口浏览器验收

使用原React/BrowserOwner/DEV入口、一个隔离测试环境。主档1920×1080 CSS视口，记录实际innerWidth/innerHeight/DPR与图片固有尺寸。此为本轮实际主档，不声称Owner日常设备已确认。

1. 新空环境走中枢—略过或阅读日记—任务—工具/专长—创建—出发。关键任务/失败告知不能被略过机制吞掉。
2. 自主走大厅/药房，真实单次照明搜索不出现单项表单；物品hover、拾取、取空、重开都在同一新版UI。
3. 原真实路线达到H7，完成工单才出现署名；回看不再调查。不要为截图直接注入完成fact。
4. 旧角色恢复只取已有已审合法checkpoint作为**明确标注的恢复专项**，不冒充上述新玩家原生路线；不自动重播。
5. 主视口无文本/边框溢出、对话遮按钮、双滚动区覆盖或无用的大空结果。保留原非阻断地图改进欠账。

代表原图4张即可。保存失败、失权、不同随机分支和边界主要用确定性React/正式命令测试；无证据需要时不再铺浏览器矩阵。未有适用原生浏览器能力就说明具体缺口，不反复操作无能力接口，不让Owner调系统来救验收。

## E. 最小负控

至少四类临时变异须被业务断言检出并还原：
- 未调查H7就公开正文；
- retrySave再次签发剧情/搜索结果；
- 唯一工具便捷调用绕过原L3或重复dispatch；
- 失权旧回调仍写阅读书签/恢复旧叙事层。

先确认不是编译/加载错误造成失败；记录变异点、用例与失败摘要。最终check在还原后运行。不要新增巨型mutation框架。
