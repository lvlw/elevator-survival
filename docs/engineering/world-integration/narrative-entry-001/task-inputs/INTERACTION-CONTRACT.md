# 首段交互减法与呈现合同 v1.0

## I1. 唯一工具不再选第二次

本批覆盖source/task中的lit/crow/toolbox/card工具意图。用户已经点了“照明搜寻”“使用撬棍”等明确方法；`describeAction`只缺item且公开候选恰好一个时，构造绑定该真实selector的完整请求，仍经原preview、capture、confirmation与execute链。

不按名字扫描raw current，不选择候选第一项，不把工具选中变成新实际持有者。以下均不自动补齐：有第二个真实候选；缺数量/摆放/多产物位置/伤口/目标/材料/池分配；动作方法未选；句柄过期。零候选或电量等公开资格不足时显示原安全拒绝/不可用原因，不为了继续而选另一个工具或改成普通搜索。

仅有一个候选也不自动省略原L3保护。`unknown`不等于安全，不能用隐藏感染资格筛选候选。一次点击只能一笔原提交、原写入和原结果；双击、重绘、按钮hover均不能执行。

实现建议：新增小型纯request补全助手，供执行与短说明共同使用；只基于安全公开输入。原普通拾取first-fit保持，不自动旋转、重排、补快捷位或改变任务件明确放置。

本批不开展“所有药食/维修自动选好”的泛化项目。真正多伤口、多材料/数量/维修池仍给有意义的参数；物品已指定的上下文应保留指定对象，不重新让玩家从全列表选一遍。

## I2. 不再让ⓘ成为每个动作/物品的常驻伴侣

普通ActionButton和物品格的默认读法改为短hover/focus提示，主点击仍执行原意图（或原本就存在的详情入口）；F1/明确详情等可访问路径保留。不能把hover实现成会捕获焦点、挡住按钮或必须关闭的对话框。

提示应靠近触发物，避开主按钮；鼠标移开/失焦、动作或实体失效即消失。长内容进入主动详情，不把全部SafeFacts塞进每个小tooltip。可使用很短的可取消延迟避免扫过时闪烁，但不绑定游戏时钟。

用途文案来自正式内容的安全摘要。绷带至少说明基础恢复、止血/适用伤口，以及已存在的生存首用例外；基础/条件说明可以取正式配置，不得在React复制数值或宣称当下必定恢复固定HP。抑制剂/消毒剂不能通过不同tooltip或按钮可用性泄露隐藏目标。

感叹号/警示形态仅给实际异常、未保存或需注意的风险；不把每件正常物品都画成警报。不强制把全部详细说明删掉。

## I3. 成本事前可查，结果事后准确

明确行动方法后，唯一输入可安全完整绑定的动作在短提示中展示正式preview返回的公开成本；可见主按钮附近保留必要的简短成本，不要求先点说明。

结果记录可以写“使用手电筒完成搜寻 · 电量 −N”；N必须来自N3可信提交回执。保存失败明确写“操作已生效，尚未保存”，不是“执行失败”。回看、retrySave和订阅不得再追加一条动作消耗或重播。

不把新详细反馈变成第二份持久游戏日志；继续沿既有session-local Feed/结果展示责任，旧Feed语义保留、只在本批真实回执支持处丰富文案。

## I4. 一个场景，不是一排系统入口

- 防火门是一个现场对象，合法方法属于同一对象的不同办法；仍是原独立命令，不把开门和移动合并。
- 搜索结果有物时清楚显示名称、用途、占格与直接拾取；取空后紧凑展示，不占中央半屏。
- 对话在中央场景下方有界呈现，任务发布用中枢风格；不挤掉生命/精力、当前位置、行动、必要参数、未保存警告。
- 复用已接入三栏、背景、工具/物品图与C2敌图。做完本段真实页面，不以另开原型URL/静态截图作为交付。
- 本批不重画节点地图、不添加拖拽/寻路，不扩大分辨率范围。主视口若因新叙事布局发生溢出，属于本批要修的可用性问题。

## I5. 信息与戏剧的优先级

最高优先：真实死亡/终局、失权/异常、未保存提示与原确认。
其次：玩家当前主动打开的必要参数/详情。
最后：环境短句、初次观察与普通发现反馈。

读文字零玩法效果；点击“采取行动”才调用原命令。自动播放不能先执行再征求确认；跳过不省略真实成本。首战不因动画未结束锁按钮，不合并B1的去重scope或改它的180ms等原行为。
