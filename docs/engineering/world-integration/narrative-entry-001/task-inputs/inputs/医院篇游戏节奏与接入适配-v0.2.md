## 1. 本轮确定了什么

Owner已经接受v0.1主线：保护性的紧急停运留下未完成的恢复；周衡为执行人；林岑提供等待者视角；玩家首先为回到现实而行动；高潮从循环录音转向真实回应。

本轮精写继续这一方向，并将文字与下列体验绑定：

**目标先讲清 → 尽早亲手行动 → 自主决定路线 → 调查／人物提供不同角度 → 真实成果带来场景回应 → 真实返航与结算。**

不重新询问是否采用已经确认的核心冲突。具体台词、提示呈现与叙事记录接缝仍为本轮定稿输入，不冒称现有实现。

## 2. 节奏不是延长阅读时长

不把“写满一小时”设为目标。当前没有本剧本的真实游玩时长数据，不能声称这套文本会自然带来30、40或60分钟乐趣。观察的是玩家什么时候开始有计划、什么时候愿意继续，以及什么时候被操作或文字拖住。

### 文本密度建议（设计预算，不是测试结果）

首次自动引导：同一必经段最多连续三张短卡；一张卡容纳同一语义的一到三句，不逐句索取点击。连续两个已提交普通动作后，不强行补播积攒的三段旁白。

普通新地点：一条短观察优先；没有值得说的新信息就安静。重复经过：默认无弹出。重要人物：初见简短开场，剩余话题由玩家主动问。高潮：两到三段声音／画面变化可比日常更慢，但可跳过且不改变结算。

教学退场不是按计时器：玩家已经独立完成某类操作后，不再讲同一功能。跳过教学的人仍有短hover/focus说明、公开成本和正式保护告知，不能以“你没读”处罚。

## 3. 一条首段示例路线，不是新强制路线

1. 显示屏给出回归现实的目标；玩家可读或不读日记。
2. 准备期叙事转场后，看到两项实际成果、七任务日、返回点和失败边界。
3. 在补给柜选择工具／明确专长效果，正式创建成功，再真正出发。
4. H0醒来，认识返回点；当前合法其他方向不被隐藏或锁住。
5. 进入H1听到循环广播，开始形成“为什么仍在播”的问题。
6. 自己选择搜大厅、去药房、查值班区域或后勤方向；不是接到按键顺序测试。
7. 搜索完成后看真实掉落，选择带走，背包实物发生变化。
8. 面对防火门或其他路线取舍，自行判断现在做什么。
9. 只有实际进入遭遇才发生首战；玩家可以退却，不赠保底胜利。

**首段的设计验收问题：** 玩家不用看外部说明，能否说清“我为什么进去、要做成哪两件事、回哪里，以及现在自己想先做什么”。不要求他说出作者偏好的路线。

如果玩家从H0先去酒店或通信，允许直接开始那里的发现；大厅广播推迟到真正抵达，NPC不能假定玩家已经听过。用于文字审读的线性顺序不成为玩法前置。

## 4. 交互减法是叙事接入的组成部分

### 4.1 完整意图直接执行

“照明搜寻”本身已经是玩家意图。如果当前公开可用的手电唯一、所有必要参数可唯一且无损地确定，就由现有安全描述与选择句柄组成完整请求。按钮处显示本次可知成本，执行后在既有结果记录显示真实消耗。**不再弹唯一一项的下拉框，也不再追加普通确认。**

这里的“唯一”不能变成UI扫描内部状态、猜物品、选择第一个实例，或用hidden eligibility泄露知识。若存在多个耐久／电量不同的工具、多个数量分配、多个伤口或位置方案，就保留有意义的选择。

“先不选也能执行”不是目标；消除伪选择，同时把真选择做好，才是目标。

### 4.2 普通说明用hover／focus，不用遍地惊叹号

- 常用物品的短用途、已知代价与状态由hover/focus展示；普通点击详情仍可用，不要求先点说明才能行动。
- 绷带不能机械地在所有状态显示“HP+1”。当前正式规则有专长首用差异、上限和目标资格；文案必须反映适用效果，不在UI另抄公式，也不把隐藏目标是否合格通过提示泄露出来。
- 感叹号留给真正待注意的异常或风险，不作为所有说明的装饰。文字、边框与图标要有层级，不只靠颜色。
- 详细规则按需打开，不能把原参数表单换成更长的说明弹窗。

### 4.3 不增加新的通用保护确认

沿用正式L0—L3：读文字零玩法效果；普通完整意图一次执行；必要参数仅补缺项；返程、跨日、关键物处分及正式必死安全分流等沿当前有效约定处理。

不把“有剧情”“第一次战斗”“推进任务”本身当作新增L3理由。关键区别是这次选择实际有什么风险和不可逆性，而不是按钮属于哪类场景。

### 4.4 搜索／发现／拾取分得清，但不分成三次教学

搜索是付费行动；结果展开是展示；拾取是真实迁移。普通结果直接提供拾取入口；可用原first-fit的场合不强迫手填格位。任务提取、真实多目标或多数量仍按原明确输入。

没有地面物时保持短摘要；重新打开查看不重搜、不发物。不让“现场物品0件”成为中央最大的信息块。

### 4.5 风格化美术与顺滑交互同步

剧情并不为左右栏溢出、低可读文字或无效窗口遮挡提供借口。这些是主视口基本可用性。跨五档分辨率、真实zoom、DPR2、移动版专项仍按Owner决定阶段性后置，不借叙事工程重新扩张。

### 知识变体的优先级

同一时刻只选一组适用短句：终局／失权先于普通对话；已完成成果先于“还需恢复”的旧台词；亲自调查所得与NPC转述分开；被读过的叙事片段不能被“来源事实为真”直接替代。

例：先供电、后见周衡，不再让他说“那边还没通电”；先见周衡、后读工单，不再让主角第一次惊讶“有人主动停运”；先旁路进入机房，不强迫回去补打一场技术员。

## 6. 对现有底层的影响，不能全部叫“纯UI”

### 已有结构可复用

五图地点与通路、真实搜索和物品、任务生产者、战斗、终局、现有保存和安全动作入口继续复用。上限、精力、疾病、奖励、失败罚则和初配不随剧本改变。

### 本次纯呈现候选

任务文字组织、人物说话的语气、底部对话表现、已完成事实的视觉反馈，以及现有公开信息的轻提示，都属于内容或表现设计。正式发布的任务声明必须与玩法一致。

### 下一次工程必须先补清的窄接口

实际读取的 `PlayerReadyView` 只有当前地点、地图、公开目标、样本状态、来源和动作等，并没有完整暴露“已读周衡署名工单”“与林岑说过什么”“听过哪一段广播”的叙事接口。

因此不能让组件扫描raw current、旧战斗、私有facts或日志文字来补故事。需要一个有边界的叙事公共查询／触发记录设计，明确哪些是新增可知文本，哪些只是在表现既有成果。无需先建通用任务SDK或大型剧情引擎。

特别是“系统记录电量减少多少”，现有战斗B1并不等于所有探索命令都已有安全消耗回执。若正式返回不足，就单独确定窄的公开结果契约；不读取raw trace、不从前后血量猜执行过程、不把新增事件总线藏进UI接线。

### 仍未批准的玩法改变

H1大厅直接出生、进世界后才发工具、取消／中途赋予专长、日记赠永久道具、中枢真实等待日结、NPC限时死亡／营救计数、第二份可接委托，均不由本剧本推定授权。

## 7. 对话播放与真实提交必须分离

**读文字不会完成行动，跳过演出也不会跳过行动。**

直接行动通过原唯一入口提交，结果是真实状态改变；叙事只消费受控且安全的已提交事实。失权、死亡、离开当前场景后，过时文本不复活窗口、不替玩家补动作。

关键场景需要区分三件事：玩法成果是否成立；玩家是否已知相应信息；这段演出是否已经播放。不能做一个“剧情完成”布尔值同时代替这三件事。

只读翻页可以是会话内展示状态；与分支、首次触发和回看相关的持久记录如何保存，需要专门定义。持久化已读状态不能令每翻一页都产生玩法revision或重新抽随机。实际存档失败不能把“文字看过了”当成玩法保存成功。

刷新／恢复处理建议：优先恢复最后成功保存的游戏事实；普通历史演出不自动重放。持久叙事能力尚未支持的旧档，从当前事实提供中性的摘要／回看入口，不虚构“你之前已经与某人谈过”，也不重发新手补给。旧档兼容安排需正式批准，本文不暗示自动迁移。

## 8. 美术和演出的投入次序

**第一优先：中枢派发、医院初见、平台回应。** 三处是情绪变化最大的节点：从被选中，到进入陌生地方，再到亲手完成一件事。任务装置、声音、场景状态与对话框应作为同一场面设计，不单独交一套离线预览就算完成。

**第二优先：林岑／周衡的少量有效状态、工具与物品的近看。** 各人物先解决初见、谈话、结果回应的可辨认表达，不先做几十种无处使用的表情。物品说明要短，图像别画出当前装备没有的功能。

**第三优先：一般节点环境细化。** 优先让到访与成果有必要差异，不要求一口气重画全部地图。角色玩家v2、透明清稿与背景2×保留原门槛；不能拿它们当理由不实装已选叙事场景。

动态不为耗时而做：阅读速度可调／文字可立即显示，过场可跳过，减动态不损失信息；慢是为了人物停顿或结果出现，不是为了让游戏看起来更长。

## 9. 后续接入推荐：一个能实际玩到的叙事片段

下一步建议以 **P01—P06＋H01—H05＋H07** 为首个接入候选，覆盖“中枢醒来—任务发布—情境化准备—真实入场—自主搜索与拾取—首次工单悬念”。同时处理这一段直接相关的唯一工具输入、短tooltip与动作反馈；不要先做纯对白播放器，继续让正式游戏保留难用表单。

H06首战的短过渡可一并接入，沿用现有B1/C1/C2，不扩完整逐击B2。中段人物对话和结尾已经有本稿的连续文本，但工程按窄可审边界推进，不把新叙事记录、全文美术和五图接线包成不可审查的大Goal。

这不是把整章重新拆成十轮准备：内容本稿一并给足；第一次做出能在原DEV入口走通的短章节体验，评估其节奏，再复用同一规则接中后段。已确认故事不再反复征求选择，只对新增核心规则冲突向Owner提出明确取舍。

**本文件没有开工授权、分支写权限或commit/push权限。** 工程前仍需集中定稿叙事知识／记录接缝和本批路径，不要求Owner逐函数决定。

## 10. 下一次验证关注点

不再为每段话跑五档浏览器。固定一档主桌面窗口，先验证真实意图与剧情关系：

| 检查情景 | 要看到的结果 |
|---|---|
| 跳过日记／过场 | 目标、期限、后果仍清楚；不少补给、不变更路线、不多结算 |
| 唯一合格手电，点击照明搜索 | 一个普通意图完成一次真实搜索；无唯一选项表单；成本事前可查、结果事后准确 |
| 存在真对象／目标选择 | 没有擅自选第一项；必要参数明确，普通确认不套娃 |
| 搜索随机两种不同结果 | 台词不承诺同一种物资；重看不重抽、不补物 |
| 先供电／先样本／酒店绕开 | 对话匹配真实先后；主线资格不增加读完某人的门槛 |
| 真实失权、死亡、保存失败 | 失效叙事层不遮终局、不复活旧控件；保存重试不重放行动或奖品 |
| 未去过或未调查的分支 | 不提前画节点、不替玩家知道署名或时戳、不读raw状态 |
| NPC只聊不交换／反复回访 | 0物品交易；有一次性完成后的不同回应，不重复来源 |
| 转运已成但没拿样本 | 让人感到成果真实，同时明确仍有未完成目标，不提前通关 |
| 主段首次体验 | 玩家能说出目的、当前局面与自己的下一步；不要求背出最优路线 |
