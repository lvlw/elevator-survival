# 验收清单

## A. 规则适用边界

- [ ] ordinary + stackable 才进入自动补堆／部分拾取。
- [ ] non-stackable 普通物品保持现有完整实例放置要求。
- [ ] task item / access permission / component / module 不进入普通 pickup。
- [ ] DEC-017、DEC-052、UIR-015 均未被改写。

## B. 容量行为

- [ ] 先补充背包内兼容未满堆叠。
- [ ] 兼容堆叠填满后，剩余数量再尝试 first-fit 空格。
- [ ] 仅空间不足时，按可容纳数量部分拾取。
- [ ] 仅负重不足时，按可承载数量部分拾取。
- [ ] 同时受空间和负重限制时，取两者允许的最小数量。
- [ ] 无任何可拾取数量时，拒绝且零副作用。
- [ ] 合并不减少重量；堆叠只节省格位。

## C. 来源与恢复

- [ ] 合并／拆分后来源份额无重叠、无丢失、无重复。
- [ ] 原地面剩余单位仍留在原节点。
- [ ] ItemState 未刷新。
- [ ] 保存恢复不重复应用拾取或合并。
- [ ] 不引入时间、UUID 或随机数作为规则身份。

## D. 玩家体验

- [ ] Preview 解释可拾取量、合并量、新建量和剩余量。
- [ ] 普通 1×1 stackable 物品满格仍可通过兼容堆叠拾取。
- [ ] 不自动装备、补快捷位、整理、旋转已有物品。
- [ ] 任务物品的选位与受控转移未变化。
- [ ] 真实浏览器画面和操作证据覆盖满格合并与部分拾取。
