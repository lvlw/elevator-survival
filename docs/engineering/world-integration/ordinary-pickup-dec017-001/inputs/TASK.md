# 任务书

## 1. 目标

在新感染世界的普通物品拾取链中，落实 DEC-017 已确认的堆叠拾取语义：

1. 对 `ordinary && stackable` 的地面物品，优先补充背包内已有的兼容未满堆叠。
2. 再把剩余数量放入可用空格。
3. 同时遵守背包负重和格位约束；只能容纳部分数量时，只拾取可容纳数量，剩余单位留在原节点。
4. 当全部数量都可并入已有堆叠时，不应要求虚假的空格放置位置。
5. 只有确实没有任何可拾取数量时，才拒绝；拒绝不得扣物、改变状态、写入保存或产生部分效果。

这是实现已确认规则，不是新增规则。不得借此改变掉落数量、物品尺寸、重量、堆叠上限、来源配置或其他玩法参数。

## 3. 权威规则与边界

### DEC-017（已确认）

首版 1×1 可堆叠物品拾取时：
- 优先补充背包已有兼容未满堆叠；
- 再为剩余数量创建新堆叠；
- 背包空间或负重不足时，只拾取当前能够容纳的数量，剩余留在原节点；
- 堆叠只节省格子，不减少重量；
- 状态不兼容的物品不能合并。

### DEC-052 D03（新感染世界局部规则）

任务物品不是 ordinary。任务物品提取和搬运必须由窄受控生产者校验执行身份、阶段、位置、真实实例、资源、明确格位和负重；不能将任务物品全面开放给普通 pickup。

因此：
- 本任务只处理当前正式目录中 `ordinary === true` 且 `stacking.kind === 'stackable'` 的普通物品。
- 密封病原样本箱、门禁卡、任务组件、通信模块及其他非 ordinary / 非 stackable 实例不得进入这条路径。
- 不改变 `task-transfer`、任务物品留置、取回、安装、交付及来源资格。

### DEC-052 D08（真实来源与严格守恒）

必须保留来源份额、实例身份、ItemState、拆分／合并的来源范围及唯一容器约束：
- 不能按名称生成替身；
- 不能删掉原实例再无来源地重建；
- 不能重复消费或重复发放；
- 部分拾取、合并和保存恢复后，来源份额仍须严格守恒。

### UIR-015 当前有效约定

普通 revealed node item pickup 的 Interaction 继续遵守当前有效 first-fit 约定：
- 固定 row-major（先 y 后 x）；
- 使用正式 Preview 检查未旋转放置；
- 不移动、重排或旋转已有物品；
- 不自动旋转待拾取物；
- 多数量仍由玩家明确输入；
- 无合法未旋转方案时，才进入原有手动放置／旋转路径。
先补兼容堆叠，再对剩余数量应用上述放置规则；不能让 first-fit 反过来阻止本可完成的堆叠拾取。

## 4. 具体实现要求

### 4.1 兼容堆叠

- 只在背包中查找目标堆叠，不把装备位或快捷位当作可合并背包堆叠。
- 兼容性必须使用现有正式定义／`areItemStatesStackCompatible` 等唯一规则，不能只比较显示名称。
- 必须尊重物品定义的堆叠上限。
- 多个兼容堆叠时使用稳定、确定的顺序；优先沿用现有 row-major 位置顺序。若现有正式材料对此没有明确规定，将该排序记为实现 Draft，并在报告中说明。
- 堆叠后的总重量仍按单件重量 × 数量计算。

### 4.2 部分拾取

- 对多数量普通堆叠，保留现有“玩家明确输入数量”的交互。
- Preview 必须显示实际可拾取数量、合并数量、新建堆叠数量／位置，以及留在地面的数量。
- 若空间或重量只能容纳一部分，允许只拾取可容纳部分，余量留在原节点。
- 若全部数量可合并进现有堆叠，则不应要求额外格位。
- 若完全不能容纳任何数量，拒绝并给出可理解原因，状态和保存均不改变。

### 4.3 来源与身份

- 使用现有确定性 stable split identity / provenance 机制。
- 合并时转移准确来源份额；部分拾取时分割不重叠来源范围。
- 地面剩余数量必须继续存在，已拾取数量必须只在背包出现一次。
- 保留资源状态；不因合并、拆分、保存恢复刷新电量、耐久或其他 ItemState。
- 不使用系统时间、UUID、Math.random 或新增随机源生成实例身份。

### 4.4 UI / 预览

- 只对本任务涉及的普通可堆叠物品接线。
- 玩家看到明确结果，例如“可拾取 2，另有 1 留在现场”，并知道原因是格位还是负重。
- 不自动装备、不自动补快捷位、不自动整理现有背包。
- 任务物品现有明确选位与保护确认保持原样。
- 不重做整套背包视觉，不扩展移动端或多分辨率适配。

- 不改变任务物品或特殊任务转移链。
- 不改变保存格式、来源模型、Run/委托生命周期。

## 7. 开工、验证与交付

开工：
1. 读取准确 BASE 的 `AGENTS.md`、DEC、UIR 和相关源码。
2. 核对 HEAD、分支、worktree、status、diff。
3. 实际运行 `npm run test:run` 建立本轮基线；报告真实文件数和测试数。
4. 检查当前普通物品目录中哪些项目实际 stackable，不得按显示名称猜测。

必须新增正反例：
- 完整背包但存在兼容未满堆叠：仍能拾取并合并；
- 兼容堆叠有余量，合并后仍有剩余且有空格：先合并，再新建堆叠；
- 兼容堆叠有余量但没有空格：只拾取可合并数量，余量留地面；
- 负重只允许部分数量：只拾取负重允许数量；
- 格位和负重均无容量：拒绝且零副作用；
- 物品状态不兼容：不合并，若有空间则独立放置；
- 多个兼容堆叠：顺序确定、数量守恒；
- 任务样本箱／门禁卡／任务组件：仍走原受控路径，不进入 ordinary merge；
- 保存恢复后不重复拾取、不复活来源、不重复合并；
- 旧医院相关测试语义不变。

必须覆盖：
- Core 正式计划／提交；
- Player Preview 与公开查询；
- React 实际拾取流程；
- 来源份额与 ItemState 守恒；
- 真实浏览器至少一个 1440×900 桌面场景，展示“满格但能并堆”及“部分拾取后剩余留地面”两种结果。
