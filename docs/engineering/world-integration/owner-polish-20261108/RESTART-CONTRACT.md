# 死亡后新尝试的 Browser 契约

仅已落盘的正式 dead 可开始。旧局继续显示，准备界面中的工具、专长和撤销只改变草稿。最终确认以后，唯一持锁 BrowserOwner 生成一次新身份，用原 createFirst 生成初配并截获严格 prepared checkpoint。该临时 session 从未成为可玩上下文，写入端只接收一次内存交接。用原冷恢复验证候选，核对新角色、run、generation 均不同，旧死亡局仍与最后成功写入的 checkpoint 一致。

替换的提交点是现有 CHECKPOINT_KEY 的单次同步 setItem。替换后该 key 存放严格 tagged envelope，内含新 reservation 与原 v1 checkpoint。原 reservation key 不再决定这个槽当前角色。普通保存或重试继续覆写同一 envelope。初次创建和旧合法 v1 双键读取走既有路径。旧客户端对新外层严格拒绝，不能用旧版本继续此档。

| 边界 | 结果 |
| --- | --- |
| 取消或未落盘死亡 | 无新身份或存储写入 |
| 生成、严格准备或验证失败 | 保留旧档，当前草稿不会再次生成候选 |
| 读取核对失败或写入抛错 | 保留旧档，保存重试沿用同一已准备候选 |
| 提交前失权 | 禁止写入 |
| 提交后失权、刷新或冷读失败 | 完整新档已持久化，仅由再次持锁冷恢复读取 |
| 新局接管 | 旧 controls、叙事及演出选择失效，使用新的正式第一中枢 |

读取新旧格式均零写。新局阅读记录使用新 generation 专属副键。旧阅读记录留在原键，读取新局时不参与新角色的阅读标记。游戏 v4 字节、生命周期、保存期望和原单写者协议照旧。存储验证限于浏览器单键更新的逻辑原子性。
