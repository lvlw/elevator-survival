# 感染驻留玩家安全查询与受控选择合同 v1.0

状态：MAINLINE_RATIFIED_TECHNICAL_CONTRACT。经 DOC-WORLD-QUERY-001 原字节归档并实审后成为本范围唯一工程依据；不是新增 DEC／UIR，不授权新增玩家知识、UI接入或生产开工。

## 1. 来源、适用版本与唯一事实

技术定稿基线：`7a3acd3855aefdde68fdaed13ebe037f3e9bd6de`。承接同提交 `docs/engineering/world-integration/route-acceptance/query-contract-draft-v1.0.md`、`query-field-matrix.json`、`next-engineering-contract-draft-v1.0.md`；当前事实以真实 v4 CombatValue／唯一会话为准。玩法权威仍为有效DEC，特别是DEC-013、025、026、045、049—052；展示边界读取UIR当前有效速查及相关010—012、015。

这些候选并未证明查询实现完成。原矩阵3 supported／12 partial／9 not-supported仅是基线支持快照，原生TEST公共事实适配器不是生产玩家视图。实际查询工程不得把候选字段存在当成已实现。

唯一current、身体、物品、来源、敌人、任务、钱包及历史仍由既有P/R/S持有或校验。查询不接收调用者的下一状态、Effect、随机结果、资格结论或隐藏风险；不能通过完整getState序列化再删几个顶层字段来构造玩家视图。

## 2. 四领域phase、五合法停点与未创建状态

领域phase仍为first-hub、active-world、living-hub、dead。active-world分别投影为稳定世界和完整玩家战斗决策点；战斗不是第五领域phase。适用完整停点：首次中枢、稳定世界、玩家战斗决策点、生还中枢、完整死亡。无current／坏档阻止加载是应用状态，不伪造角色死亡或新委托。

首次选择catalog可在尚未创建current的Setup准备层读取，不发物、不创建角色。已有first-hub中的真实初配选择只按正式能力展示；不能因为界面仍在中枢就重新调用初配、更换已锁定选择或补发物资。本合同不新增改选命令。

## 3. 只读投影与命令选择分层

### 3.1 玩家读入口

纯查询读取受控composition提供的严格current、版本绑定dependencies和真实持久化状态，只返回显式白名单、不可变的玩家视图。query／preview／Hover／Focus读取：零玩法mutation、零revision、零生产者／Effect计划／随机、零保存、零通知、零行动authority签发。

玩家视图不能包含完整内部状态、raw规则对象、完整receipt／trace／archive、真实origin／execution／seed、未揭示产出、敌人精确HP、raw CTB或未来随机序列。错误说明、嵌套值、accessibility属性和selector也要按同样边界检查。

### 3.2 不透明选择器

物品／伤口的真实技术ID只留在受控接缝。普通视图使用不包含、也不编码原ID的session-local opaque selector；不得使用base64、长度编码、截断或哈希真实seed／execution／origin来伪装安全。静态公开catalog枚举不因此变成秘密，但它只能在对应知识条件下出现在视图中。

选择器只是找到当前已知对象的句柄，不是行动授权、结果或恢复资格。私有映射只保留对象身份与视图绑定元数据，不存第二身体、敌人、库存、余额或资格缓存；不持久化到v4，不改保存格式。具体字符串／对象句柄表示可在工程详细设计内确定，但必须证明跨会话、旧快照和冷恢复的失效约束。

### 3.3 映射生命周期与读取零副作用

不让查询在每次读取中隐式更新绑定表。可在显式composition建立、canonical已提交或已恢复时生成新的不可变投影上下文；或者使用具有等价约束的纯生成方案。重建上下文只做展示派生，不提交玩法、不保存、不发新任务；禁止异步监听器分别改资源或结算。

同一current重复读取保持同一选择含义。current推进、phase／battle变化或冷恢复后，旧绑定不得误指向同序号新实例。保存失败后使用已提交的新内存视图；仅retrySave不推进current，不重算规则或重新发物。映射失败不能回滚已提交玩法或把旧视图冒称最新可执行状态。

### 3.4 最小受控选择提交

未来Interaction将显式选择及必要数量／坐标／旋转／目标送给最小受控解析入口。入口先核对会话、快照、用途及真实对象绑定，再形成既有正式命令交S执行。无未知句柄fallback、自动目标替换、自动走多边、自动拾取或静默重试命令。旧revision／battle／已消费实例即使名字相同也不能通过。

查询字段或内部按钮enabled不是最终授权。S／原生产者仍验证最新合法性并执行一次；解析选择器本身不产生Effect或更改current。与保存重试是两个独立操作。

## 4. 24项字段的边界

具体清单见同目录 `player-query-field-contract-v1.0.json`。它保留原24键和3/12/9支持分层，但将支持快照与未来验收责任分开。

- 地图只显示canonical已知节点／路线；远端只为最后观察，不因内部有通路就预告未知侧门。地图查询不成为第二导航入口。
- 当前来源机会、已领取事实、本地已揭示地面和真实容器分别投影。未揭示物不可提前显示；来源查询不可物化物品。完整来源账本留内部。
- 任务目标按玩家已获得／已观察／已正式完成的事实显示；持有指定样本与已交付不是同一进度，普通物不得替代指定实例。不将访问五图数量当作成功条件。
- 战斗仅显示正式当前意图、允许公开的敌阶段和相对顺序、可用命令与必要资源说明。不得投射完整未来序列或通过试跑resolver得知结果。已有五阶段映射须回用正式同源owner；不能为新敌人凭经验另划阈值。
- 玩家HP、精力、饱食、公开伤势和已发生药耗可展示；感染只按已批准当前公开阶段／机制表达。缺少新世界正式安全映射时明确unknown并记录缺口，不借旧医院阈值、不展示进度精值或预测某次隐藏日结必死。
- 终局摘要来自真实已提交结果，包括所得、扣款和安全物品处置摘要；不泄露原始绑定。生还中枢无新真实内容时明确无后继，不生成继续委托、自动治疗或Day8。
- 保存反馈来自实际S持久化状态；内存已提交但保存失败必须与已保存区分。查询本身不读取磁盘核验或写入。

所有字段必须有实际同源来源和知识依据。unknown不得写成safe或not-guaranteed；确需新知识、精确未来推断或新提示机制时，在该字段停止并提待审问题。本合同不借unknown永久删除所需查询能力；对应缺口必须列入交付及进入UI前Gate。

## 5. 同源资格与安全预览

地图移动、来源、任务、药食、维护、战斗和终局的资格／费用必须复用或窄抽取正式纯校验owner，不在React、查询facade或TEST策略里重算规则。禁止用调用生产者并丢弃结果的方式获取预览；那仍可能签发、抽取或消费。

若当前代码只有内联资格，实际工程任务须明确可窄抽取的路径和保护测试后再改。抽取只复用现有规则，不新增通过条件、不放宽P/R/S。先做范围内完整详细设计和测试，不让Owner逐函数协调。

所需公开安全metadata不足时，不根据隐藏内部布尔、概率或精值生成更详细的拒绝说明。信息相同而隐藏状态不同的一对合法输入，应在所有可见字段、选项、数量、排序和拒绝说明上保持一致；实际公开伤病、药耗或知识变化则应如实不同。

## 6. 验收与不在范围内

工程应覆盖五停点、no-current／blocked、24字段、三敌、来源与实物、两类战斗死亡、Day7和H0空steps、跨会话／冷恢复／旧revision选择器、非法输入与错误对象传播。逐层查字段，而非只过滤名为seed的顶层键。

零副作用观察覆盖核心生产者、随机、authority、S dispatch、Storage和通知；合法与拒绝都执行。透明性负控应故意注入raw selector／隐藏值并被拒；选择器失效负控应捕获旧对象被误接受；真实公开变化保留对照。

不同会话句柄可以不相等；测试只能对句柄进行一一重命名比较，同时独立扫描其载荷。不能删除整个动作列表或选择器后假装非干涉通过。重复读取同上下文应稳定。

不批准UI、DOM接入、浏览器存储、多标签、O3、商城、身体服务、第二委托、跨未来委托改专长、素材制作或依赖升级。本合同不能自动执行下一工程；工程交付后仍准确SHA实审，完整E03与Owner体验另验。
