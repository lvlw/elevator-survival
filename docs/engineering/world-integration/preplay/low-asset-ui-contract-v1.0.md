## 1. Goal与复用

完成新世界显式DEV入口、五停点与全部已有正式操作的低资产可玩界面。复用已审安全facade、controller/browser owner、合法UI primitives和真实对应资产；不把旧医院StableRun Store、Scene Time、旧感染终末或New Run流程套到新世界。

沿用Stage-First：房间／战斗为中央主体，主要决策不依赖整页滚动；只读已知地图、正式单边Travel Cluster、装备／背包切换、真实6×4 footprint和两个快捷位。不得做成长而密的开发按钮台。窄屏可读性和必要操作不能靠截掉控件或缩小字伪装。

既有资产必须核对真实绑定；缺图可中性功能框或通用占位。不得把搬运工画成护工、不猜敌人真实定义、不用贴图或房间文案泄露未知路线／结果。新音频、最终人物、五图最终美术不是本批前置，也不在此授权制作。

## 3. 分级交互与草稿

L0 Hover／Focus／地图／Preview等读取零dispatch、零IO、零玩法作用。L1只对完整普通意图一次执行。L2只补必要方案、数量、格位、旋转、源／目标、材料及机械总池分配；不默认首对象、最大数量、自动替代材料或填槽。

L3主动返回、明确截止、任务关键物留置及获准破坏性操作按当前有效UIR保护；动态必死保护只用基础工程已审的完整命令安全事实，不把unknown等同安全或全部必死、不套统一弹窗。确认绑定原请求及重要安全上下文，提交前重验，失效则显式重选。

普通已揭示整实例pickup可采用既有便利：玩家明确点击后，未旋转按y再x逐格调用正式安全Preview，首个合法锚点形成同一正式请求；无合法位置进入手动旋转／放置。不自动重排、旋转、拆合、补快捷或另发整理。新P的整实例语义保持，不借旧医院优先堆叠文案新增自动合并。任务取得／task-transfer／交易／安装材料不扩展first-fit。

物品图缺失可占位，数量大于1才堆叠角标；背包／快捷右键和键盘等价菜单就地操作。装备仅显示已有正式支持操作，战中只读携带不等于可整理。

新current、恢复或阶段／战斗变化时所有旧对象草稿／确认失效；retrySave同current不另换目标。双击单飞、取消0动作，任何旧selector拒绝后不静默刷新再发。

## 4. 更新、Feed与信息安全

严格委托基础controller的稳定安全snapshot与显式ready返回；原生blocked回调不是最终React状态。执行已提交／保存失败、普通拒绝、程序异常三类反馈分开。Feed只读已公开实际变化，不能从raw commit／previous current补隐藏信息；刷新以“恢复当前状态”开始，不复原动作流或重放。

D1按已批准粗档显示，不把最低档称健康／安全；隐藏医疗Preview仍unknown。DOM、aria、title、data属性、错误文案和视觉排序都遵守同一边界。当前公开相对顺序不是完整未来Ghost；缺能力不能在组件模拟resolver。
