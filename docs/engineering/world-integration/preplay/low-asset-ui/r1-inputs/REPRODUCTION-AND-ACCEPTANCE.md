# 修前复现与验收定位

本文件是原生复现规格，不是声称已由主线执行的Vitest模板。包内源码隔离脚本使用明确React适配器，不能冒充原生DOM／浏览器。请先在真实仓库建立修前回归，再修改生产。

## R01／UI-01

用真实空档初配和S到达可搜索房间；通过实际React按钮的Hover／Focus或既有可访问说明入口，在不执行搜索的前提下查询完整无照明搜索的费用及公开机制，并与相同opaque请求的正式preview比较。对一个无需输入的调查动作作同类回归。当前版本没有该只读入口，预期修前在用户可见说明断言失败，而不是导入／fixture／超时。

保留正控：普通完整动作仍一次点击执行；参数不足只打开必要输入；取消不执行；合法移动既有费用保持；战斗说明不预测隐藏敌响应。别以“所有动作先确认”解决。

## R02／UI-02

真实Setup中，三工具／三专长说明能对应具体已批准能力与限制；对每条文案记录来源，不只是检查字符串不含“已批准”。初始化读取仍零身份生成／发物／写入。真实任务取得组件／模块后，地面／背包／菜单／参数／材料／title/aria的玩家名称一致；选择仍传递原opaque对象，禁止按显示名查找第一件。

## R03／UI-03

真实DOM取得一件非药食普通材料及一件任务模块。逐件右键／菜单键打开，验证没有以该实体为目标的“使用药食”。合法药食对象仍有操作，通用药食入口仍能另选合法来源；模块的移动／任务留置仍保留。原版本应在两项菜单断言上失败，不能写成正式生产者把模块当药消耗。

可选用原真实DOM路线达到模块，也可用明确标注的已审真实P/严格恢复TEST前态；两者不能混称从空档。旧选择、已消费、拆合、移动、冷恢复后重新打开菜单都不得复用旧绑定。隐藏消毒／抑制目标存在与否的成对状态保持相同菜单／说明。

## R04／V01

真实写成功→刷新→恢复后，玩家文案不把“本session未写”误写成“没有保存过”。保存失败仍醒目说明已提交但未保存；只重试保存不得新增dispatch/current/通知。仅改copy或现有可靠安全上下文，不增加IO。
