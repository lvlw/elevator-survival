## 2. 唯一映射

纯core安全owner读取正式已提交身体及版本绑定的配置`config.health.infection_damage`，选择当前进度所属段。四段按序对应“未达病程损耗档／低病程负担／中病程负担／高病程负担”。当前技术边界为0、60、90、120，来自已有配置，不另建可编辑阈值表，不修改运行时或文档试用参数。

UI只获得公开标签和必要的安全说明／样式分类，不获得进度、min边界、该段损血值、增长表或潜藏暴露总数。字符串key和最终DTO形状由后续基础工程在不改变语义的范围内确定，不在本任务注册schema或新版存档。

最低档不代表未感染、无暴露或未来安全；最高档不代表死亡。仅对合法完整当前值派生，非法配置／错版本不能默认成最低档。合法无current、被阻止加载等应用态不伪造角色或感染档。终局只展示保留的当前／历史公开事实，不模拟额外夜晚。

## 3. 医疗、未来后果与知识等价类

消毒剂／抑制剂隐藏目标Preview仍unknown，实际执行仍由正式S/P检查。公开日额与真实物耗可显示，但不能用目标enabled、动作列表长度、顺序、不同unknown文案或具体拒绝细节提前泄露隐藏目标。

同公开档且其他公开信息相同的输入必须全视图非干涉；应覆盖同档不同进度、潜藏暴露、抑制内部事实及相反尚未揭示随机结果。跨档只允许本次批准的公开区别；已明确执行后的真实结果可按原规则反馈。不得把所有差异抹平，或只比较删除选择／动作后的对象。

D1不是未来日结预测授权；当前粗档不能用于给出下一周期精确损血／必死答案。既有UIR-015要求的完整命令安全保护仍由正式公开安全事实承担；没有充分依据的分支保持unknown，不等于safe或not-guaranteed，不新增隐藏预测权限。

基础工程应按实际配置测试段内值、边界前后值、最高段以及非法原输入／错版本；不能只测四个标签常量。每一适用完整停点均使用唯一当前事实；query/preview零生产、零随机、零authority、零写入／通知和零revision。
