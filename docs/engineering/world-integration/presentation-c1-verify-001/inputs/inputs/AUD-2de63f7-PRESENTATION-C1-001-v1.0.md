## 2. 实现核对

### 2.1 A名称仍来自当前安全查询

BattleStage只使用当前 `view.combat.opponent.name`，三类名称及unknown沿用A；没有按地点或旧战斗补猜，没有向DOM暴露内部visualKey、精确敌HP或raw CTB。原五阶段含“失去能力”继续作为公开阶段，不改成胜利或死亡。人物仍为中性占位，没有采用新美术。

### 2.2 B1只在原直接返回路径消费

app保留原execute/confirm、singleFlight、必要参数与保护确认，只在两处原调用周围接入消费者；不由snapshot、Feed或血量差补造动作。不支持的操作、非combat入战、拒绝、取消和过期选择不产生新回执。同步订阅只做失效检查，不播放历史。

消费者是有界临时内存：一个scope引用、一个ordinal高水位、一个generation和一个当前cue。先消费再安排显示；skip/cancel不回退高水位，缺号不补播，结构相同但引用不同的scope不重置活消费者。不把已消费token集无界保留或写入存档。

### 2.3 正常提交、真正失权与旧回调分开

本次原命令中的正常busy→stable不被误判为离场；直接结果返回后仍核对当前owner/controls、稳定view引用和取消代。提交后失锁/销毁时，真实规则提交不回滚，但迟到反馈丢弃。旧timer检查当前session及timer句柄，旧订阅检查live及session身份，不能清掉重获控制后的新反馈。

动画不决定命中、资格、保存或终局。真实死亡/退却等先显示最新canonical view；短文字回执不是可执行的旧场次。保存失败保留“操作已生效、尚未保存”；retry及冷恢复无历史重放。程序异常保留可观察性，不伪装成成功并自动重发命令。

### 2.4 动态与布局

C1只增加180ms短文字位移/透明度反馈；OS媒体偏好与本地减少动态取OR，本地关闭不能覆盖OS开启。改变偏好落稳既有cue，改回普通动态不重播。对此已有自动React测试和主线端口隔离证据，但真实浏览器媒体true仍未验证。

自查发现的1366装饰占位遮挡，由允许的styles.css局部修正：舞台grid允许收缩、敌信息局部滚动及Feed高度调整。没有改整套布局、背包事实或动作所有权。布局DOM记录支持修正意图；完整像素覆盖仍按C16限度处理。

## 5. 开放项及判定

**C16-A：真实浏览器媒体偏好true，未验证。** 所有交付浏览器帧媒体值false；TEST matchMedia不替代浏览器媒体仿真。原合同允许浏览器媒体仿真，不必要求Owner更改系统设置。补验需分别证明页面matchMedia、真实样式及实际动作无动态。

**C16-B：完整代表视口，部分未验证。** 1366保存失败原图是全尺寸，但1920、1280与占用图尺寸不符；390只给滚动片段。DOM几何不能替代完整图像，JPEG不得拉伸/拼接冒充原生全页。

**C16-C：真实125%/150%缩放，NOT VERIFIED。** 原任务是能力允许时补测；这是独立能力/发布检查，不因做不到真实缩放就单独判源码失败，也不能用CSS viewport或transform冒充。

浏览器两次动作间隔约1015ms，超过180ms，不能作为动画窗内下一动作不锁定的实际浏览器证明；这点有确定性React测试，补验能力允许可补，不新增玩法门槛。旧快捷物品消耗后焦点落到原退却按钮及说明浮层，列为后续交互观察，未发现自动执行退却，也未判为C1新增阻断bug。

当前CI仍7项依赖告警（2moderate/5high）；完整公告、影响链及修复尚未结论。不自动audit fix，不改依赖/CI。19项既有资产元数据风险、高清/透明边缘、历史三份专项原件缺口、完整Owner首玩/分段九组合、O3发布与正式美术继续独立开放。
