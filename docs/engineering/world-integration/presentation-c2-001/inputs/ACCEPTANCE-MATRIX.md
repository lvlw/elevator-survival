## 明确运行的命令

从新任务工作树仓库根执行；先读取实际package确认未发生授权外变化。

```bash
# W0实际基线
npm run test:run

# W3新增模块及受限适配、现有UI/应用/会话原生组合与E03
# 本批所有新测试均应在下列前缀中被执行；可另跑精确文件做快速迭代。
npm run test:run -- src/ui/infected-world src/app/infected-preplay src/app/infected-browser src/state/residence-session src/content/infected-world-v0.1/acceptance

# W4最终默认检查（包括所有测试和构建）
npm run check

git diff --check 4f349d97024151ac79aa099425ce83217ef47b31...HEAD
```

上列base已固定。不预填新增数量或通过数量；历史337/4858只是校验参照。定向、组合和默认检查重复覆盖的用例不计多次新增。

## 必做语义负控（临时改本批新文件，随即还原）

1. 放宽成任意一图成功即可ready：T04/T05必须业务失败。
2. 去掉当前key同步匹配：跨组切换T07必须显示错误并检出。
3. 去掉有效代/取消保护：T08晚回调复活或误伤必须检出。
4. 篡改专用TEST资产副本摘要或阶段配对：T02必须因绑定不符失败；不破坏获批源图、不提交mutation。

负控日志保留错误断言与还原结果，不用语法/import失败冒充业务检出。不要求制造超范围玩法bug来跑负控。负控恢复后最终check再跑。

## 浏览器取证安排（只做本批必要范围）

先核验工具能力与准确任务URL。用本任务新回环origin；控制台或公开自动化工具仅用于允许的测试操作、观测，不覆盖游戏状态/API骗过验收。允许TEST-only生产者输出合法checkpoint、资源请求失败/延迟仿真，但不得把假的Image成功结果装进生产页作ready证据。用过的故障注入必须清除，原图说明正常/故障场景。

原UI自然read-null→至少一次真实入战/动作链作为接入口见证；另两敌允许复用现有生产者形成strict checkpoint。既有已覆盖长链可用自动回归，不要求Owner手走全部路线。

所有五个桌面尺寸读取实际viewport/DPR与元素几何；提供4—6张有代表性的原始截图即可：1920与1280完整正常图、1366实际动作/说明层或保存失败、其他敌人当前图、加载失败占位，能合并覆盖则合并取证。不要求五尺寸×三敌×五态的75张大包。如工具只能给部分像素，明确该项PARTIAL并保留几何观察，不缩放补边伪造。390压力档顺带观察；旧C16媒体true/zoom缺口保持，工具确实支持时可补，不能重复无效探测或更改OS设置。

图片低姿态/变stage属于静态renderer范围，不强行把不可达状态做成真实战斗截图。正常游戏截图不得挂脚点/命中锚或开发控制台；TEST诊断有使用时注明，不假称它来自正式UI。

当前组三敌原图合计13,907,305字节。组PNG约4.00/4.91/4.35MiB；原尺寸RGBA平面算术约25/30/30MiB，**不是浏览器内存实测值**。请报告实际可测的请求、加载时间和应用自持对象界限，不能因工具拿不到GPU数据便虚构测量或启动新性能框架。
