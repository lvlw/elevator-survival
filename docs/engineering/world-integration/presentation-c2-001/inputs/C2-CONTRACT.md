# C2定稿合同 v1.0｜三敌静态图DEV有限接入

执行身份：`ENG-WORLD-PRESENTATION-C2-001`。Owner采用授权见本包原话；本合同是此次主线工程定稿。旧草案仅作来源导航，以下局部澄清优先于其模糊实现描述；不覆盖已确认玩法、玩家知识或当前UIR。

## C2.1 唯一事实来源与有限采用

输入只取当前 `view.combat` 的公开 `opponent.kind / visualKey / name` 与 `enemyStage`。映射三组各五阶段：`healthy / wounded / severely-wounded / critical / incapacitated`。图片是这些事实的显示，不反向制造事实。不得读取实例ID、定义ID、精确敌HP、百分比、raw CTB/trace、seed、风险抽签、内部病程或旧/未来战斗。不得按地点、标签文字、Feed、前后HP或B1动作猜身份、阶段、命中或死亡。

采用范围仅 `APPROVED-ASSETS.json` 列出的15个准确PNG。展示名称及阶段仍由正式公开事实决定；unknown仍为原“当前对手”。失去能力不是死亡/胜利证明；真实 `combat=null` 必须清图，不能为了播放失能姿态留住已结束战斗。

不扩查询类型或存档，不改动作、选择器、请求、单writer、L0—L3、安全预览、支付和终局。不把UI资源epoch与selector scope或B1 scope混用。患者/医院旧规则不变。

## C2.2 固定表、原始字节与校验边界

生产只接受列明PNG的静态import和封闭注册常量，不接受任意URL、远程catalog、SVG脚本、旧prototype或用户自选资源。按自身属性/封闭枚举查询，非法键（包括constructor、toString、__proto__）不可命中原型。未知组/阶段不得默认成healthy或另一敌人。

源PNG原字节复制，注册几何与本包一致。源码中可只保存渲染必要字段；完整sourceCommit/hash/blob留在任务输入与测试oracle，不把来源路径、hash或注册调试数据渲染到DOM。

**构建/准入失败**：缺静态import源会使build失败；错摘要、错原生尺寸、注册不符、混组/缺阶段必须使必跑资产测试和 `npm run check` 失败。不得声称未经修改的单独 `npm run build` 已额外实现摘要检查，不改package/CI添加新pipeline。本地W0比对固定源对象，CI用已归档批准清单校验当前文件，不要求浅克隆含旧历史。

**运行期失败**：网络、图片load/decode或最终显示错误，才使当前组回退中性；它们不是玩法错误，也不能触发回滚、保存、全页fatal或再派发命令。不要捕获任意程序异常后一律伪装成资源失败；只处理已界定的资源失败分支。

## C2.3 整组加载、失败与有界占用

只有当前合法known组被显示时，启动该组五图的load/decode，不主动预取未遇到敌组，不从import表在模块顶层发请求。同组五图全部准备并校验实际native尺寸后才原子发布；任何一项失败，整组用中性占位。不存在隐式旧成员保留或跨组拼接。unknown/非法阶段没有有效渲染选择，不发图像请求。

五图加载等待与错误都不禁用、不隐藏原合法行动，不扩大singleFlight，也不延迟正式稳定状态、B1/C1回执或死亡/退却切换。名称和阶段始终可读，无断裂图标或大面积错误弹窗。

本批采用**10000ms固定组准备超时**，仅为呈现默认，不是玩法时间。超时从本组准备启动计，不因stage/重绘/保存重试重置；超时后失败终局、清理本组活动句柄，晚到success不能复活。没有自动重试循环、轮询或新增重试按钮；后续真正新挂载/新资源代可再尝试图片，但不得重发游戏命令。

组件自持资源以当前组为限，不维护所有曾见组的无界Map。每个有效准备代最多启动五个approved图解码；结束、换组或卸载后解除旧监听、timer、闭包及不再需要的对象引用，未启动任务不得继续排队。浏览器已开始而不可取消的请求/解码仅保证不回写，不能假称物理终止或GPU内存即时释放。浏览器自身HTTP/解码缓存与JS自持资源分开记账，不把传输PNG体积当真实内存。

同组stage变化、普通重绘、retrySave及B1反馈取消/减少动态不能重新发起五图准备或重置失败状态；正常busy→stable若未实际卸载不应造成资源抖动。宿主按既有规则确实卸载时则正常清理，不为保持贴图改动宿主生命周期。StrictMode重建按代隔离，不要求不可控网络“绝对只请求一次”。

使用已测环境的原生Image/load/decode路径；缺少必要能力时保守中性，不安装兼容依赖或修改浏览器全局。测试必须明确控制完成/失败/悬挂，而不是因为jsdom不自动加载就把永远占位算PASS。

## C2.4 同步归属检查与异步隔离

渲染当下必须同时满足：当前known键合法、当前stage合法、ready组的键与当前visualKey相同、资源属于当前有效挂载/代且整组可用。否则本帧中性。**不能只在useEffect中清旧state**，因为跨组props更新到effect执行之间也不得显示上一组。

所有load、decode、timeout和DOM onError都绑定实际资源代和应答对象。换组、失权引起卸载、`combat=null`、离开舞台及真正销毁后，旧回调不得恢复图层、清空新组、修改玩法或引出未处理Promise rejection。已替换stage的旧DOM错误回调不得误伤新stage；当前正在显示成员的真实错误应使有效组整体退回中性。

同组切阶段只选已准备组中的当前那张，不先显示旧stage再等待effect。不要伪造中间阶段、播放逐击动作或延迟终局。图片失败只影响图片；文本、controls、Feed、保存失败提示与原C1反馈仍由原owner管理。

## C2.5 几何、可读性与无障碍

使用同一1536×1920注册坐标（非原生分辨率），按原scale/translate/imageCss等价放置完整源图。源图保持长宽比，不逐态trim贴底、不重设脚点，不把负translate误认为可删的空白。变换数据见批准清单；`motionEnvelopeCss`、命中锚只作历史出处，**本批不启用它们的动作/FX**。不展示审阅十字、圆点或网格。

实际敌人容器4:5，以**可用宽与高共同约束**并保持脚点稳定；160×200/240×300只是旧审阅比例，不是生产固定尺寸。保留人物主体而不是靠overflow:hidden裁掉头脚制造通过。优先缩放装饰图层，不缩小必要文字、不挤掉原行动按钮，不改主Shell/Feed/HUD/弹层布局。

图片不是控件，不新增焦点/onclick、说明确认或遮挡；用不可截获操作的图层。成功态可使用只含公开名称/阶段的alt；若由同一role=img容器承担可访问名称，内层图置空alt以免重复播读。占位保留可理解名称及阶段。禁止私有值进入text/title/data-*/aria/隐藏DOM。静态构建资源URL及公开visualKey不是新增玩法身份，但不能借此输出整个内部对象。

玩家仍原中性占位。既有对手名称/阶段/公开意图/相对顺序、ActionButton请求与顺序、保存信息和B1/C1提示不改。尤其不借本批修旧动作列表焦点迁移或其他UI债务。

## C2.6 旧测试的精确适配

仅 `combat.test.tsx` 与 `current-opponent-presentation.test.tsx` 可做旧测试窄适配：增加专用测试fixture导入/生命周期清理、把known成功态从“中性且无img”改为“精确当前图且公开名称/阶段正确”，或将原用例明确设为加载中/失败并保留无图断言。**无论采用哪种写法，都必须有真实原controls链上的known-ready正向证据**，不能全部测试停在占位。

不移除原合法动作/序号/唯一提交/current次数/写入/随机/隐私/死亡/终局/无自动重启/冷恢复断言；unknown五态与不按地点猜测仍完整保留。不skip、放宽匹配到总是true、更新整份快照忽略差异，亦不借此更改旧通用fixture。需要的新工具仅新建本批fixture。

15槽static renderer检验与三敌原生可达stage检验分账。失能等不可达组合用明确TEST-only公开props验renderer，不建立HP0活动战斗、不修改伤害/阈值。原生流程使用真实生产者/strict codec，不能用注入假的view全局替代来源链。

必须实际运行原DEV入口的生产React代码，用真实A公开事实驱动图片；加载期间/失败仍可合法动作、ready当前stage、换stage、退却/死亡清图、读档无反馈重播和键盘路径均有代表证据。三敌至少各有真实活动场景和一次实际动作；15槽静态/renderer部分不冒充15种原生可达。
