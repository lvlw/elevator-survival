## 3. E03-A-F02：路线结束后的测试／程序异常可能被吞为正常结果

准确源码 `src/content/infected-world-v0.1/acceptance/e03-test-routes.ts:89-101`：

- 第95行只把TypeError、RangeError及非Error对象向外抛出。
- 第96行只要current已dead，就清除failure而不继续抛出其他Error。
- 第97行只要Error具有code属性，就可当作路线停止；没有证明它是已知游戏业务拒绝。

因此，“真实行动已使角色死亡”之后发生的普通Error／AssertionError可被掩盖成普通death；存活路径中的某些带code程序／环境错误也可被包装成route-stopped。真实死亡本身当然是允许的实验结局，但不能成为忽略测试自身失败的理由。

这是**源码选段隔离证据**，不是完整原生P/R/S或者72种子复跑。没有据此宣称作者已记录的63成功／9死亡含有假结果；也没有宣称每一个send中的断言都会被现有外层计数漏掉。具体风险是异常分类过宽。包内原生模板要求在真实seed05经真实S/CTB提交死亡后，再注入测试/程序错误，并在真实移动后注入未知code错误，检查它们确实向外传播；不清敌、不替换current、不覆写随机。

修复应显式区分：真实已提交终局、声明的路线条件缺失、限定的业务拒绝、测试/程序/基础设施失败。所有AssertionError及未知程序异常必须失败，不得仅靠phase=dead或任意code属性放行。合法失败止损、普通死亡、酒店无消毒剂停点、原四成功见证和72条默认样本继续成立；无需给所有死亡加异常。
