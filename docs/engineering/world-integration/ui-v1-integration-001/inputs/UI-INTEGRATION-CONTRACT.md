# UI v1.2真实接入定稿合同

## A. 目标来源与状态

来源固定在`c5abeda4861710325a123e8321a314423525f8df`下的`docs/design-drafts/ui-v1-001/`：R2/v1.2、Readiness有效修订、HTML/CSS母版与对应主稿。后文是本次主线工程约束，不冒充历史草案已经完成采用或新的玩法DEC。

复用的是视觉结构、组件样式、资源/裁切和交互意图。**禁止复制SCREENS、sampleItems、designWeight、flow-context、作者state/index作为运行状态或保存事实。禁止iframe嵌入原型假装已接入。** 当前地图、初配、病程、物品、任务、费用与结算必须来自实际安全接口。

## B. 屏幕和信息结构必须成套迁移

1. 五桌面档目标为1920×1080、1600×900、1440×900、1366×768、1280×720。按R2三栏主壳、HUD、中央场景与内容层、右携带、紧凑反馈组织，不保留旧大底部日志和支撑按钮条作为唯一运行布局。低于1280宽或720高按目标抽屉/局部滚动降级，390压力档测试另账。
2. 对尺寸优先核对**实际母版DOM及导出记录**，不能从概括文字拼出另一版。公开数据比示例长导致的必要自适应可在UI白名单内解决，并记录差异；不要把正文整体缩小、整屏transform缩放、裁掉按钮或强制低分辨率截图伪装一屏。
3. R2普通层按短内容/详情/摘要/参数/整理/地图分档（主稿约640/680/800/880/1000/1040宽，受中央可用宽限制），高度随内容；小提示就地锚定，不全部居中，保护确认才按既定流程。不能因这次“整体迁移”额外给每次普通动作加确认。
4. 在Hub、探索、战斗、终局和系统异常之间保留同一设计语言与真实上下文。帮助/放大/还原/Tab不能重新建Session或丢失初配、地点、未提交参数。
5. 主要操作与必要安全信息可达；内容局部滚动合理，不能靠滚动隐藏行动的已知必死/费用/物品来源。初选仍明确工具和专长、创建后不自动出发。

## C. 药房是必过阻断场景，不是可选漂亮截图

- 使用H2对应的现有药房背景；实际选择键只来自公开地点身份，不使用“所有医院统一大厅”兜底。
- 未搜索、已揭示有物、逐项拾取、已取空、收起重开都与正式来源/地面/背包一致。空状态以紧凑明确的已处理/当前无物表达，中央场景仍可见，不画假物品填空，也不恢复已耗来源。
- 普通拾取/数量/旋转/无位置处理继续由正式Preview与现有执行链完成；不把新版图像当作可点击自动领取权限。
- 右侧已存在并有R2图的物品不得继续统一显示相同缺图符号。真正unknown才用可区分的名称/占位；名称通过Hover/Focus/详情可访问，不能只依赖美术猜物品。
- 移动、原位休整、任务/药食入口按照当前合法action可达；不能从只读地图另建移动入口。

## D. 地图、身体、物品、任务和近景

- 三栏左区采用正式公开目标/已知地图，不把R2的NODES/示例路线全部显示。当前未揭示节点、NPC、路径和结果不因asset已入仓而出现。可在资料清单列完整定义，运行画面只用安全投影。
- 地图始终只读；Travel Cluster承载正式邻接移动，不做瞬移/自动路线。背景focal不改变可通行性。
- 19种物品同源映射贯穿地面、背包、快捷、装备、参数与详情。数量>1角标，真实资源/耐久只由公开view提供；跨格物体不按图形猜footprint。
- 右键与菜单键/Shift+F10保持既定对象操作；左键不被擅自改为原型的另一个物品菜单。参数绑定opaque selector和原对象，不以名字/索引重新找一个“差不多”的对象。
- NPC图只用于已有公开林岑/周衡内容，不增加话题/交易。样本谨慎/直接、护具正常/最后一点/破损/未装备的真实支付均来自正式Preview，不抄原型固定10/6/1数值。
- 医疗维护可美化与分组，但不改变额外确认已知欠账的规则语义，不自动选材料、补快捷栏、整理背包或合并堆栈。
- 近景仅在真实当前对象的说明/参数/结果里出现，不给每次行动加通用事务弹窗。

## E. 战斗与反馈：改善可见布局，不虚构事件

- 采用R2战斗的中央普通/最大态及主体空间分配，而不是保留小人物贴图再称迁移完成。实际人物、当前意图、阶段、原行动条、相对顺序与携带必须一起测量。
- 三敌五态仍由A公开key/stage选图；C2的整组ready/timeout/failure、当前组渲染检查及旧代回调隔离不改。允许CSS容器和组件外观适配，注册画布与15PNG原字节不改。
- 玩家v2继续延期；保留中性、非持特定装备的占位，不引入v1/v3，不让占位大到压过真正敌人。当前图仅表当前公开阶段；失能不等于死亡/胜利。
- B1/C1现有发起动作反馈保持一次性、可跳过、减少动态和不阻塞下一合法动作。**不制造敌人逐击、命中、伤害数字、连续CTB位置或结果重演。** 原型这些效果只作后续排除项，不得用血量差或Feed文本补猜。
- 非战斗且无在播反馈时，不再常驻空“跳过反馈”条。减少动态设置可在新版帮助/选项内访问；C1 hook须保持原controller生命周期，重排UI不能重置scope/high-water或复播旧token。终局/失权即时切换，不等动画决定规则。
- Feed继续来自唯一session-local owner，不另写第二日志、不持久化派生历史。新版可收纳/展开同源记录并优化展示；原序号与文本不能伪改为未有证据的“获得/命中/成功”。本批不修改feed生成或新增披露字段；通用重复文案不得占据主舞台。

## F. 资源准入和异步行为

- 本次非玩家DEV候选清单为46图；C2敌图15张沿用。最多按表复制/复用，不改源像素、alpha、色调、不伪造2×。9切边只通过受控CSS/React组件使用现有面板图；不加载TEST调色主题、作者脚本或注册SVG的任意代码。
- 新运行资源必须从src已打包路径解析，不依赖docs服务、磁盘绝对路径或外链。基线已有相同blob可复用，避免重复。
- 构建/测试准入校验Git登记后的准确PNG字节和原生尺寸，不能用“加载失败会回退”掩盖复制错源。19项旧catalog差异不倒改；本次新manifest以准确Git字节记账。
- 场景只加载当前公开场景和当前可见内容，不整包预解码全部背景/NPC/物品，不让图片、字体或主题准备阻塞动作/保存。按每类资源安全回退；未知/切换/失败时不留上一地点或上一对象的误导图片。
- 颜色与边框沿R2，可用正常CSS实现，不建立通用皮肤商城/任意主题脚本SDK。框架和依赖不换。

## G. 接缝与测试迁移

允许在app.tsx中重新组织props/JSX、打开/关闭本地展示层，复用现有事件回调；`guarded/execute/choose/confirm`的请求、确认、single-flight、error和取消逻辑不得另造或降级。正式方法只走原BrowserControls。

允许适配UI子树内部结构/aria查询/CSS类断言，前提是逐项记录“旧结构断言→新等价交互”。保留原玩法、提交数、存储数、隐私、stale、死态/终局断言。不得删除/skip整文件、把原生集成改成全mock、降低计数或让资源永远pending来过测。

核心/state/app其他模块冻结；出现确实需要修改协议的缺口，给最小证据并停止相关分支，不为页面好看新加玩法字段。其余UI工作正常继续。

## H. 视觉完成门槛与主线/Owner顺序

Codex必须自行用实际DEV React走主流程、检查页面，再交主线。每份主稿对照标明：原型目标、真实运行状态、来自正常操作还是合法TEST冷态、允许差异（玩家占位/B2未接等）。目标样例不能假称生产事实。

至少提交药房未搜/有物/取空、带19图代表的携带及详情/参数、三敌战斗、一个保护/失败状态的可检查原生证据；完整视口和截图固有像素对应。设计/实际并排可以派生，但原图必须原字节保留。没有原生画面，不能仅凭单测或静态稿标整体DONE。

本次Owner截图已经是明确的负面验收依据（references/OWNER-rejected-pharmacy.png），不是要求再让Owner证明旧壳不好用。收到报告后由主线先审真实新版图；在主线明确给出可试玩条件前，Owner试玩不安排。

C16系统reduce=true、真实zoom和390原缺口依当前工具能力重核：有受支持能力则测；没有则逐项NOT VERIFIED，禁止覆盖matchMedia/改CSS缩放冒充。不要再次在无能力接口上循环一整批。已知局限不掩盖、不扩写为全兼容，但不阻断已经可完成的新UI实装。
