主体可以采用分层、近似树状排版，但不能将实际通路删成一棵树：非父子连线、交叉连接、回访通路及有向信息按公开输入保留。它表达“地点之间怎样相连”，不表达真实建筑比例、物理距离或朝向。

## 已核实的接缝

准确基线中的 `src/ui/infected-world/components/knowledge-map.tsx` 当前将节点和路线渲染为文字列表。`PlayerReadyView.map` 已提供：

- nodes：`name / place / visited / current`。
- routes：`from / to / observation(current|last-observed) / passable(true|false|unknown)`。

`player-queries.ts` 当前将路线端点投影为 `place + ' / ' + name`；UI只以完整公开地点名称匹配节点，不以短房名、列表序号或私有ID重新猜测。匹配缺失或重名歧义时保留原公开路线文字，不补造节点或向核心取隐藏标识。

原型的SVG形状、视觉样式可以参考；不得照抄 `knownMap()` 内的样例地点数组、假坐标关系或由SCREENS推导的通行事实。资料中的全图只用于对照，运行图的成员和关系必须全部来自当前安全投影。

## 展示要求

1. **左栏小地图**：优先显示当前区域的已知地点，标明当前位置；已知跨区域连接显示准确目的地/区域出口。空间不足时用有界的当前邻域视窗并明确“局部示意”，提供“展开已知地图”，不能通过缩小整图使标签难读。过滤仅改变视窗，不宣称视窗外无路。
2. **展开图**：在原R2地图内容层展示全部已知关系，必要时按已知区域分组或局部滚动；小图和展开图复用同一安全输入及图模型。不可把未来五个区域固定排好、提前列出未知区域或为未知节点预留可识别的占位。
3. **节点**：明确区分“当前”“已到达”“已知未到达”；使用标记/文字，不仅靠颜色。没有已知节点时显示真实空状态，不补默认医院图。
4. **路线**：区分已知可通行、已知受阻、通行未知；`last-observed`须保留“上次观察”标识，不能伪装成实时状态。通路可通行不等于当前可执行移动，战斗、精力、死亡等资格仍仅由正式行动决定。
5. **方向**：`from/to`有向信息不得被无向线吞掉。两条反向路线只有确实均已公开且状态相容时，才可共用双向线；状态/观察时间类别不同则在图或只读详情分别表达，不推导反向通行。
6. **只读交互**：允许展开、关闭、选中/聚焦查看已公开地点或路线详情。点击节点不移动、不自动寻路、不生成多步命令。当前合法移动仍只有原Travel Cluster执行入口。查看地图不消费精力、不派发规则命令、不保存、不刷新知识。
7. **实现**：优先React内联SVG＋现有CSS，排版为有界、确定性的展示逻辑，不引第三方图库、Canvas/WebGL、力导向动画或通用地图框架。图的位置不得由隐藏全图、seed、真实HP或未来路线决定。避免普通重绘让节点无意义跳动。
8. **无障碍**：保留可读取的地点/路线文本等价表示（可折叠详情，不须再把两份长表常驻占满左栏）；键盘可展开/关闭/查看，焦点合理返回，不陷入装饰图形。
