## 1. 调整依据与结论

Owner提出：游戏性稳定之前，不应花太多时间处理不同浏览器分辨率的适配，要求后续暂缓这一块开发。主线评估同意收窄**跨视口适配、兼容扩张和重复取证**，但不暂停新版UI真实接入，也不免除主视口的基本可用性和规则/保存验证。

本补充仅改变本期优先级与验收视口范围，不新增玩法DEC，不追认其他未批准素材，不改变发布兼容承诺。此前的五桌面档设计保留为参考目标，暂不要求本轮全部实现、精修并取得像素级证据。

## 2. 唯一主视口

在原任务当前进度上锁定**一个桌面CSS视口**作为本批主验收环境，记录宽、高、DPR和实际浏览器；不能以图片文件尺寸或显示器物理分辨率代替CSS视口。

优先使用已获准观察并已记录的Owner实际游戏窗口；没有可靠记录时，沿用本轮已经主要开发且能正常取证的一个桌面档作为暂定主视口。不要为选视口再开调查、遍历五档，或要求Owner修改系统/浏览器设置。选择后保持固定，不在各页面之间挑选不同尺寸规避缺陷。

不为本补充自动接管Owner日常浏览器、读取其他标签或操作其现有存档。当前工作区、HEAD和已完成进度由Codex实查；主线没有直接读取用户磁盘。

## 3. 现在继续做

- 完成原M1—M3整套新版UI：主壳、场景、药房搜索/拾取/取空/重开、真实携带、信息/参数/保护层、战斗、终局和异常。
- 在同一主视口核对上述真实React画面，保持既有R2设计语言和主要信息架构；不能退回旧壳贴图或另交静态原型。
- 主视口必须文字可读、主动作和费用/关键警告可见、确认/取消可达、地图标签可理解、人物不被信息层挡住。必要的长内容局部滚动、动态数据/长名称/多条结果处理属于基本UI可用性，不能借“暂停适配”跳过。
- 键盘焦点、对象绑定、只读零提交、L0—L3、保存失败/只保存重试、冷恢复、死亡、失权、隐私及已有减少动态逻辑保持。
- 原小地图继续按安全投影完成节点/连线，图规模增加时仍可阅读并提供完整已知关系的可达查看方式；不要求多分辨率精修。
- 原定向回归、E03、负控还原后的默认check和准确SHA CI继续执行。已有W0基线不因本补充重复建立，最终真实检查不取消。

## 4. 暂停新增工作

- 其余桌面分辨率的逐档排版精修、等比例和像素对齐调试。
- 390窄屏、手机/平板专用布局及为这些尺寸新建的抽屉/断点优化。
- 125%/150%真实浏览器缩放、DPR2/多显示器/额外浏览器组合的专项适配与取证。
- 为同一页面或每次小改反复拍摄五档全套截图，或反复调试已知不支持的截图通道。
- 为达到其他暂缓视口的几何一致性而重构正常的主视口布局。

现有正常的响应式CSS、降级行为和测试保留，不倒拆、不回滚已完成成果，也不删除/skip既有语义断言来制造全绿。如果正常操作已经发现主视口的真实阻断，必须修复；如果只是暂缓视口的独立问题，准确登记其范围，不为此反复扩大本批。

减少动态逻辑本身不是分辨率适配，不删除或放宽。原C16媒体能力缺口仍按原记录保留，不因本补充标记完成。
