## 1. 方案范围

只针对当前医院—物流—通信这一固定局势、有限物资来源的候选完整世界，建立明确声明的跨日事实。

建议采用：**新一天开始新的探索，但不撤销同一 Run 中已经完成的世界改变。**

不把整个 Scene、Combat 或地图知识原封不动续到明天；也不把同一地点每天重建为未被探索的新副本。

本版不加入敌人迁徙、再占据、补货、物资配送、尸体搜索、离线战斗、背景再生、动态闭门或天气变化。这些不是永久禁止，而是需要未来明确内容契约与再次核算。

## 3. 三种重新进入

**刷新、关闭再恢复。**恢复同一次已保存探索，不重置剩余时间、当前节点、战斗CTB、意图、背包或随机进度。

**同一次探索内离开节点再回来。**保持该Scene事实；战斗逃跑后的重入按遭遇契约重新锚定，不能重抽搜索或重置敌人生命。

**正常日结算后，在后一天再选同一地点。**获得当天新探索的预算与入口位置，使用新Scene实例；从本Run明确持续的地点事实接续。它仍然占用当天唯一主要场景机会。

新 Run 不继承以上地点、来源、敌人或权限事实。Profile已安全提取收藏仍按原规则处理。

## 4. 明确持续的世界成果

### 4.1 已解除危险

本固定局势中，医院感染护工、物流感染搬运工、通信感染检修员一旦在正式战斗中失去能力，该敌人不在后续日期自动复活；其造成的相应阻挡保持解除。

“该敌人已解除”不是“整个地点永久安全”：未处理的其他障碍、原有环境风险、时间、负重与返程成本继续存在。

胜利不自动送物资。后续搜索、实际拾取与搬运仍支付各自成本。同一已解除敌人不再提供第二次战斗奖励或材料来源。

### 4.2 已处理障碍与设施

明确持续：医院已打开的防火门、物流已解除的物资柜卡件和运输固定卡件、通信已解除的设备通道卡件，以及已完成的匹配/核查所产生的实际结果。

不重复支付同一不可逆处理成本，不因换一种工具再处理而额外产出材料。门被工具箱打开后产生的电子元件，与首次事件结果同一次兑现；未拾取不重新产生。

**不能把物理解除和当前资格条件混同。**医院工作人员通道仍每次检查当前背包中的真实门禁卡。昨天持卡通过不等于永久开门；卡留在中枢不能凭过去记录继续通行。防火门已经真正开启则是不同事实。

不新增通用“修复任何设施”能力，也不让单个障碍结果自动打开所有相关区域。

## 5. 未击败敌人：保留伤害与下一意图，重建接战时间轴

### 5.1 建议保留

同一个Run内同一个具名遭遇的敌人，保留实际剩余生命、尚待执行的已选定意图、实际循环进度，以及已经消费的随机风险序列位置。

本稿三个简单敌人不在玩家离开时暗中回血、受到额外伤害、演算下一套攻击循环、复活或迁移。未来若有能跨遭遇持续的敌人效果，必须显式定义其持续语义；不能把玩家流血等规则套给敌人。

保留意图表达的是下一次应执行的行为，不表示视觉上保持同一挥击姿势一整天。

### 5.2 不保留战斗临时量

战斗结束后不把旧CTB绝对时间、临时延后、玩家防御或逃跑准备带到下一场战斗。这与刷新恢复未结束战斗不同；刷新应精确恢复正在进行的战斗。

### 5.3 本版再接战候选标尺

| 敌人 | 在本Run内从未交战 | 曾进入战斗且仍存活，再接战 |
|---|---|---|
| 医院护工 | 按既有未警觉70/当次警觉50，开场抓挠 | 玩家0、敌人50；保留下一意图 |
| 物流搬运工 | 玩家0、敌人150，开场重砸 | 玩家0、敌人50；保留下一意图 |
| 通信检修员 | 玩家0、敌人60，开场工具挥击 | 玩家0、敌人50；保留下一意图 |

“再接战50”是本稿明确提出的候选值，不是原DEC已经确认跨日这么做，也不是对所有未来敌人通用的永久公式。

只来过地点、没有进入该敌人战斗，不算曾交战。首次进入战斗后即使立即逃跑、没有伤到敌人，也已建立这段遭遇。

医院场景警觉仍按当次探索处理，不把昨天的Scene警觉标签默认复制到新Scene；已交战敌人的再接战50不再叠加提前。两名新敌人本版没有额外噪声警觉变体。

金属管签名行动仍按每次探索最多一次；同次逃跑重入不刷新额度。合法进入新一天的新探索，按该探索的原定规则生成额度，不能通过刷新获得。

### 5.4 必须接受的策略后果

允许把同一敌人的突破分成多日：此前实际伤害保留，玩家付出日期、往返、食物、医疗与维护机会后再来收尾。

这不是保证撤退后每个维度都变好。再接战可能以先前未执行的危险意图开场，原先的首访动作不能照搬。不得为了防分段突破而私自把敌人补满，也不得让每次重入不断增加伤害。

## 6. 物资来源：尚未使用不消失，已经兑现不重发

### 6.1 来源机会与已产生物品分开

| 实际状态 | 同Run后续日期建议处理 |
|---|---|
| 来源尚未被搜索/开启到揭示内容的提交点 | 保留该一次性来源机会与既定内容，不因改日期重新抽取 |
| 只解除柜门卡件，尚未执行单独的主要搜索 | 卡件保持解除，来源仍未兑现；下次仍支付搜索成本 |
| 已完成搜索/独立互动，物品已揭示 | 来源已经兑现；不会因只拿了一部分而再生成一整包 |
| 已揭示但未带回、或主动放下的普通物品 | 同次探索可返回取；探索结束遗失，不形成跨日地面仓库 |
| 已安全带回的普通物品 | 在真实Run容器中保留数量与ItemState，不复制到地点库存 |

示例：物流前区解除卡件20、主要搜索30为两个行动。第一天只解卡件就撤，第二天还可以搜；通信维修柜20的动作本身就揭示材料，完成即兑现，不能称“尚未搜索”再领。

开柜/搜索的取消或规则拒绝不兑现来源；正式动作已经提交，即使随后越零返程来不及拾取，该来源也不能回到未使用。

### 6.2 特殊实体

样本箱、控制组件和启动模块等任务对象在原装置中尚未执行实际提取时，保留候选提取机会；单纯观察或核验信息不等于提取。

一旦提取动作产生实际可携带任务实体，原来源就不能再次生成。安全返回后对象在任务储存区；实际取出又留在结束探索中则按正式任务物遗失处理。丢弃、未安全返程不能克隆另一份。

权限物品的新增补充建议：已揭示后留在结束探索中的门禁卡同样不作为跨日寄存；安全带回则存于真实Run库存，今后要使用须实际携带。它的遗失不自动宣告主线失败，仍要检查撬门、撞门等真实替代路线。

收藏品继续只以安全提取兑现Profile记录。上述新契约不改变任何跨Run继承。

### 6.3 确定不可完成时

原位未提取机会尚存，不属于已经永久丢失。只有真正发生不可逆资源/任务事实变化并确实没有合法替代时，才按正式无隐性死档要求明确失败；不能把“不符合当前推荐路线”当作无解。

安装材料没有自动保留、替代来源没有自动补发。来源耗尽的结果须能通过玩家已确认的来源记录与行动提示解释；不能展示尚未发现的秘密来源来假装保证可达。

## 7. 一次性来源与敌人风险的确定性

本固定局势的一次性储备，在逻辑上由本Run、规则版本、稳定地点身份和具体来源身份确定；允许延迟物化，但不要以首次访问日期或新Scene实例身份重新抽出同一批库存。

因此未用医院药房第2日搜或第5日搜，在没有明确世界变化时，是同一批既定医疗品，不是两次抽奖。只检查是否使用过并不足够：若内容仍随访问日变化，依然会出现择日改变同一库存结果的问题。

这局部改变DEC-032对医院一日搜索使用Scene实例的随机锚点，仅在未来新完整世界版本中采用；原医院一日的派生方式、已绑定版本和存档不静默迁移。

敌人风险序列跟随同一个持续敌人：已执行风险检查不回退，重入不会重抽已提交攻击。后来真正执行的下一次攻击是新事件，使用后续位置；不是让每次撕咬永远绑定同一个结果。

不同敌人、物资来源与事件继续使用隔离子流。查询、预览、刷新或访问别处不消费这条敌人的风险进度。此处规定可观察语义，不规定具体哈希函数、游标类型或文件名。

## 8. 玩家知识与新探索预算

新一天重访从入口与该次时间预算开始，不继承昨日剩余时间或原位置；不能重开同一天的已结束Scene。初始200仅沿用当前候选标尺，不成为所有场景永久统一值。

Run情报保留已经正式取得的事实，例如物流定位与组件接口；已有同一事实时不要求付费重新读一遍日志。尚未完成的实体核验/操作仍需要真实执行。

DEC-045的地图知识不默认跨日保持不变。新Scene仍按入口与逐点表层观察发现路线；持有Run情报不直接获得整张图，也不让隐藏物理捷径参与返程。

建议在地点选择与情报记录中表达玩家实际确认过的结果：“上次已解除作业区危险”“维修柜已取用”“备用料架上次未开启”“敌人最后公开意图为撕咬”。这些记录不是对未知地点的远程全知。当前交战前仍按正式可见边界展示其本次意图与相对行动顺序。

永久清除危险不等于免费抵达料架：仍需从入口走到作业区，观察其显式导视，发现并走完相应边。

## 11. 敌人分段突破的额外核查

另核算一个两段战斗示例，而不是整条多日路线：通信第一次以9生命执行基础、防御、蓄力、逃跑，440完成脱离，玩家6生命、敌人6生命，敌人下一意图为工具挥击。

假设合法进入新的探索，玩家仍有可用3耐久金属管和该探索尚未使用的蓄力额度；同一个敌人继续6生命，再接战50。玩家0时使用蓄力可直接令其失能；实际CTB0，仍按已有最低战斗时间收费10，不是0场景成本。

本例不计算两天完整移动、进食和修理，也不假定这些免费完成。它只说明保留敌人伤害确实会允许跨日分段突破，这一策略后果需要一并接受或明确另议，不能在实现时私自补满敌人生命。

## 12. 所有权与保存的最低约束

本节是概念约束，不指定完整RunState、WorldState、类型、文件或API。

- 同一地点可以对应不同日期的多个Scene探索实例；同一个敌人/一次性来源不是每天重新创建的一份奖励对象。
- 明确持续的事实在任意稳定时点只有一个可变权威所有者。活动Scene与Run持续层不能各自保留一份可分别修改的敌人生命、掉落或完成状态；采用何种投影/交接由后续实现契约明确。
- 物理物品跨Scene、背包、快捷栏、仓库时沿用真实实例、数量和ItemState；来源“已兑现”不等于在地点保存第二份库存。
- 一次已提交行动的消耗、敌人变化、障碍/来源结果和当前phase须处于同一个一致状态。不能只在结束本日才第一次记住白天已经击败敌人或产生任务物。
- Return Ledger继续只记录正式返回；不能用它代替全部世界事实，也不允许Launch伪造返回。
- 保存恢复应拒绝当前版本不可能出现的矛盾，例如敌人已解除却仍有可战斗副本、已兑现来源再次生成物品、同一实体跨容器重复、必须具备的持续状态缺失。不能通过自动补全、重新抽取或回血修复。
- 历史Scene/终止摘要是只读记录，不是可以重新运行的一份当前库存。

## 13. 需要接受的整体取舍

本方案会让已清理地点的后续取货更容易，使前一天的投入真正改善后一天。未用一次性来源仍需取得，但不会刷新，所以不是无限补给。

会允许消耗日期分段击败敌人；再接战仍有移动、危险意图和当前状态约束。没有保证撤退后敌人处于较容易开场。

已清理地点的短探索仍可消耗一天并使用已有食物恢复，不新增最低战斗/搜索门槛。日期、食物、日级危险和最终期限承担相应成本。

当前固定世界没有证明任意长Run经济，不能将有限一次性库存在七日可用宣传为已满足三十日循环。DEC-036长期基础维护底线仍需独立验证。
