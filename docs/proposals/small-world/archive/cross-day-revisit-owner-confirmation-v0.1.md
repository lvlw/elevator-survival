## 2. 当前接受的契约范围

适用于当前医院—物流—通信的第一版固定局势，不自动扩展到所有未来任务世界。

| 主题 | 当前设计基线 |
|---|---|
| 已解除危险 | 列名敌人正式失去能力后，同 Run 不自动复活或补替身；对应危险阻挡保持解除，不等于整个地点永久安全。 |
| 未击败敌人 | 保留实际剩余生命、已选定下一意图、行为进度与已消费风险序列位置；不自动回血、离线攻击、额外掉血或迁移。 |
| 再接战时序 | 对本稿列出的三个敌人，再接战为玩家0、敌人50，保留下一意图；清除已结束战斗的绝对CTB、临时延后、防御和逃跑准备。同次探索重入不刷新每次探索的蓄力额度。 |
| 已完成障碍 | 明确的物理解除结果持续，不重复收费或重复产出材料；实时实体权限仍须检查当前实际携带的凭证。 |
| 一次性来源 | 尚未兑现的机会保留；完成揭示即兑现，不因部分拾取、换日或重访重发。已揭示遗留普通物品不成为跨日地面仓库。 |
| 特殊实体 | 原装置中尚未提取的任务机会可保留；已取出遗留的任务物继续按遗失处理。已揭示遗留权限实体不跨日寄存，安全带回的仍须以后实际携带使用。 |
| 随机连续性 | 一次性储备绑定同 Run 的规则版本、地点与来源，不由首次访问日期重抽；敌人风险跟随持续敌人，已执行检查不回退，不与其他来源共享可变子流。 |
| 新探索与知识 | 合法新日重访使用新 Scene、入口与本次预算；不继承昨日剩余时间。Run 情报保留，当前地图知识仍按明确发现规则产生，不默认跨日全亮。 |
| 所有权与存档 | 同一持续事实只有一份可变权威状态；物品转移保留真实实例、数量和 ItemState，不以来源记录复制库存。刷新恢复同一次活动探索，不等于创建新探索。 |

医院既有首访参数继续按正式规则处理。两名新敌人的首访150／60、生命、伤害、风险与场景具体成本仍是候选内容；本次接受再接战50，不把它们一并升级为已确认数值。

旧医院一日的绑定版本、随机派生和活动存档不静默迁移。正式 DEC 的局部覆盖与扩展仍需准确落文。

## 3. 分段突破的准确状态

**当前允许，体验待试玩复审。**

本轮接受保留敌人伤害所带来的策略：玩家可以付出日期、往返、真实医疗与整备成本，在后续日期继续处理同一敌人。

该接受不是“体验已经通过”，也不是“以后不得修改”。在新的明确决定之前，后续设计和工程规格应按这条基线推进，不自行增加敌人回血、撤退伤害税、分段次数限制或额外评级惩罚。

本轮没有认定任何敌人都需要分段击败，也没有承诺分段一定优于或劣于一次完成。发现实际不适后，先定位问题，再讨论必要的规则或内容修改。

## 4. 分段突破试玩复审项（验证安排，不是新增玩法）

| 对照情境 | 重点观察 |
|---|---|
| 准备充分，一次完成 | 是否具有完整的战斗节奏与合理成本，而不是被设计成明显吃亏的选择。 |
| 遭遇不利，合理撤退后再来 | 前次投入是否被感知为保留的成果；重返时的不同意图是否能看懂，是否仍有值得执行的新计划。 |
| 本可继续，却主动分段 | 是否利用每次探索蓄力额度、新日维护和恢复，形成明显压倒其他选择的固定打法；比较必须计入日期、物资和放弃的其他访问。 |
| 连续多次分段 | 是否主要变成重复进出、赶路、开界面，而不是新的判断；是否破坏紧张感或造成机械消磨体验。 |

需要特别区分三个问题：规则是否正确执行、玩家是否理解已保留的意图和再接战顺序、玩家是否觉得这种策略值得玩。前两者通过，不自动表示第三者通过。

首轮体验观察使用正常玩家界面，不把敌人精确生命、raw CTB、完整未来循环或核算脚本作为玩家默认知识。定向对照可在之后进行，并与自由试玩分开记录。

记录日期、真实物资和工时消耗、最低生命、公开伤势/暴露、敌人公开生命阶段、重复访问与重复操作，以及 Owner 的具体感受。不预先编造数值通过线、通关率或“只许撤退几次”的规则。

若出现问题，先区分：信息提示不足、战斗时序或数值问题、日期/资源预算问题、重复操作负担，还是“保留伤害”的生命周期本身不合适。改变敌人恢复、意图保留、再接战或撤退语义，仍须重新讨论确认，不能当作普通修复隐式处理。
