## 1. 本轮结论

候选敌人能够在已有玩家行动与 CTB 语义下，产生“防御路线40场景时间、直接损血3、武器磨损4、外套磨损1”的具体结果。但同一遭遇并非固定收费：连续基础攻击可以30时间结束，损血5并可能挫伤；医院式控制路线在本候选上不占优；初次立即逃跑可以10时间无伤脱离。

同时，v0.2 未完整核算的一条合法路线成立：现场核查 → 防御战斗 → 先搜索并拾取补给 → 最后提取组件至0时间 → 强制返程。正常负重、无流血和挫伤时，债务0、真实返程20，因此只损失1生命。不能继续把“未提前通信调查”解释为“必须放弃补给”。

新的比较应当是：准备换取安全余量；现场核查者可以少搜、准备更多医疗、或显式以生命承担强制返程。并不要求所有选项在同一状态下同样划算。

## 2. 正式语义、候选数据与计算的区分

正式语义来源：

- DEC-025：单敌人、无站位 CTB，当前意图、基础/签名/防御/快捷医疗/逃跑。
- DEC-031：行动即时生效，再推迟下次行动；金属管基础4/100/耐久1；蓄力6/180/耐久3、基础延后140、匹配弱点追加60；防御80，外套后剩余直接伤害减半并向上取整，持续至下次玩家行动机会且最多处理一次攻击；绷带80、恢复1、止血处理伤口；普通逃跑80；战斗持续量到场景时间公式。
- DEC-035：同点完成事件、玩家、敌人顺序；行动后流血与死亡优先；真实债务和返程成本；到入口且无债务/返程时0损耗。
- DEC-036/037：至少1耐久允许最后一次破损支付；0耐久时临时攻击2/140；临时攻击资格只取决于武器槽；每天3工时、金属1产生5机械维修量。
- DEC-033/034：饱食、恢复、轻度挫伤和开放伤口的既有生命周期；不新增重伤、击倒或感染治疗。

本稿借用上述玩家参数检验新候选内容，不宣称这些医院测试数值已成为所有世界的最终平衡。

v0.2的200场景时间、双向边10、运输卡件20/撬棍1、核验10、提取20、主要搜索30、现场核查40、物资数量与手工卡件40方案仍全部是候选。

## 3. 遭遇内容：感染搬运工（工作名）

### 3.1 定位

单体感染者，仍使用搬运工具。慢而明显的第一记重砸，之后才有较快横扫。以直接伤害和伤势压迫为主，不因“感染者”标签自动产生暴露。

医院护工的典型问题是阻止后续扑咬；本候选的问题是能否对第一记重击正确安排防御，以及愿意为快10场景时间承受多少损耗。不增加免控、减伤阶段、架势条、站位或伤害反弹。

### 3.2 候选内部参数

| 参数 | 候选 |
|---|---:|
| 敌人生命上限 | 16 |
| 初次玩家时间 | 0 |
| 初次敌人时间 | 150 |
| 首次公开意图 | 重砸 |
| 重砸原始直接伤害 | 6 |
| 重砸完成后至其下一行动 | 240 CTB |
| 重砸原始伤势风险 | 高60%，成功产生轻度挫伤，不流血 |
| 回钩横扫原始直接伤害 | 3 |
| 横扫完成后至其下一行动 | 100 CTB |
| 横扫原始伤势风险 | 高60%，成功产生轻度撕裂伤与流血 |
| 两招感染暴露 | 无 |
| 行为 | 重砸、横扫交替；无第三招 |
| 钝击控制弱点 | 无；不等于免疫控制，蓄力仍延后140 |
| 战斗胜利收益 | 解除当前作业区危险，不自动发物品 |

内部生命阶段暂作13–16完好、9–12受伤、5–8重伤、1–4濒危、0失能。也是候选分段，不从医院14生命直接复用阈值。普通界面只显示相对阶段、当前意图、相对时序和风险方向，不公开这里的精确参数或完整未来循环。

本轮初次遭遇不额外发明物流警觉变体、环境随机伤害或额外武器磨损。未来需要这些内容时必须显式设计。

### 3.3 地点边界

沿v0.2：入口—大厅；大厅分别通往前区、记录室、作业区；作业区后接维修料架。前区及现场记录室不要求先击败搬运工。

在作业区入口的表层提示中，表达可见重物撞击、工具和敌人当前动作；首次进入危险仍存在的作业区触发遭遇。胜利后才可稳定核验、解卡件、提取或搜索。逃跑返回大厅，不清除敌人，不取得作业区物资。

同次探索的重入可优先沿既有模板设计：保留敌人生命/公开意图/循环，清除绝对CTB和临时延后，重入玩家0、敌人50。本条仅是候选，本文数值证明不依赖重入。跨日敌人、危险解除、来源耗尽及导航知识边界继续未冻结。

## 4. 参照防御战斗：从行动得到40/3

输入：生命6，武器6，外套4，快捷绷带1；无流血、伤势、暴露，正常负重。蓄力本次探索未使用。

| CTB | 行动 | 结果 |
|---:|---|---|
| 0 | 基础攻击 | 敌人16→12；玩家下次100 |
| 100 | 防御 | 防御有效至玩家下次180 |
| 150 | 敌人重砸 | 外套6→5，防御ceil(5/2)=3；生命6→3；外套4→3；伤势高降2级再降1级=无 |
| 180 | 基础攻击 | 敌人12→8 |
| 280 | 基础攻击 | 敌人8→4 |
| 380 | 基础攻击 | 敌人4→0，战斗结束 |

敌人首次重砸后，下一次横扫应在150+240=390，故380时的胜利先于横扫。实际结束380CTB，场景时间40；不把最后一次攻击的后摇加到480。

结果：损血3、武器消耗4、外套消耗1、无新伤势/暴露，不用绷带。此无伤势结论是该防御与有效外套下风险降至0，不是只挑选了幸运种子。

## 5. 替代行动与失败分支

均从同一输入开始，除明确改动外。

| 用例 | 行动 | 结束CTB/场景时间 | 结果 |
|---|---|---|---|
| 防御完成 | 基础、防御、基础、基础、基础 | 380/40 | 生命3，武器2，外套3，无伤势 |
| 连续基础，无挫伤分支 | 基础×4 | 300/30 | 生命1，武器2，外套3 |
| 连续基础，挫伤分支 | 基础×4 | 300/30 | 同上，并有轻度挫伤 |
| 套用医院式控制 | 基础、蓄力、基础、基础 | 380/40 | 生命1，武器0，外套3；重砸移至290但没有被取消 |
| 战中插入回血，无横扫伤势 | 基础、防御、基础、绷带、基础、基础 | 460/50 | 生命2，武器2，外套2，绷带0 |
| 上述横扫造成伤口 | 同上 | 460/50 | 生命1且流血，快捷绷带已用；不能把下一次普通正时间行动视为安全 |
| 初次立即逃跑 | 逃跑 | 80/10 | 生命6，装备不损；返回大厅，敌人未解除 |
| 起始武器仅3 | 基础、基础、蓄力、临时攻击 | 380/40 | 生命1，无伤势分支；武器实际消耗3至0 |
| 起始生命仅3，照搬防御路线 | 基础、防御… | 150/20 | 防住仍损血3，死亡，后续不执行 |
| 起始生命4，防御路线 | 基础、防御、基础、基础、基础 | 380/40 | 生命1，存活 |

连续基础：首次150重砸，在外套下直接伤害5，伤势剩低20%为挫伤。它比防御快10场景时间，不是毫无用途；是否值得需要结合剩余时间与生命。无外套时风险另算。

蓄力：本敌人没有钝击控制弱点，不能照搬对护工的200延后；140使首次重砸从150到290。三次攻击合计14伤害，不足以击败16生命目标；还需第四次，期间重砸发生。不得为扶持新敌人而偷偷削弱金属管，也不得为挽救某条路线而赠送弱点。

低耐久：3→2→1，然后蓄力合法破损支付到0，累计14伤害；380时临时攻击再补2。实际武器消耗3不是5，不创建负耐久债务。但它承受重砸5，不是舒适的标准续航路线。

战中绷带：防御线原来380结束；在280插入绷带后到460结束，390的横扫成为真实额外攻击。无伤势时6−3+1−2=2；横扫伤势触发时460末次攻击后流血再−1。不能用“加80CTB、加1生命”替代重算整条事件队列。

若只是预先回血，可在中枢或战斗前合法使用绷带；前者不耗场景时间、后者耗10，都消费真实绷带。本文并未禁止玩家用药。止痛药不直接回血，亦不能预防性无伤使用；急救包不能在战斗中使用。

## 6. 初次撤退不是先挨打的固定罚款

本候选首次敌人150，普通逃跑完成80，因此直接逃跑先完成，不自动受一次重砸。把敌人当前公开意图识别为不值得打，及时离开，本身有价值。

有提前信息时，进入作业区之前已花20移动，逃跑10返回大厅，再10到入口，总40。本次现场核查后才进作业区，则开战前80，逃跑10，再返入口10，总100。没有主线物，也没有额外奖励；现场已合法记录的情报可保留。

这只证明首次、正常负重、无伤势输入的逃跑；不把它扩张为任何重入或任何负重都无伤。

## 7. 替换v0.2路线预算

维持v0.2的非战斗成本：已调查仅任务90、已调查任务和补给120；现场核查仅任务150、现场核查任务和补给180。

| 路线 | 防御战斗40 | 连续基础30（无挫伤） |
|---|---:|---:|
| 已调查，只取组件 | 130 | 120 |
| 已调查，组件和补给 | 160 | 150 |
| 现场核查，只取组件 | 190 | 180 |
| 现场核查，组件和补给 | 220 | 210 |

这些总额是若能付清全部普通行动的规划账，不是禁止命令，也不是强制返程直接伤害值。

挫伤若在战斗中产生，之前已走过的路不追溯涨价；后续每条基础10边才变11。时间变化不作用于核验、解卡件、搜索和提取。

## 8. 关键反例：220路线只需1点强制返程损失

从生命6、无伤势、正常负重出发，采用防御战斗。

| 步骤 | 消耗 | 剩余时间 |
|---|---:|---:|
| 入口→大厅→记录室 | 20 | 180 |
| 核查记录 | 40 | 140 |
| 记录室→大厅→作业区 | 20 | 120 |
| 防御战斗 | 40 | 80 |
| 核验接口 | 10 | 70 |
| 解卡件 | 20 | 50 |
| 搜索作业区补给 | 30 | 20 |
| 显式拾取已揭示补给 | 0 | 20 |
| 提取组件（预先显式指定合法背包位置） | 20 | 0 |

最后一次任务提取在正时间开始，成本恰好耗尽剩余20，债务0。主要效果已把组件放入玩家预先明确选择的位置，再检查无流血、玩家存活、进入强制返程。作业区至入口是两条已知边，成本20：

- 有效紧急撤离时间 = 0 + 20 = 20。
- 基础损耗 = ceil(20/20) = 1。
- 流血追加0，防具不减免强制返程。
- 生命6−战斗3−返程1=2，全部已携带物安全提取。

全部最低包重量11，占10格；开局绷带在快捷栏，不额外计背包重量。可用摆放例：2×3组件放(0,0)，两堆口粮放(2,0)/(3,0)，金属(4,0)，布料(5,0)。仅验证此输入，不默认给调用方整理背包。

顺序不可交换成“0时间搜索完后再免费拾取”。本文先搜先拾取，最后以独立任务提取行动把组件放入显式位置。时间0后没有额外普通拾取命令。

|---|---:|---:|
| 路线规划量 | 190 | 220 |
| 安全返回生命 | 3 | 2 |
| 当晚用口粮 | 无 | 1 |
| 次日饱食 | 2 | 4 |
| 当晚生命恢复 | 1 | 2 |
| 次日生命 | 4 | 4 |
| 次日剩余口粮 | 0 | 2 |

| 次日出发时剩余工时 | 0 | 3 |

但若以生命4入场、同样不额外用药：防御后生命1。只取组件190可主动返回；拿齐后再承受强制返程1会死亡。不同生命、余时、负重、医疗储备和后续目标能够改变取舍。需要的是状态相关选择，不是每个状态下每条路径都同样好。

## 10. 上一轮多日结论哪些保留

v0.2三条多日算例以物流40/3和对应磨损为输入；本候选的防御线兑现了该局部输入，不等于三条全链验证完成。通信终段仍使用未证实的40/3，必须继续替换。

v0.2紧凑路线的“只取组件”不再是唯一代表；应增加本稿拿补给、主动接受强制返程的分支。它次日生命同为4，却拥有更好的饱食、库存和维护余量。不能仍据单一只取件分支宣称快线天然物资匮乏。

提前通信调查仍能省下物流现场60时间，并提前提供安装材料与口粮；它还多一次日级恢复，也多一夜的感染/饱食成本。是否长期值得必须在相同世界与可用信息下比较，不由本次一个局部表宣布。

## 11. 尚未关闭的门槛

- 新敌人的名称、初次150、生命16、两招参数、伤势映射等内容未冻结。
- 本次只对金属管、有效外套、正常负重、撬棍基准进行了核算；三专长未设计，无工具手工卡件、工具箱、手电筒及备用装备仍需验证。
- 同次重入仅列候选，跨日敌人状态、一次性来源、已解决危险的持续事实未冻结，不靠重复打同一敌人刷物资。
- 未穷举行动策略或所有风险树；不声称防御路线在任意输入上全局最优。
- 通信终段及安装材料同趟取得仍缺具体危险设计。
- 医院后置、工具损坏、带额外战利品造成负载、医疗插入、已感染状态的跨日组合仍未验证。
- 不为保住220/190差异而禁止强制返程、提升全局返程伤害或制造调查专属伤害税。

## 12. 实际做了什么核算

本轮运行独立 Python 纸面核算脚本 paper_encounter_check.py：10个指定战斗分支、3条无流血路线分支及库存/工时算术断言。风险由测试输入显式指定，没有随机采样，不产生胜率报告。

脚本输出的 paper_results.json 包含逐CTB事件与时间/生命/耐久。它们不是生产测试、不是仓库中的正式命令回放、没有证明保存恢复或通用core已经能加载此新敌人。

参考脚本仅表达本文用例所需规则，不是完整游戏模拟器；真实工程前仍应使用正式版本化内容和正式结算路径重新验证。

## 13. 继续推进的建议

保留“第一记重砸值得防御、无额外控制弱点、及时撤退可以不受击”的候选敌人方向，继续接受反例审查。

把物流的比较扩为：准备后从容取件和搜索；现场核查只拿任务；现场核查带齐并承担真实强制返程。撤回“紧凑路线必然没有补给”的预设。

随后用同样方法具体化通信终段，重点验证首次访问兼取安装材料，而不是先宣布完整三日快线已经通过。
