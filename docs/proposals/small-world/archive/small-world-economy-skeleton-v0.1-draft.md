# 《电梯求生》小型完整世界经济骨架 v0.1

> 状态：讨论稿 / Proposal。不是 DEC、Design Freeze 或 Codex 实现授权。
> 规则依据：当前 Project Sources 的已确认 DEC；既有医院实现背景仍锁定交接基线 `11cc705a9a923b367919cc9139de5097c006beb7`，本轮没有重新审查或运行该提交。
> 本稿独立提出候选结构；没有读取或冒充引用 GOAL-7D-PREP-001 两份未提交提案正文。
> H、C、L 等简称只是讨论标签，不是正式 content ID、状态字段或实现类型。

## 1. 一句话方案

用医院、通信中心、物流站三个主要场景，构成四次必要访问的主线。以一次常规补给加两次机动访问作为七日期限的初始容量预算。日期由玩家分配，不把地点绑定到固定第几日。

第一版只验证一个固定局势：设施停摆、现有物资尚有部分留存、物资来源有限、关键关系稳定。暂不加入配送循环、人物救助交易、随机世界日程、额外危机条、有限超期或复杂生成器。

这里的“完整”表示设计路径覆盖开始、恢复、推进和终局，不表示完整七日里程碑已经设计冻结或通过验收。

## 2. 正式边界与本稿新增提议

### 2.1 沿用的正式边界

- DEC-003：七个游戏日，每天只能选择一个主要场景，返程不恢复当日选择次数。
- DEC-023：实体任务物必须实际携带并安全带回；任务储存区属于 Run；普通情报不是背包物品。已取出又遗留在结束的探索中的任务物视为遗失，不能默认次日取回。
- DEC-028：第7日仍有正常行动机会；确认结束第7日后终检，成功或失败均不进入第8日。具体成功条件仍待设计，提前成功没有在当前基线中确认。
- DEC-029：医院样本箱是既有切片目标，不是已确认的完整七日最终核心部件。
- DEC-033/034：使用现有生命、饱食、感染与医疗测试参数。本稿不增加食物直接回血、感染治愈或免费治疗。
- DEC-036/037：维持装备身份、无限维修与最低攻击边界；每日工时3，金属零件1提供5机械维修量，布料1提供4织物维修量；工具箱不能用基础工时，手电筒需电池。
- DEC-045：场景地图知识不默认跨日；Run 情报文字不自动变成已经发现的地图路线。
- DEC-005/041：正式完整七日仍需三个专长，全部可通关。本稿不虚构专长效果，先做不借助专长优惠的经济底稿，不能据此宣布最终验收通过。

### 2.2 新增内容全部为候选

三个地点的完整世界职责、四次主线访问、两件新任务物、终局安装材料、固定供给数量、跨日一次性来源、设施与危险清除的持续事实，均属于本稿提议。医院的新增互动只进入未来完整世界内容版本，不改写已审定的一日切片。

## 3. 终局：三个实物成果，不是搜空世界

候选目标是完成隔离样本回收，并取得匹配的启动部件，恢复离开当前任务世界的能力。日常往返场景与离开当前任务世界不是同一个操作；不把每天已能使用的电梯说成完全不能运行。

终局资格暂定：

1. 密封病原样本箱已安全进入任务储存区。
2. 电梯控制组件已安全进入任务储存区。
3. 应急启动模块已安全进入任务储存区。
4. 普通库存还拥有金属零件1、电子元件1，供显式最终安装操作消费。
5. 玩家仍存活，没有触发感染终末或其他正式硬失败。

最后的安装与离开是候选专用任务操作，不要求第四处主要场景，不增加第八次访问，不默认由某个专长或工具箱授权，也不把它扩张为通用制作系统。

样本箱仍是实物任务证据，不是电池、万能钥匙或治愈感染的药。其隔离批次信息与控制组件型号共同帮助确认应急启动模块，这只是本稿采用的工作性叙事关系，正式叙事仍须细化。

新任务物试算规格：控制组件 `2×3`、重量6；应急启动模块 `1×2`、重量2。二者不可堆叠，须实际携带与安全提取，安全入库后不继续占背包。本稿不要求把任务储存区物品再次搬去其他地点。

成功不要求满生命、满饱食、无感染、所有装备修满、清空地图或取得全部医疗品。样本箱以及另两件任务物的任务事实不再另存为重复的“完成计数”。

### 3.1 终检顺序的开放边界

当前 DEC 明确普通日结算顺序与第7日终检，但未完整规定最终安装、终日各阶段和成功检查的编排。本稿建议生命与感染等正式硬失败不能被“物品齐了”覆盖；确切终日顺序必须确认后才能实施。

后文算账停在第7日终检确认前，不利用尚未确认的终日恢复、Day 8 工时、伤势清理或额外行动来证明可行性。

## 4. 主线依赖图与场景职责

医院取证 H → 样本箱安全入库。
通信调查 C1 → 控制组件位置/型号记录，以及应急启动模块的匹配流程。
C1 → 物流深区取件 L1 → 控制组件安全入库，并记录匹配信息。
H 与 L1 的实物成果及相关情报 → 通信终段 C2 → 应急启动模块安全入库。
三个实物成果与安装材料齐备 → 中枢终局操作。

医院取证与通信调查可以交换顺序。物流前区补给 L0 不要求 C1、样本箱、控制组件或指定日期；不得把基本食物藏在受损玩家还过不去的主线锁之后。医院药房原有基础搜索也不要求完成主线。

### 4.1 医院

承担高风险样本取证和医疗恢复。保留一日切片的六节点、既有战斗、搜索与提取语义。重访价值来自此前未使用的医疗来源，而不是重新生成样本箱、金属零件和同一护工。

候选新增一个独立封存药柜，作为较明确的急救与感染管理来源；不作为原药房搜索的补货或再次抽取。通信调查可提供它的定位/领取流程情报，具体互动和知识结果须由内容显式声明。

### 4.2 通信中心

承担情报、型号匹配和终段突破。首次调查能够取得可执行的线索、少量值班补给和安装材料；后续带着已取得的匹配信息回来，才处理对应的应急启动模块。

这次重访必须让此前未知或缺条件的目标真正变得可处理，不能只是把相同搜索再点一遍。首次到场需能够理解缺少的证据和信息来自哪里，不使用无提示资格锁。

### 4.3 物流站

承担普通补给、基础材料和实体控制组件。前区支持低损耗补给后撤；深区承担取件及较大的携带收益。不能为了获得前区口粮，强迫玩家先完成深区战斗。

设备取件与物资搬运应在节点时间上竞争，具体成本由下一版路线细化检验；不能因为库存表写了这些东西，就默认一趟全部安全带回。

### 5.1 食物数量为什么先取6份

物流前区2、通信值班区1、物流深区3，共6份。初始饱食6，首晚后4；第2至第7日晚各用1份口粮，可以在无浪费情况下让每晚结算后维持4。

这是“持续保住2点饱食恢复上限”的预算，不是胜利条件。只要求七次结算都不进入匮乏，在没有额外饱食消费且适时食用的条件下，5份就可使终日饱食至少为2；4份可以接受终日匮乏1点生命损失。更少食物也不自动失败，结果取决于生命与其他消耗。

两处补给加一次主线取得过程能够承载全部6份，不需要独立安排六个找食物日。只有整条路线能实际取得这些库存时，这一总量账才有意义。

### 5.2 安装与维修不得双花

通信调查拿到的金属1、电子1是普通资源，不做不可消费的保护库存。玩家可以用于修武器或工具箱，但必须知晓终局仍需要一组。物流独立维修料架提供另一组固定来源，补救须支付路线或一次额外访问，不自动返还已用材料。

基准账用物流深区的金属修复取件后的机械磨损，保留通信材料到终局。不能把同一份金属同时记作武器维修和最终安装。

### 5.3 医疗与感染各自有来源

基础恢复靠绷带、食物和正常日恢复，不借急救包随机结果。药柜提供确定但有取得条件的急救包和抑制剂，用于额外的风险分支。感染抑制剂只减少当日增加，消毒剂只处理未结算暴露，不新增完全治愈。

本稿没有人物救助消耗，因此不把同一批医疗品再承诺给技术员任务。未来加入救助交易，必须重新核算数量和访问次数。

## 6. 新路线的成本目标——尚非真实战斗结果

所有数字是候选场景设计的预算输入。尤其生命、武器和防具损耗，指一条选定参考分支的结果，不能实现成“进入这个场景固定扣这么多”，也不构成风险结果上限。

| 物流前区 L0 | 约110，非战斗路线 | 0 | 0 / 0 / 1 |
| 通信调查 C1，含表中补给 | 约140，非战斗路线 | 0 | 0 / 0 / 1 |

上表先按正常负重、无伤势移动修正、没有新增暴露或开放伤口、没有强制返程计算。新敌人、障碍、移动和搜索细表尚未建立，因此这些目标尚不能称为已验证可执行。

医院原战斗不调整、不降价；新场景也不把感染护工按每天复制。基准路线使用撬棍只是控制变量，其他工具和无工具方案仍须补齐，不将撬棍变成主线资格锁。

物流深区最低提取包为控制组件重量6、口粮3、金属1、布料1，总背包重量11；组件占6格，三份口粮按上限2分两堆占2格，金属和布料各1格，共10格，可排入6×4。该核算不包含出发时其他备用工具、药品和自选战利品。

这说明最低包不必依靠超载才能带回，不说明背包取舍已经有趣：可选物资与工具携带张力仍待内容验证。

## 7. 将第二日半血案例走到第七日

### 7.1 起点

第1日已经安全带回样本箱，未搜索药房；中枢维修后装备满状态，日结算后生命6、饱食4，绷带1，无口粮、材料、伤势、流血、感染或暴露。该状态是此前讨论的固定纸面分支，不是假定用户真实存档。

### 7.2 逐日账

第1至第6日的“生命/饱食”表示普通日结算完成后。第7日单独停在终检确认前。路线含一次主动选择的医疗储备日和一次终段合理撤退，不要求每个人按此日程行动。

| 日期 | 行动 | 安全带回的关键内容 | 明确消费 | 生命/饱食 | 剩余口粮 |
|---|---|---|---|---|---:|
| 1 | 医院样本箱 | 样本箱；大厅材料已用于首晚维修 | 已在固定起点中计入 | 6 / 4 | 0 |
| 2 | 物流前区 L0 | 口粮2、绷带1 | 绷带1回血，口粮1；工时1修撬棍 | 9 / 4 | 1 |
| 3 | 通信调查 C1 | 线索；口粮1、金属1、电子1、电池1 | 口粮1；工时1修撬棍；安装材料留存 | 11 / 4 | 1 |
| 4 | 物流深区 L1 | 控制组件；口粮3、金属1、布料1 | 场景参考损血3；口粮1；本日金属5点修武器4和撬棍1，工时1修外套 | 10 / 4 | 3 |
| 5 | 医院未使用的药房 | 绷带1；原随机医疗品不计为回血收益 | 口粮1；不使用候选药柜或急救包 | 12 / 4 | 2 |
| 6 | 通信终段尝试，在取出模块前撤退 | 不取得模块；不凭空奖励补给 | 参考损血2、武器磨损2/外套1/撬棍1；工时3修武器2和外套1；口粮1 | 12 / 4 | 1 |
| 7 | 再次完成通信终段并安全返回 | 应急启动模块 | 出发前工时1修撬棍；参考损血3；口粮1；最终安装需留存的金属1和电子1 | 终检前生命9，食用后饱食6 | 0 |

第6日结束时武器6、外套4、撬棍2。第7日先用本日工时1把撬棍修到3，再出发。第7日返程装备为武器2、外套2、撬棍2，仍不要求修满才能成功；剩余本日工时2没有被重复使用。

终检前还保留绷带2、布料1、电池1，以及未用于维修的安装材料金属1和电子1。药房抽取不承担大额回血假设；即使抽出的医疗品在该分支没有立即使用价值，上述生命账也不变化。

第7日无流血、无感染或暴露，食用后饱食6。复用现有日级危险和饱食消耗不会把这个输入变为死亡；本稿仍不把终日+2恢复或生成第8日计为已确认结果。

### 7.3 维护核查

- 第2、3日分别只消费当日工时1。
- 第4日消耗物流金属1，维修量5在本次操作分为武器4、撬棍1；当日工时1修外套。
- 第5日没有磨损，不把闲置工时存起来。
- 第6日工时3已用完，撬棍欠1不能当晚再修。
- 第7日新增工时3，出发前只用1补上撬棍；材料留到最终安装。
- 布料没有暗中折算为机械维修，电子元件没有单独修工具箱。

这是独立纸面算账的算术核对，不是正式 TypeScript resolver、保存恢复、战斗或浏览器模拟通过。

## 8. 日期自由度：四次主线访问，不是四个指定日期

示例顺序：

- 先推进：医院 → 通信调查 → 物流取件 → 通信终段，最早第4日具备实物前置。
- 先恢复：医院 → 物流前区 → 通信调查 → 物流取件 → 通信终段，第5日具备前置。
- 先调查：通信调查 → 医院 → 物流取件 → 通信终段；最初食物和信息准备不同。
- 一次恢复加一次合理撤退：约第6日具备前置。
- 两次针对性整备加一次合理撤退：上述第7日参照。

这些只是拓扑与预算见证。第一条不能直接称为“已经第4日通关”，因为提前成功还不是正式规则；也不能因为存在这些顺序，就宣布不存在固定最优解。

### 8.1 早离门禁

本稿推荐下一步讨论：条件齐备后，允许玩家在稳定中枢显式完成安装并提前结束；第7日作为最后期限，而非必须等到的领奖日。它改变 DEC-028 的成功时点，需要 Owner 确认并形成正式决策。

确认前继续按七日基线验证，不能实现提前成功、免费跳日或默认休息。当前已知 End Day 需要先完成当日主要场景并返回；不把“等到第7日”当成零成本空白日期。

若坚持仅第7日成功，则第4/5日备齐之后还需要有意义的剩余目标或允许的日程安排。这个体验问题真实存在，不能靠人为增加交付次数把四次访问填成七次。

## 9. 重访、库存与持续事实：必须明确的候选规则

建议本局只增加一层有限的持续记录，先覆盖一次性来源是否已兑现、唯一任务物是否已提取、明确已解决的障碍/设施结果、明确已解除的危险。不是把整个 Scene 自动跨日保存，也不是重新生成一个“没发生过任何事”的医院。

每个物资来源在本 Run 内只兑现一次。未使用的来源机会可保留；成功揭示后，该来源不因次日访问重新抽取。已揭示却未安全带回的普通物资不自动成为未来节点仓库。已取出又遗留的任务物继续按 DEC-023 的遗失边界处理。

任务物还没有从原设备/容器中取出，与拿出来后留在结束的探索中，是不同情况。前者是否保留原取得机会由本稿候选持续规则声明；后者不能默认重新生成同一件任务物。

唯一任务物永久遗失且无替代来源时，应按 DEC-028 明确宣告不可逆失败；仍有真实替代路线时不能提前失败。本稿暂不新增克隆任务件或自动替代奖励。

已击败危险跨日保持解除属于待确认的内容生命周期提议；未击败敌人的生命、意图和再进入起点，仍需单独确定。第6日撤退的预算不依赖次日免费弱化敌人，也不宣称敌人已经按某种新规则恢复。

Run 情报可以提示下次去哪儿，但下一次 Scene 的地图知识仍由明确发现规则产生；不因玩家或设计者记得完整地图而自动补全。

## 10. 玩家凭什么能作出这些决定

开局公开三个地点的名称、主要资源倾向与模糊危险范围，并清楚告知期限、样本任务和启动部件需求。

物流前区的有限补给与深区主线危险要能够区分，避免玩家误以为半血必须硬闯整个仓库。通信调查应告诉玩家零件在哪、何种匹配信息仍缺失、哪些普通材料还要留给安装。材料使用预览可以解释已知任务需求，但不自动替玩家锁仓或保留物品。

在通信中心首次看见终段设备时，给出可解释的前置方向；不使用必须全知才能理解的隐藏失败条件。跨场景线索必须记录来源，并由内容显式声明能产生什么知识或选项。

具体节点路线与获取顺序尚未写完，所以本稿只确立信息需求，未声称玩家知识受限的路线验证通过。

## 11. 尚不能由此宣布通过的检查

| 检查 | 当前结论 |
|---|---|
| 主线依赖覆盖终局 | 候选结构已给出；四次必要访问，安装不额外占主要场景 |
| 半血起点、无急救包收益、一次撤退的总账 | 在列明输入与参考损耗下算术自洽 |
| 新场景每个动作确实能产生所列成本 | 未验证；敌人、障碍和节点细表尚缺 |
| 同一趟带回任务和全部计入补给 | 最低携带包可容纳；路线时间与危险仍需实证 |
| 开放伤口、暴露、感染阶段与强制返程组合 | 未验证；只能分别列账，不按平均损血替代 |
| 基础维护长期底线 | 现有每日工时仍是再生来源；本稿只核算有限任务，未证明无限重复高磨损循环或三十日覆盖率 |
| 侦察/工程/生存与三个初始工具 | 未验证；没有借用未设计的专长优惠 |
| 首日先去其他地点、不用撬棍、材料误用 | 有结构性分支，仍须逐条执行验证 |
| 重访的状态/物品/地图/敌人生命周期 | 部分候选语义明确，未冻结，不允许直接编码 |
| 提前成功、最终日结算编排 | 待确认，不能按本稿自动改 DEC 或源码 |
| 不存在固定最优路线、玩家能推理、体验有趣 | 未证明，须知识受限测试和 Owner 试玩 |

## 12. 第一版需要重点攻击的反例

1. 物流前区反复访问没有新收益，却仍优于所有推进；或每日免费工时让拖延成为唯一选择。
2. 新场景实际战斗与返程损耗高于预算，把半血玩家的净恢复吞掉。
3. 主线与材料都在物流深区，但同一日取不完，必要访问从4次变成5/6次。
4. 终局所需电子元件被拿去修工具箱后，无已知或可达的替代来源。
5. 没抽到急救包、被抓出伤口或累积感染时，恢复路线只能纸面成立。
6. “还有一次机动日”在两次前置或终局安装中已经被隐性使用。
7. 主线前置提前满足，却必须机械地等到第7日。
8. 固定一次性库存在首版足够，但被错误宣传为支持任意长 Run 的完整再生经济。

## 13. 推荐下一轮先确认的范围

先审主线与访问结构是否值得保留：三个地点、四次必要访问、物流前区可早期恢复、任务与补给适度兼得、终局不额外强迫第四地点。

然后分开确认主线物与安装消耗、有限重访持续事实、提前成功与最终日顺序。确认方向不等于逐项批准掉落数量、生命损耗、敌人或生命周期实现。

若方向保留，下一份设计应具体化物流前区和通信调查，再把物流取件与通信终段的真实动作成本替换进本账；先检验这一个局势，再考虑A/B/C变化和有限超期。
