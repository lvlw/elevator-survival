## 1. 已确认方向与未确认内容

### 1.1 本轮已确认方向

**访问结构。**四次主要访问是一条标准路线的预算，不是主线资格或必须完成的次数。通信调查必须通过可解释的信息与实际成本收益证明自己值得占一天；已有实际前置且时间允许时，不因首次到访而禁止处理通信终段。不保证所有配置都能压缩成三次。

**终止时点。**主线及实际离开条件满足、合法安全返回稳定中枢后，玩家可以显式选择成功离开，不必等第7日，不追加尚未发生的过夜。已经提交的死亡或正式硬失败不能被任务完成覆盖。没有发生的日结算不提前转换暴露、扣日级流血、消耗饱食、回血、清理轻伤或生成次日工时；离开不等于痊愈。第7日同样使用这一成功语义，仍然没有第8日自由探索。

样本回收按上一轮审查方向作为独立任务目的继续设计，不再把样本批次牵强解释为电梯启动参数。三个地点和三个实物成果继续作为候选结构，完整任务条件、两个新部件的功能与命名仍需内容确认。

### 1.2 没有被这次认可顺带确认的内容

- 金属零件1 + 电子元件1的最终安装消耗。
- 新物资的数量、具体来源、跨日机会与耗尽边界。
- 新场景200时间、各条边10时间、搜索30等试算值。
- 现场核查、通信记录与模块匹配的具体内容及知识效果。
- 新敌人、伤害、伤势、暴露、战斗耗时与装备磨损。
- 敌人、障碍、已揭示物品与地图知识的跨日规则。
- 提前成功的正式命令、状态结构、存档格式、Profile 写入与UI。
- 最终日期入口的详细确认文案与失败原因编排。
- 有限超期、默认休息、自动整理、免费治疗、物资补货、自动安装或自动成功。

本文件把下文所有新增节点、行动、数量与比较算例统一标为“候选”，不以方向确认代替这些内容的审批。

不改变 DEC-003 每日只能选择一个主要场景的承诺边界；不废止 DEC-027/033 的普通日结算顺序；不改变 DEC-023 的实体安全提取、情报与任务物分离；不改变 DEC-035 已发生死亡优先；不改变 DEC-045 地图知识不默认跨日。

## 3. 修订后的任务与依赖

候选任务目的为：回收指定密封病原样本，并取得能恢复离开当前任务世界能力的部件。

- 医院：样本箱安全入库，是独立的回收成果，不是启动装置的密码或燃料。
- 物流：控制组件安全入库；现场明确取得该实物的接口信息。
- 通信终段：取得与现场接口信息匹配的应急启动模块并安全入库。
- 中枢：三件实物与最终确定的安装条件齐备后，显式完成任务并离开。

本版暂时沿用 v0.1 的安装材料1金属 + 1电子做经济比较，不宣告该配方已确认。

### 3.1 两种信息不得混为一枚唯一钥匙

“控制组件的配发、目标货位与运输卡件处理记录”可以从通信档案取得，也可以从物流现场留存记录核查取得。两种来源解决同一个定位问题，不能只认通信来源。

“实际控制组件的接口标识”在物流目标旁核验取得，用于后续通信终段匹配。它不是样本批次，也不是访问次数；本版不要求为了读它先把组件带回任务库。只读标识而尚未提取组件，可以拥有这条信息，但不能获得实物回收进度。

通信前期记录不直接替代现场实物接口核验。这个信息分工是候选叙事和互动方案，需确认是否自然、有用，不得为了守住四次访问而不断追加唯一凭证。

医院不再是通信终段的开门前置；玩家可以先处理设备线，最后回收样本，但最终成功仍需要候选任务规定的所有实物。

### 3.2 标准路线与紧凑路线

- 标准见证：医院 → 通信调查 → 物流取件 → 通信终段。
- 紧凑候选：医院 → 物流现场核查与取件 → 通信终段兼取安装材料。
- 恢复见证：医院 → 物流前区补给 → 通信调查 → 物流取件 → 通信终段。

这些是用于核算的顺序，不是指定日期、推荐唯一攻略或实际通关保证。其他顺序也需用实际资源和当时已知信息验证。

## 4. 本版候选内容的共同标尺

两处新场景本轮暂取200场景时间，普通双向边10；这不是“所有世界都必须200/10”的通用规则。下面按装备撬棍、无照明优惠、正常背包负重、无轻伤移动修正计算。

一次完整地图边移动、一次核查、一次解卡件、一次提取、一次主要搜索各自是行动；查看已有说明与整理背包不另收费。独立任务互动不是第二次通用搜索。

所有候选物資仍通过实际揭示、显式拾取、携带和安全返回进入库存；玩家不因选择某种“路线模式”自动领包。通信调查、通信终段只是活动标签，不是两个互不相通的模式或两个可各刷一次物资的场景。

对简单运输/柜门卡件，本版另提无工具手工处理40时间，撬棍20时间且磨损1；不把撬棍说成能破解精密电路，也不靠它锁死主线。此备选仍需确认，不自动套用医院防火门伤势和警觉规则。

## 5. 物流站：用现场核查替代前期调查

### 5.1 六节点候选拓扑

- 电梯入口 ↔ 分拨大厅。
- 分拨大厅 ↔ 前区物资间。
- 分拨大厅 ↔ 现场记录室。
- 分拨大厅 ↔ 备件作业区。
- 备件作业区 ↔ 独立维修料架。

每条边10。大厅按明确表层导视公开前区、记录室和作业区方向；进入作业区后才按该处表层观察发现维修料架。前区补给和记录室均不要求先通过作业区危险。

### 5.2 行动与结果

| 节点/行动 | 候选时间 | 工具成本 | 结果 |
|---|---:|---|---|
| 前区：解除物资柜卡件 | 20 | 撬棍1 | 允许处理该物资来源 |
| 前区：主要搜索 | 30 | 无 | 揭示口粮2、绷带1 |
| 记录室：核对留存调拨记录 | 40 | 无 | 当前目标货位与运输处理信息；不是重复阅读收费 |
| 作业区：处理危险 | K物流 | 按未来正式战斗 | 成功后允许稳定处理目标；不预填敌人数据 |
| 作业区：核验实物接口标识 | 10 | 无 | 取得该实物的接口信息 |
| 作业区：解除运输固定卡件 | 20 | 撬棍1 | 目标可被取出 |
| 作业区：取出并装好控制组件 | 20 | 无 | 实体进入显式携带流程，不等于已安全入库 |
| 作业区：主要搜索 | 30 | 无 | 揭示口粮3、金属1、布料1 |
| 维修料架：解除卡件并取出存放物 | 20 | 撬棍1 | 揭示金属1、电子1、电池1；不能重复兑现 |

未调查玩家到大厅时能够得知现场记录可核查，不是面对只有一个灰按钮的死路。已有相同定位事实的玩家可直接采用目标处理路线；信息效果由正式内容定义，不按“去过通信中心”授权。

### 5.3 逐项时间账

准备充分、只取组件：往返移动40 + 核验10 + 解卡件20 + 提取20 = 90 + K物流。

准备充分、取组件并搜索作业区补给：90 + K物流 + 30 = 120 + K物流。

未提前调查、现场核查只取组件：90 + K物流 + 记录室往返20 + 核查40 = 150 + K物流。

未提前调查、现场核查并取全部上述补给：180 + K物流。

独立前区补给：往返40 + 解卡件20 + 搜索30 = 90，不进入作业区危险。v0.1 的110只是总额目标，本版按明确行动改算90；数值尚待验证。

若仅为比较代入 K物流=40：准备充分并带补给160；现场核查只取组件190；现场核查兼带补给220。

220不是“禁止命令”，也不是一个可直接折算伤害的总超时数。玩家可以省略搜索或考虑正式允许的越零行为；后者须按逐行动顺序、超时债务、实际返程与当时玩家状态重新算，不能直接拿总量减200代替返程公式。

## 6. 通信中心：第一次来，也可以完成终段

### 6.1 六节点候选拓扑

- 电梯入口 ↔ 接待大厅。
- 接待大厅 ↔ 值班室。
- 接待大厅 ↔ 调度档案室。
- 接待大厅 ↔ 设备通道。
- 设备通道 ↔ 应急装置间。

每条边10。表层发现仅按明确导视逐点应用，不因持有通信记录就在新 Scene 自动获得全图。当前空间知识和 Run 情报仍分开。

### 6.2 行动与来源

| 节点/行动 | 候选时间 | 工具成本 | 结果 |
|---|---:|---|---|
| 调度档案室：检索整理调度记录 | 30 | 无 | 物流目标货位、处理流程及后续接口核验提示 |
| 值班室：取出维修柜备件 | 20 | 撬棍1 | 金属1、电子1、电池1 |
| 值班室：主要搜索留存口粮 | 30 | 无 | 口粮1 |
| 设备通道：解除物理阻挡卡件 | 20 | 撬棍1 | 处理实体护栏/阻挡，不是电子破解 |
| 设备通道：处理危险 | K通信 | 按未来正式战斗 | 成功后可抵达并处理应急装置 |
| 应急装置间：对照实际接口匹配 | 10 | 无 | 确认合适模块；需要对应实物信息，不检查访问次数 |
| 应急装置间：取出启动模块 | 20 | 无 | 实体进入显式携带流程 |

值班室把原稿同一地点的备件与口粮分为独立维修柜互动和一次主要搜索，总量不增加。这是本版新增内容拆分，不是免费增加一次通用搜索。

先前没取的备件可以在终段访问中取得；已经取走的不能再领。这个跨日一次性来源持续边界仍须独立确认。

### 6.3 逐项时间账

提前调查并收集值班物资：移动60 + 档案30 + 维修柜20 + 口粮搜索30 = 140。

只完成通信终段：往返移动60 + 物理卡件20 + 接口匹配10 + 提取20 + K通信 = 110 + K通信。

首次到场直接终段并拿安装材料：110 + K通信 + 值班室往返20 + 维修柜20 = 150 + K通信。

以上再搜索口粮：180 + K通信。

若仅代入 K通信=40：终段150；首次终段兼取材料190；再加口粮220。

因此紧凑路线不必另占一天拿安装材料，但要为这次同场取得支付实际时间和第二次撬棍磨损。该分支不取得值班口粮，也不凭空取得先前没查过的通信档案。

v0.1 的终段170为旧总额目标；本版按候选动作改为150（当K通信=40）。它不是战斗已经变简单、已经测试通过或正式调参批准。

## 7. 信息投资到底买到什么

| 比较项 | 提前通信调查 | 直接物流现场核查 |
|---|---|---|
| 主要访问次数 | 标准见证4次 | 紧凑候选3次 |
| 物流现场定位耗时 | 省略记录室往返与核查60 | 真实支付60 |
| 物流附带补给 | K=40时有余量安排30的搜索 | 只取组件190；再搜索超出本次200标尺 |
| 安装材料 | 较早取得，可显式留存或用于维修 | 必须在之后通信终段兼取或另找既有来源 |
| 日级生存 | 多一次过夜、食物需求、威胁进展 | 少一次过夜，也少一次恢复与新日工时 |
| 任务风险 | 执行余量相对较大 | 时间和医疗插入余量较小 |

没有“走快线扣评分”“跳调查固定扣血”“没去某地就关门”等新增惩罚。两条路径都从同一世界、同一来源和同一行动规则中形成。

不是所有初始实用装备都必须同样容易压缩；无工具手工路线的额外时间可以使三次紧凑访问不再有充分余量，但标准路线不得因此变成无解。专长正式效果尚未设计，不借专长优惠证明通过。

## 8. 第二日半血分支的两条完整条件性算账

### 8.1 输入与证据级别

第二日开始：生命6、饱食4；金属管6、外套4、撬棍3；当日工时3；开局绷带1；样本箱已安全入库；无食物、维修材料、伤势、流血、感染和暴露。

两条比较都刻意保留原绷带不用，避免一条用药、另一条没用而混淆。它不是禁止玩家使用绷带。

为了孤立“是否提前调查”，暂沿用v0.1对两次新危险的选定参考分支：物流损血3、武器4/外套1/撬棍1磨损；通信终段损血3、武器4/外套2/撬棍1磨损。通信值班备件柜另耗撬棍1，不能漏算。

这些伤害和战斗耗时尚未来自正式敌人或 TypeScript resolver；它们不是均值、风险上限或可直接写入游戏的整场固定扣费。以下只是条件性经济计算，已用独立算术脚本核对生命、饱食、库存与工时，不是游戏测试。

### 8.2 标准路线：第4日条件性成功

## 9. 提前成功的已确认语义与待落实交互

已确认方向应用于第1至第7日所有满足实际条件的合法稳定中枢，不设任意最低成功日期。材料/任务条件刚齐备不会自动成功；玩家须显式结束本局。中断网页不等于结束Run。

建议采用“完成安装并离开”一次确认，将未来正式确定的安装消费与成功终止原子提交。该名称、材料来源选择、UI预览和具体状态结构仍待工程规格；不另设可反复安装的玩法。

已经死亡或已经触发感染终末时不能进入这条成功路径。仍合法存活但下一晚可能死亡时，可以在下一晚前离开；不暗中结算、清除或治疗其未结算暴露与伤势。

仍处于活动Scene、战斗、返程或未完成返回结算时不能直接从深处离开本世界。必须完成正式返程和安全提取，不把任务完成按钮变成免费传送。

具备资格但选择继续探索时，Run仍进行中。后续死亡仍会失败；消费安装材料可能使资格暂时不满足；派生资格不作为独立永久“已成功标记”保存。

第7日仍有正常行动与整备，成功语义不追加过夜。期限结束入口的精确文案、未具备条件的最终确认、失败原因排序与保存处理应在终局专门规格中明确；不产生Day8。

## 10. 食物预算随离开时点重新计算

到第d日安全返回即离开，只发生d-1次普通日结算。不存在先自动算第d晚、再显示“当天离开”的双重成本。

无伤势/感染且追求每次结算后饱食4以保住2点恢复上限时，第一晚可用初始饱食，之后每晚一份：第3日离开需覆盖2晚、通常用1份；第4日覆盖3晚、用2份；第7日覆盖6晚、用5份。前提是每份取得时间足够早、无超额浪费。

这不是最低通关食物要求。紧凑算例选择第二晚饱食2、只恢复1，完全没有食用口粮。旧稿六份固定来源暂不自动减为五份；它们还可提供恢复、探索与误差缓冲，但不能再全部标成强制消费。

## 11. 本版明确没有解决的问题

1. **实际战斗。**K物流=40、K通信=40与损血3尚未验证，需真实敌人意图、玩家行动、伤势与暴露分支，不能编写整场固定扣血。
2. **时间余量。**紧凑两次探索仅余10；战斗延长或插入治疗可能耗尽余量。具体强制返程只能由逐行动状态计算。
3. **知识与物理可达性。**内容应明确同一定位事实可由两处取得；不根据玩家记忆或UI文本自动生成导航知识，也不在无通信访问时随机隐藏现场记录。
4. **重访。**候选一次性来源和已处理障碍需要跨日所有权。未击败敌人的状态、已揭示物资及遗留任务物不能默认保存或刷新。
5. **医院后置。**样本独立、末日可立即离开会使医院后置有避免感染跨夜的价值。必须与医院早期医疗、材料和高生命处理风险的价值比较；不能为了平衡硬加无提示样本失效或某日开门。
6. **补给搭配。**未提前调查者能否同时拿前区口粮、组件或维修料架要逐项算，不自动继承标准路线库存。
7. **强制主线与自由度。**本版仍有实际接口核验与模块匹配依赖，需确认其内容价值，不把“依赖有名字”当作证明。
8. **完整七日验收。**三个专长、初始三工具、合理撤退、安装材料误用、普通不利随机结果与多种首日选择仍需验证。

## 12. 本轮阶段结论与下一步

已完成的是：收录两项Owner确认方向；修订主线依赖；给出通信准备和现场核查的同源候选；把新场景部分总额预算拆成节点与行动；独立核对两条条件性经济账，没有进行正式游戏运行。

当前新增待审核心是：**用一次提前通信调查节省物流现场核查时间；紧凑路线通过舍弃部分搜索并现场兼取安装材料省下一次访问，而不是依靠唯一钥匙或固定扣血。**

下一份设计优先验证物流作业区真实危险，使“现场核查只取件190”中的K物流替换为可执行行动结果；继而验证通信终段与材料兼取。若不能成立，应调整内容成本或承认无法压缩，不隐藏增加日期。

正式落文应先准确记录已经确认的访问原则与提前成功语义，再分别确认新内容和跨日生命周期；本版不直接转为全功能Codex实现任务。
