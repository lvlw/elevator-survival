隔离 React 测试用正式 BrowserOwner、公开 PlayerSession 与真实 React 控件，存储和 lease 使用测试端口。两个控制种子通过正式随机算法及实际 H2 子流预选，路线执行不读取隐藏状态。没有修改生产权重或重抽。

- `owner-polish-pharmacy-test-12` 在 H2 得到正式 roll 70。药房地面展示绷带 1 和急救包 1。点击拾取后急救包离开地面，进入背包，实际资源路径含 `item-firstaid-v1.png`。通过防火门进入 H4，真实攻击和退却产生 HP10/12、E58。通过药食入口选择急救包，结果 HP12/12、E58、包内消耗 1，恰好一次 checkpoint 写入。该见证是仅受生命损失的合法目标，没有制造伤口；伤口/挫伤显式资格和精确效果按 `medical-qualification.ts` 与 `shared-medical.ts` 核对。

## 主推荐与试验

只把 H2 固定奖励由绷带 1 改为绷带 2，保留 H2 四种随机权重 35/30/20/15 和其余来源。选药房是为了将应急储备前移到 H1 邻接的医疗地点，额外一条不会挤掉急救包分支；L1 仍可补后半段，不把抵达物流当早期急救前提。玩家仍需承担搜索、路程、格位与额外 1 重，绷带适用资格不变。增加早期容错也可能削弱 H2/H4 的压力，特别是擅长避战的玩家；优先看更早受伤的同路线与酒店输入竞争，不从见证推断通关概率。

`candidate.json` 是唯一改值的隔离候选。用正式配置构造器、版本一致的任务/位置目录、新的 TEST 初态走 H0→H1→H2，调用真实来源计划。对照两组强制 roll 1 和 66，当前与候选均为 E96→84，均仅签发一项随机医疗物品，分别是消毒剂 1 和急救包 1，绷带签发 1→2。没有在候选下重跑完整驻留路线，也没有验证长链通过率。候选配置和内容 ID 分别为 `owner-polish-h2-bandage-test-v0.1` 与 `owner-polish-h2-bandage-content-test-v0.1`。正式 ID 未改，既有开始的驻留不变。若采纳，须正式批准新版本与恢复兼容方案，不能以现有 ID 重解释旧来源记录。此批没有第二投放备选。
