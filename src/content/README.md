# Content

存放版本化内容配置，不保存可变 Run 状态。

- 医院 `v0.1` 配置位于 `hospital-v0.1/`。
- 内容配置先通过核心 Zod 契约校验，再递归冻结。
- 注册表对未知版本明确失败，绝不回退到最新版本。
- 后续规则版本应追加注册，不覆盖旧版本对象。
- 医院节点图属于版本化内容，稳定节点ID和边ID不得因展示文案变化而改变。
- 静态图只保存潜在连接；本次探索的运行时通行状态不写入静态图定义。
- 新医院图版本必须新增版本化内容入口，不能静默覆盖旧版本图对象。
- 医院物品物理目录位于 `hospital-v0.1/items/`；稳定物品ID不随展示名称变化。
- 当前物品目录只保存尺寸、重量、旋转和堆叠等物理库存属性，不包含随机品质或词缀。
- 攻击、医疗、维护、装备资格及其他行为由后续独立能力目录通过相同稳定物品ID关联。
- 新规则版本应增加对应的新物品目录，不得静默覆盖旧版本定义。
- 医院物品资源档案位于 `hospital-v0.1/items/`，通过稳定物品ID与物理目录关联；资源上限来自同版本规则配置。
- 物理库存属性与状态资源分属独立目录；新规则版本不得静默覆盖旧资源档案。
- 医院18件正式物品均具有明确资源档案；消防斧依照 DEC-039 使用最大值2的耐久资源。
- 医院装备资格目录位于 `hospital-v0.1/items/`，通过稳定物品ID关联物理目录，包含2项武器、1项防具、3项实用装备和12项不可装备物品。
- 装备资格与状态资源彼此独立；新规则版本不得静默覆盖旧资格目录。
- 医院快捷栏资格目录位于 `hospital-v0.1/items/`，通过稳定物品ID关联物理目录；当前7项可进入、11项不可进入。
- 快捷栏资格、装备资格和物品资源档案相互独立，资格本身不表达具体使用效果或使用上下文。
- 医院三个主要搜索定义位于 `hospital-v0.1/search/`，分别配置固定物品、零次或一次加权抽取，以及固定情报ID。
- 当前医院主要搜索的全部物品产出都显式声明 `none` 初始资源状态；未来有耐久、完整度或电量的场景物品必须由内容定义明确给出初始值。
- 主要搜索掉落使用独立的确定性随机子流；手电筒及其电量不属于掉落物化输入，不改变正式物品结果或固定情报ID。
- 医院18项搜索照明资格档案位于 `hospital-v0.1/items/`；只有 `utility_flashlight` 是低照明主要搜索提供者，其余17项均不是提供者。
- 医院搜索命令显式选择有灯20或无灯30；照明成本1来自同版本规则配置，搜索揭示结果仍留在节点。
- 搜索掉落与拾取资格保持分离；门禁卡被拾取后仍只是背包中的实体物品，不自动开启门或写入独立权限状态。
- 医院障碍内容位于 `hospital-v0.1/obstacles/`，包含防火门六种选项、工作人员通道背包门禁权限和稳定事件ID。
- 工具箱开门固定产出的电子元件先进入当前节点地面状态，不自动拾取或合并；消防斧与强行撞门设置的单级警觉事实决定感染护工首次行动70／50。
- 医院战斗内容位于 `hospital-v0.1/combat/`：感染护工使用稳定敌人ID，只有抓挠和扑咬两个行动，并按固定循环交替。
- 扑咬伤势成功在医院切片记录为轻度咬伤；抓挠记录为轻度撕裂伤，精确伤害、CTB和风险数值来自同版本规则配置。
- 医院场景战斗遭遇目录同样位于 `hospital-v0.1/combat/`；隔离走廊绑定唯一感染护工遭遇，敌人实例由场景实例、遭遇ID与敌人定义ID稳定派生。
- 医院遭遇ID为 `encounter_hospital_infected_orderly`，事件ID为 `event_hospital_infected_orderly_encounter`；急诊大厅防火门与保安值班室工作人员通道共用同一敌人。
- 首次进入隔离走廊按场景警觉使用70／50首次行动时间；逃跑返回本次实际来源节点，重入使用50并保留敌人的生命、意图循环和行动计数；胜利后该危险不再触发。
- 医院战斗内容将 `consumable_bandage` 与 `consumable_painkiller` 分别绑定为战斗绷带和止痛药；核心只读取绑定角色，不硬编码医院物品ID。
- 两种医疗物品的战斗CTB均从医院 `v0.1` 版本化配置读取为80；绷带恢复、止血与伤口处理以及止痛药激活同样读取该配置和共享条件操作。
- 消毒剂、急救包、感染抑制剂、口粮和通用电池即使具有快捷栏资格，也没有战斗医疗绑定，不能在战斗中使用。
- 医院场景医疗内容将绷带、止痛药、消毒剂和急救包分别绑定为显式的非战斗医疗物品；场景时间唯一读取各医疗配置项的 `sceneTime`，不另设场景医疗时间副本。
- 消毒剂每日使用次数属于日级状态；场景返回、中枢医疗和未来日结算共享同一状态，不能由新场景实例或进入中枢重置。
- 医院任务事件目录位于 `hospital-v0.1/task-events/`；每个任务事件都严格绑定正式场景遭遇、任务产物和来源情报。样本箱以稳定实例在场景内取得并携带；只有返回结算将其转入 Run 任务储存区后，医院目标选择器才判定已完成。
- 医院18项物品的返回生命周期目录位于 `hospital-v0.1/items/`：隔离区门禁卡为权限物品，密封病原样本箱为任务物品，其余为普通物品。返回结算据此把背包中的门禁卡和普通物品送入 Run 仓库，把样本箱送入 Run 任务储存区。
- 最小 Run 整备库存管理会读取同一物理、资源、装备和快捷栏目录；任务储存区在本阶段只读。仓库与背包、装备和快捷栏间的显式迁移不自动合并、补充或恢复 ItemState。场景和中枢医疗复用同一份四项医疗内容绑定；中枢从 Warehouse、Backpack 或 Quick Slot 消费真实实例，并与场景共享日级消毒剂次数。维修、充电、制作、拆解与日结算仍未实现。
- 医院 `v0.1` 世界威胁内容将通用进展解释为感染阶段，并由版本化配置保存每次待处理暴露贡献、各阶段日基础增加、终末阈值和抑制剂参数；当前只表达和派生这些事实，不执行感染日结算或终末失败。
- 医院当前日中枢内容将感染抑制剂和压缩口粮绑定为零时间生存消耗品；两者只能从真实仓库、背包或快捷栏实例显式消费。抑制剂记录当日1次／15点抑制但不立即修改暴露或进展，口粮按配置恢复2点并在6点封顶。
- 医院Return与当前日中枢通过显式Run身份、当前日和终局场景实例保持生命周期连续；连续性规则版本必须等于医院依赖实际加载的版本。感染进展119仍可进入活动中枢，120及以上只能作为终末威胁事实交给未来Run终止协调，不能继续整备。
