# Core

纯 TypeScript 规则、状态转移、Effect、确定性随机与结算逻辑的边界。

- 配置契约和运行时校验属于核心，具体医院配置不属于核心。
- 最小 Run 身份在创建时绑定已注册的规则版本。
- 核心不依赖 React、React DOM、Zustand、DOM 或浏览器 API。
- 场景边移动、主要搜索、节点物品显式拾取、医院防火门、工作人员通道实时权限和单级警觉事实已经实现；感染护工战斗、医疗、任务对象和完整 RunState 尚未实现。

## 确定性随机

`src/core/random` 提供版本化的计数器式确定性随机基础。结果由种子、随机算法版本、命名子流和抽取序号共同决定，各子流彼此隔离。

- 禁止使用 `Math` 对象的 `random()` 或任何时间、系统随机源。
- 算法输出由黄金测试锁定。
- 改变既有随机序列必须增加算法版本，不能静默修改旧版本。
- 规则版本决定游戏参数；随机算法版本决定种子与抽取序号如何映射为随机结果。

## 场景节点搜索状态

`src/core/scene-search` 负责主要搜索定义、独立随机物化、场景级预定结果和节点揭示状态。

- 搜索结果只依据 Run seed、场景实例稳定ID、节点稳定ID、主要搜索序号和随机用途标识独立物化。
- 场景搜索状态创建时即为所有可搜索节点预定结果；节点搜索顺序及其他随机子流消耗不改变结果。
- 每个节点物品由物理实例与身份一致的资源状态共同组成；搜索定义必须显式声明初始资源状态，不能按名称推断或默认填满。
- 搜索前的预定结果属于隐藏状态；搜索揭示会把物品移入独立的节点地面物品状态，搜索与事件产物共用同一地面状态和显式拾取系统。
- 玩家可见投影在搜索前只公开“可搜索”，不得返回预定物品、情报、随机命中或实例ID。
- `preparedOutcome` 属于场景真实状态，React 不得直接将其作为玩家情报展示。
- `validateSceneSearchState` 是场景真实搜索状态的严格恢复校验边界；玩家 UI 仍必须使用玩家可见投影，不能直接读取隐藏预定结果。
- 本模块不执行背包放置或堆叠合并；拾取命令由场景探索模块编排。

## 场景时间事务

`src/core/scene` 负责正时间非战斗场景行动的通用事务。具体行动先由调用方计算主要效果和行动完成后的预计返程时间，通用事务再统一处理时间扣除、超时债务、行动后流血、死亡检查和紧急返程。

- 节点、负载、伤势与路线规则由其他模块计算，不在场景事务中推断。
- 预览和正式结算共用同一权威计算逻辑。
- 输入快照不会被修改，事务输出及其嵌套快照在运行时冻结。
- 场景核心不依赖医院内容、随机模块或 UI。

## 负载与移动时间

`src/core/load` 负责根据调用方提供的背包总重量判定负载等级，并计算节点移动和返程共用的时间修正。

- 物品重量求和和背包格子布局不属于本模块。
- 多个百分比倍率使用整数比例相乘，只在最终结果处向上取整一次。
- 轻微挫伤增加移动与返程时间；镇痛生效时暂时抑制该修正，但不移除伤势。
- 本模块只查询三种可携带负载等级的逃跑基础 CTB，不实现逃跑行动或伤口加时。
- 场景事务只接收已经计算完成的返程时间，不反向依赖负载模块。

## 场景节点图与返程路径

`src/core/scene-graph` 负责不可变静态拓扑、调用方显式提供的可通行边，以及采用稳定平局规则的确定性路径。

- 静态图只描述节点和潜在连接；工具、门禁卡、事件及开门资格由其他模块处理。
- 返回路线先合计所选路线的基础时间，再调用负载模块统一应用负载与伤势倍率并最终取整。
- 场景事务只接收最终预计返程时间，不读取节点图或重复应用时间修正。
- 核心图模块不依赖医院内容、随机源、全局可变状态或浏览器能力。

## 物品身份与背包网格

`src/core/inventory` 负责固定物品定义、稳定实例身份，以及不可变的背包几何、摆放操作和重量小计。

- 物品目录不包含随机品质、随机词缀或随机属性，只有 `1×1` 定义可以声明堆叠。
- 背包快照、摆放、占用格和添加、移动、移出结果均不可变并使用稳定实例ID排序。
- 本模块只计算背包重量小计；调用方可以将小计交给负载模块，但不能把它误称为完整总携带重量。
- 装备槽、快捷栏、仓库、耐久、正式医院物品及物品效果由后续模块处理。
- 背包整理本身不进入正时间场景事务。

## 物品状态资源

`src/core/item-state` 负责独立于物理库存的耐久、完整度和电量状态，以及不可变的消耗与恢复结算。

- 资源档案必须与调用方提供的物理物品定义完整、一一对应；未知、遗漏和重复定义都会明确失败。
- 耐久与完整度允许剩余至少 1 点的已承诺行动完成，并在成本超过剩余量时归零；电量不得透支。
- 资源归零只改变状态，不删除物品实例或改变实例身份。
- 资源恢复在正式上限处截断并返回未使用数量，不实现维修材料、工时或具体行为资格。
- 模块不解释攻击、防护、照明、装备槽、消耗品效果或零资源后的临时攻击规则。
- 随身物品状态集合要求背包、装备栏和快捷栏中的每个实例恰好具有一个身份一致、资源类型合法的状态；节点未拾取物品不进入该集合。

## 装备栏与背包转移

`src/core/equipment` 负责武器、防具和实用装备槽、装备资格，以及背包与装备栏之间的不可变转移。

- 装备栏不占背包格，装备栏物品不计入背包负重；负载只根据背包重量小计判断。
- 从背包装备会降低背包占格和背包负重，卸下至背包则可能提高背包负重。
- 资源归零不会自动卸下、移动或删除物品，也不会改变装备资格。
- 装备、卸下和显式交换不自动寻找位置、旋转或替换。
- 装备核心提供物理转移能力，不代表任何游戏上下文都允许换装；调用层负责控制操作资格。
- 快捷栏不属于当前模块。

## 快捷栏与单件转移

`src/core/quick-slot` 负责规则指定数量的快捷栏容器状态，以及背包、装备栏和快捷栏之间的实例唯一性与不可变转移。

- 快捷栏保存数量为1的实际物品实例，不是背包实例引用。
- 从背包堆叠抽取一件时，调用方必须显式提供新的稳定实例ID。
- 快捷栏物品不占背包格，也不计入背包负重。
- 移出或以后使用快捷栏物品后不会从背包自动补充。
- 本模块不执行物品效果、使用时间、CTB、命令编排或UI状态。

## 玩家条件状态

`src/core/condition` 负责生命、流血、未处理与已处理开放伤口、轻微挫伤和镇痛状态。

- 各状态相互独立；具体医疗行为以后按正式规则组合多个基础操作。
- 场景行动后的流血生命损失仍由 `src/core/scene` 统一结算，条件模块不重复扣除。
- 轻微挫伤只向旅行时间模块提供修正是否生效的布尔状态，不复制移动倍率。
- 逃跑伤口加时只计算未处理开放伤口修正，不包含基础逃跑 CTB。
- 条件模块不执行医疗物品消耗、日结算、感染、战斗或 Run 终止；从生命0恢复的纯数值操作不代表终局后允许复活。

## 场景探索与移动命令

`src/core/scene-exploration` 负责最小场景探索快照和第一条完整移动命令编排。

- 移动命令以稳定边ID组合场景图、背包负载、挫伤与镇痛、场景时间、行动后流血和确定性返程。
- 负载只读取背包，不读取装备栏或快捷栏。
- 场景探索快照会将背包宽高绑定到当前版本化规则配置；通用背包核心仍可处理其他合法尺寸。
- 主要移动效果先发生，随后才结算行动后流血；死亡优先于安全返回和强制返程。
- Effect是有序、结构化的规则结果，不是UI文案。
- 移动命令先生成冻结的Effect计划，最终快照只能由唯一Effect应用器依序生成。
- 同一Effect计划可以在等价起始快照上确定性回放；这不代表已经实现事件溯源存档。
- 主要搜索命令要求玩家显式选择使用已装备照明或无灯搜索；不会自动寻找、装备或使用背包与快捷栏物品。
- 搜索时间直接读取版本化的20/30配置，不应用负载、挫伤或镇痛修正；行动后返程仍按背包负载、挫伤和镇痛状态计算。
- 手电筒照明通过 `item-resource-consumed` Effect 消费，预定结果通过 `scene-main-search-revealed` Effect 揭示；搜索不会自动拾取。
- 节点物品拾取必须显式指定已揭示实例、数量、背包坐标和旋转，不自动选择、放置、旋转、合并、装备或进入快捷栏。
- 完整拾取保持原实例身份；部分拾取只允许无资源状态的可堆叠物品，并要求调用方提供新的稳定实例ID。
- 拾取不消耗场景时间，不执行流血或强制返程；单个原子 `scene-item-picked-up` Effect 同时更新节点物品、背包和随身资源状态。
- 工作人员通道实时读取背包中的实体门禁卡，不消耗卡，也不会把权限边持久写入场景状态；防火门打开则持久写入通行边。
- 场景警觉是 `unalerted/alerted` 单级事实，只为未来遭遇选择首次行动时间，不累计噪声或创建战斗状态。
- 当前移动、主要搜索、显式拾取和防火门命令采用同一Effect应用器生成最终快照；战斗和医疗尚未编排。
- 当前没有通用事件总线、发布订阅系统或全局Effect历史。
- 场景探索快照不是完整 RunState。

## 场景障碍完整性边界

`src/core/scene-obstacle` 负责严格校验障碍内容目录，并为一个障碍选项生成唯一的确定性主要结果计划。命令生成和 Effect 回放共同使用该计划，不分别维护装备资格、资源成本、正式时间、警觉、风险或产物规则。

- 障碍应用器校验完整主要结果的数量、内容和顺序，不只校验单个 Effect。
- 强行撞门始终产生可审计的确定性风险 Effect；回放必须提供 Run seed，并重新验证算法版本、命名子流、抽取序号、随机值、风险阈值、防护使用和挫伤结果。
- 工具箱产物的定义、数量、初始资源状态、当前节点、来源和稳定实例 ID 均由共享计划锁定。
- 障碍目录拒绝未知字段和未知判别类型，并交叉校验受控边端点、物品存在性、装备槽资格、资源档案、堆叠上限和产物初始状态。
- 本边界不实现感染护工战斗或 CTB 时间轴。
