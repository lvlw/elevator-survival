# UI

React 订阅 `StableRunStore` 的公开只读接口，并将 canonical `StableRunPhase` 投影为玩家可见的 ViewModel。默认开发与生产入口先在 React render 外执行一次 Browser strict load，再向 Production App Shell 注入 `ready(store)`、`no-run` 或玩家安全的 `load-error`；组件不实现玩法规则、不直接保存，也不会在渲染或订阅过程中 dispatch，已接入的玩家确认操作只会调用公开的 `store.dispatch()`。

`presentation/` 是纯 TypeScript 的白名单投影层；`interaction/` 是纯 TypeScript 的正式命令与安全 Preview 投影层；`hospital-v0.1/` 提供医院内容的显示文案和 player-safe New Run Setup 投影。`run-store/` 使用 `useSyncExternalStore` 桥接 Store。`StableRunUiApp` 必须注入 Store 与 presentation dependencies。Headless New Run core／应用事务已经由 Production App Shell 接入：无存档或 Failure 来源都先经过实用装备显式三选一与 Preview／Confirm，再采用事务建立的唯一新 Store；首次保存失败仅显示会话态警告，不回滚。损坏／不兼容存档保留原值并只允许不可逆 Preview 后显式清理，存储读取失败只允许显式重试。`dev-preview/` 只在开发构建通过 `?dev-ui-preview=1` 动态加载，以正式构造器创建独立、内存态的 Hub／Scene／Combat／Failure 预览 Store，且在真实 Browser Storage 创建之前分流，不注入正式 New Run 入口。

当前是可替换的策略控制台。Owner Playability Review Round 1 已完成，首轮玩家信息与交互清晰度修复已完成，等待 Owner Round 2 复测；这不代表完整医院平衡或完整 V1 已验收。已接入确认式 gameplay command wiring：中枢启动主要场景、当前日中枢十二种显式 Run Loadout 整备、四种中枢医疗、口粮与感染抑制剂、五类中枢维护／充能、普通结束本日、活动场景移动、使用／不使用手电筒的主要搜索、**显式节点物品拾取**、七种非战斗 Scene 背包／快捷栏整理、主动撤离、终止场景结算、医院防火门 `scene-obstacle`、感染护工 Combat scene player actions、医院样本箱 `scene-task-event`、Scene 非战斗 `scene-medical`，以及 Scene 非战斗 `scene-battery`。Hub Loadout、Hub Medical、Hub Survival、Hub Maintenance、Daily Settlement、Scene Inventory、Medical 与 Battery UI 只从各自正式 selector／Preview 取得合法来源、目标与结果；player-safe Preview 白名单投影正式容器、数量、资源、负重、医疗状态、饱食、相对威胁阶段、威胁抑制、维护工时与浪费、时间、流血、返程及终局事实，raw Preview、审计、Effects、精确威胁进展、物品／伤口身份和 resulting snapshot 不进入普通 ViewModel。每次确认仍只通过 `Store.dispatch()` 发送一条正式 application command，胜利、逃跑、战败、医疗、充能、任务事件超时、强制返程或日结算不自动连锁下一生命周期。

拾取必须由玩家明确选择数量与背包坐标；Scene 与 Hub 整理必须明确选择操作、数量、目标堆叠、装备／快捷栏或背包坐标，任务储存区在中枢保持只读，任务物放到节点必须显著确认；样本箱提取必须明确选择 2×2 放置 anchor 与旋转；Scene 医疗必须明确选择真实背包／快捷栏来源及正式规则要求的伤势目标；Scene 充能必须明确选择真实背包电池来源和背包／装备目标；中枢医疗、生存补给和维护必须明确选择正式 selector 提供的来源、目标及适用 allocation，不自动选择、整理、拆分、合并、补充或维修。core 继续拥有容器、堆叠、负重、装备／快捷栏资格、医疗／充能／生存补给／维护资格与效果、材料兼容、维修浪费、日工时、目标合法性、时间、流血、返程终局和稳定实例身份；React 只显示安全 Preview 并发送正式命令。Medical 与 Battery 共用中性正时间 Scene 行动安全投影，完成节点不会与强制返程目标混淆，死亡原因只读取正式行动后流血与紧急返程损耗。成功结算后的返回摘要、战斗行动结果、任务事件结果、Scene Medical Result、Scene Battery Result、Scene Inventory Result、Hub Loadout Result、Hub Medical Result、Hub Survival Result、Hub Maintenance Result 和 Daily Settlement Result 只是由 execution 前后 canonical phase 及已发生正式结果投影的本地展示，不是状态 owner。日结算 Preview 会按正式阶段顺序展示当前日到次日或 Run Failure 的后果；早期终止不展示尚未执行的后续阶段。New Run Setup 已接入无存档与 Failure 来源，使用医院正式初始配装 metadata、无默认实用装备选择、Preview／Confirm 和独立原子事务；UI 仍未接入完整 RunState、Day 7 最终解析、制作或拆解命令。当前 React command 范围为 Hub Loadout、Hub Medical、Hub Survival、Hub Maintenance、End Day、Launch、Move、Main Search、Pickup、Scene Inventory、Obstacle、Task Event、Scene Medical、Scene Battery、Withdraw、Combat Action 与 Terminal Scene Settlement；New Run 创建不是 gameplay command。开发预览和检查器只在开发环境存在；检查器不提供 mutation，预览选择器只切换独立合法 Store，不发送 gameplay command，也不保存或访问真实 Run 存档。
