# UI

React 订阅 `StableRunStore` 的公开只读接口，并将 canonical `StableRunPhase` 投影为玩家可见的 ViewModel。组件不实现玩法规则、不直接保存，也不会在渲染或订阅过程中 dispatch；已接入的玩家确认操作只会调用公开的 `store.dispatch()`。

`presentation/` 是纯 TypeScript 的白名单投影层；`interaction/` 是纯 TypeScript 的正式命令与安全 Preview 投影层；`hospital-v0.1/` 仅提供医院内容的显示文案。`run-store/` 使用 `useSyncExternalStore` 桥接 Store。`StableRunUiApp` 必须注入 Store 与 presentation dependencies。生产环境的默认 `App` 在没有活动 Run 时只显示诚实的未接入状态；开发环境会动态加载 `dev-preview/`，以正式构造器创建独立、内存态的 Hub／Scene／Combat／Failure 预览 Store。

当前是可替换的策略控制台。已接入确认式 gameplay command wiring：中枢启动主要场景、当前日中枢十二种显式 Run Loadout 整备、活动场景移动、使用／不使用手电筒的主要搜索、**显式节点物品拾取**、七种非战斗 Scene 背包／快捷栏整理、主动撤离、终止场景结算、医院防火门 `scene-obstacle`、感染护工 Combat scene player actions、医院样本箱 `scene-task-event`、Scene 非战斗 `scene-medical`，以及 Scene 非战斗 `scene-battery`。Hub Loadout、Scene Inventory、Medical 与 Battery UI 只从各自正式 selector／Preview 取得合法来源、目标与结果；player-safe Preview 白名单投影正式容器、数量、资源、负重、时间、流血、返程与终局事实，raw Preview、审计、Effects、物品／伤口身份和 resulting snapshot 不进入普通 ViewModel。每次确认仍只通过 `Store.dispatch()` 发送一条正式 application command，胜利、逃跑、战败、医疗、充能或任务事件超时及强制返程不自动连锁下一生命周期。

拾取必须由玩家明确选择数量与背包坐标；Scene 与 Hub 整理必须明确选择操作、数量、目标堆叠、装备／快捷栏或背包坐标，任务储存区在中枢保持只读，任务物放到节点必须显著确认；样本箱提取必须明确选择 2×2 放置 anchor 与旋转；Scene 医疗必须明确选择真实背包／快捷栏来源及正式规则要求的伤势目标；Scene 充能必须明确选择真实背包电池来源和背包／装备目标，不自动选择、整理、拆分、合并或补充。core 继续拥有容器、堆叠、负重、装备／快捷栏资格、医疗／充能资格与效果、目标合法性、时间、流血、返程终局和稳定实例身份；React 只显示安全 Preview 并发送正式命令。Medical 与 Battery 共用中性正时间 Scene 行动安全投影，完成节点不会与强制返程目标混淆，死亡原因只读取正式行动后流血与紧急返程损耗。成功结算后的返回摘要、战斗行动结果、任务事件结果、Scene Medical Result、Scene Battery Result、Scene Inventory Result 和 Hub Loadout Result 只是由 execution 前后 canonical phase 及已发生正式结果投影的本地展示，不是状态 owner。UI 仍未接入 New Run、React Provider、完整应用编排、中枢医疗／维护／生存或日结算命令。当前 React command 范围为 Hub Loadout、Launch、Move、Main Search、Pickup、Scene Inventory、Obstacle、Task Event、Scene Medical、Scene Battery、Withdraw、Combat Action 与 Terminal Scene Settlement。开发预览和检查器只在开发环境存在；检查器不提供 mutation，预览选择器只切换独立合法 Store，不发送 gameplay command，也不保存。
